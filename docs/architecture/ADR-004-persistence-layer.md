# ADR-004: Persistence Layer

**Status**: Accepted
**Date**: 2026-06-11

## Context

Tachikoma needs embedded, file-based persistence with structured queries for session tracking, tasks, and workflows. Requirements: typed models, versioned migrations, no database server, and a driver drizzle actually supports.

The initial preference was the runtime-built-in `node:sqlite` driver (zero native dependencies), but drizzle-orm 0.45 has no `node:sqlite` adapter — its SQLite drivers are better-sqlite3, bun:sqlite, libsql, and a few platform-specific ones. Wrapping `node:sqlite` behind drizzle's `sqlite-proxy` would trade a supported driver for a hand-rolled adapter on the hottest code path.

## Decision

Use **drizzle-orm** over **better-sqlite3**, with **drizzle-kit** for generated, versioned migrations.

- Database file at `{workspace}/.tachikoma/tachikoma.db` (workspace-owned), WAL mode, foreign keys on
- Schema defined in TypeScript; domain types derived via `$inferSelect`/`$inferInsert` rather than hand-written interfaces
- Migrations generated by `drizzle-kit generate` and applied automatically at startup
- A single shared database instance exposed to extensions through the `AppContext`; each first-party extension owns its tables (aggregated into one schema module); third-party extensions use the namespaced key-value store instead

## Consequences

### Positive

- First-class drizzle driver — no adapter shims to maintain
- better-sqlite3 is the most battle-tested SQLite binding in the ecosystem, with prebuilt binaries for common platforms
- Typed schema-first models with inferred domain types; queries are SQL-shaped and predictable
- drizzle-kit generates deterministic, reviewable migration files
- Synchronous driver matches drizzle's sync SQLite API and simplifies call sites; a non-issue at this scale (single user, small DB)

### Negative

- Native dependency: installs need a prebuilt binary or a node-gyp toolchain on Node-version bumps (pnpm requires the build to be allow-listed via `allowBuilds`)
- drizzle-orm is pre-1.0; minor-version churn is possible — validated by tests
- Synchronous queries block the event loop; acceptable for this workload but worth watching if any query grows hot

## Alternatives Considered

- **drizzle + `node:sqlite`**: the original preference — zero native deps — but drizzle has no such driver today; revisit if one lands upstream
- **libsql client**: drizzle-supported and file-capable, but brings its own native core without a maturity advantage here
- **Prisma**: heavy engine binary and codegen pipeline; oversized for an embedded single-user DB
- **Kysely**: pleasant typed query builder but no schema definition or migration generation — would need hand-rolled DDL
