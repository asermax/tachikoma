## Migration convention (read before Batch 1)

The design references a migration `0006_tasks_goal`, but **migrations 0006–0008 already exist** (`channel_messages_text`, `sessions_error`, `dlt175_trunk_routing`). The real migration will be the **next available number (0009+)** at landing time.

Per [DES-002](../design/DES-002-extension-authoring.md) ("NEVER run `drizzle-kit generate` yourself — migrations are generated centrally after integration") and [DES-003](../design/DES-003-testing-conventions.md) (DDL mirrors bridge feature work until the central migration lands), this delta's feature work:

1. adds the `goal` columns to `src/extensions/tasks/schema.ts`, and
2. updates the **DDL mirror** in `tests/tasks/setup.ts`.

The central `drizzle/0009_tasks_goal.sql` + `meta/_journal.json` entry + snapshot are **generated at landing** (the `land-delta` step runs `drizzle-kit generate`), at which point the `goal` bridge lines (the `ALTER … ADD goal text` statements in `tests/tasks/setup.ts` **and** `tests/migration/tasks.test.ts`, plus the now-redundant `goal text,` in the inert `CREATE TABLE` mirror) are removed. No batch below writes a numbered migration file.

> **Implementation finding (Batch 1):** the `CREATE TABLE IF NOT EXISTS` mirror in `tests/tasks/setup.ts` is **inert** — central migration `0001_extensions.sql` already creates both task tables, so the mirror never creates them and a column added there never lands. The genuine bridge is an `ALTER TABLE … ADD goal text` per table run *after* `runMigrations` (exactly how `0005` added `pi_session_file`). The same bridge is required in `tests/migration/tasks.test.ts`, whose legacy-import tests call `runMigrations` directly and query via drizzle. Both bridges are removed at landing once `0009` is applied by `runMigrations`.

### Steps

#### Step 2.1: Add the extraction primitives and the guarded write-back helper

- Modify: `src/extensions/tasks/executor.ts`
- What to do:
  - Add `ExtractedGoalSchema = Type.Object({ goal: Type.String() });` near the existing `TaskEvaluationSchema`.
  - Add a `GOAL_EXTRACTION_SYSTEM` module-level prompt template (derives a free-text goal in the recommended "end state + stated check + invariants" structure from the task prompt). Exact wording finalized at implementation per the design.
  - Add a `MIN_GOAL_LENGTH` constant (the "unusable" trim + minimum-length threshold from R15) — start at **50 characters** (a goal shorter than that is trivially or malformedly satisfied) and note it as a tunable heuristic. R15's "empty, trivial, or malformed" maps to: empty-after-trim **or** below this length.
  - Add `extractGoal(side, taskPrompt, log): Promise<string | null>`:
    ```ts
    // try side.classify(extract); on throw or a goal that fails the trim+min-length
    // heuristic, return null (run proceeds on the task-prompt basis; nothing persisted)
    export const extractGoal = async (
      side: Pick<SideRunner, "classify">,
      taskPrompt: string,
      log: Logger,
    ): Promise<string | null> => {
      try {
        const result = await side.classify({
          system: GOAL_EXTRACTION_SYSTEM,
          user: taskPrompt,
          schema: ExtractedGoalSchema,
        });
        const goal = result.goal.trim();
        return goal.length >= MIN_GOAL_LENGTH ? goal : null;   // unusable → null
      } catch (error) {
        log.warn({ err: error }, "goal extraction failed — proceeding on task-prompt basis");
        return null;
      }
    };
    ```
- Modify: `src/extensions/tasks/repository.ts`
- What to do: add the guarded write-back helper that sets the definition goal **only when it is still null** (prevents clobbering a goal set by `update_task` or an earlier write-back between instance creation and run-start):
  ```ts
  /** Write the extracted goal back to the definition only if its goal is still null. */
  setDefinitionGoalIfNull(id: string, goal: string): boolean {
    const current = this.getDefinition(id);
    if (current == null || current.goal != null) return false;   // never clobber
    this.updateDefinition(id, { goal });
    return true;
  }
  ```
- Test: `tests/tasks/executor.test.ts` — unit-test `extractGoal` (it lives in executor.ts) returning null on a throw and on a too-short result, and the goal string otherwise. `tests/tasks/repository.test.ts` — unit-test `setDefinitionGoalIfNull` writing the goal only when the definition's goal is null and returning `false` (row unchanged) otherwise.

#### Step 2.2: Run extraction at run start and conditionally write back

- Modify: `src/extensions/tasks/executor.ts` — `executeBackgroundInstance`
- What to do: for a **fresh (non-resuming)** run whose `instance.goal` is null, extract before the opening prompt and persist the result conditionally:
  ```ts
  // Inside the try block, after `system = buildSystemPrompt(...)` and before the
  // opening prompt is assembled. Fresh runs only — a resuming instance already has its goal.
  let effectiveGoal = instance.goal;
  if (!resuming && effectiveGoal == null) {
    const extracted = await extractGoal(side, instance.prompt, log);
    if (extracted != null) {
      repository.updateInstance(instance.id, { goal: extracted });   // store on the instance
      effectiveGoal = extracted;
      if (definition != null) {
        // Guarded: skipped if the definition goal was set in the meantime.
        repository.setDefinitionGoalIfNull(definition.id, extracted);
      }
    }
  }
  ```
  - `effectiveGoal` feeds the opening prompt (Step 2.3). Because extraction is the only path that sets a previously-null instance goal, and it runs every fresh run until it succeeds, there is **no give-up counter** (R15).
- Test: `tests/tasks/executor.test.ts` —
  - Fresh run, goal null → `classify` called for extraction; instance goal persisted; opening prompt contains the extracted goal.
  - Instance already has a goal (snapshotted) → **no** extraction call; opening uses the snapshotted goal.
  - Definition goal set in the meantime (pre-set `definition.goal` before extraction resolves, or assert `setDefinitionGoalIfNull` returns false) → goal stored on the instance only, definition unclobbered.
  - Ad-hoc instance (no definition) → goal stored on the instance only.
  - Extraction throws / returns a too-short goal → opening proceeds on the task-prompt basis, instance goal stays null, definition untouched.
  - Resume run → no extraction (instance is resuming).

    ```ts
    const updateGoalTool = defineTool({
      name: "update_goal",
      label: "Update Goal",
      description:
        "Declare the terminal outcome of this background task — the ONLY way to finish. " +
        "status='completed': restate the goal, cite concrete checkable evidence the stated check " +
        "is met, and summarize what you accomplished. status='not_completable': give the reason. " +
        "This tool cannot edit the goal text — it only records a terminal status.",
      parameters: Type.Object({
        // StringEnum discriminator — NOT a Type.Union (Google-API compat, per pi-sdk-notes)
        status: StringEnum(["completed", "not_completable"] as const),
        goalRestated: Type.Optional(Type.String()),   // required when status === "completed"
        evidence: Type.Optional(Type.String()),        // required when status === "completed"
        summary: Type.Optional(Type.String()),         // required when status === "completed"
        reason: Type.Optional(Type.String()),          // required when status === "not_completable"
      }),
      execute: async (_id, params) => {
        // In-tool validation: the JSON Schema alone cannot encode "evidence required iff
        // status=completed", so this validator closes that gap. On an incomplete declaration,
        // signal an error so the agent self-corrects and retries WITHIN the run (the flag stays
        // null); on a valid one, set the flag and return success text.
        if (params.status === "completed") {
          // require goalRestated, evidence, summary non-empty after trim
          //   invalid → throw / error-result naming the missing field
          //   valid   → pendingDeclaration = { status: "completed", summary: trimmed.summary }
          //             return { content:[{type:"text", text:"Goal marked complete — ending run."}], details:{} }
        } else {
          // require reason non-empty after trim
          //   invalid → throw / error-result
          //   valid   → pendingDeclaration = { status: "not_completable", reason: trimmed.reason }
          //             return success text
        }
      },
    });
    ```
