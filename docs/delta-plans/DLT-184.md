#### Step 2.2: Implement the grant branch in `SideRunner.run`

- Modify: `src/agent/side-run.ts` (`run`)
- What to do: destructure `extensionTools`. When it is a non-empty array, take the grant path: open via `manager.open` with `inMemory: true`, `bare: true`, `bindSubagentFactories: true`, `isolatePrompt` honored, and the given `system`/`model`/`tier`/`customTools` — but with **no** `tools` allowlist (so bound factory tools register and enumerate, mirroring the background branch). Then, BEFORE `session.prompt`:
  - enumerate the registry source-agnostically: `const available = new Set(session.getAllTools().<idField is `name` per Pre-flight>().<into a Set of names>);` — covers Tachikoma-factory and pi-native tools identically;
  - `const missing = extensionTools.filter((n) => !available.has(n));` — if any are missing, `dispose()` the session and throw a self-correcting error of the same "list what is valid" form as the unknown-agent / unknown-built-in-tool errors, naming the missing name(s) and listing the grantable (non-builtin) tool names;
  - else narrow to the exact active set: `await session.setActiveToolsByName([...tools, ...extensionTools])` (await only if the Pre-flight found it async);
  - then `session.prompt(prompt)` and return `lastAssistantText` as today; dispose in the same `finally`.
- The built-in-only path (no/empty `extensionTools`) stays byte-for-byte unchanged.
- Snippet (grant branch):
  ```ts
  // if extensionTools?.length:
  //   open({ inMemory, bare, bindSubagentFactories: true, isolatePrompt, ... })   // NO tools allowlist
  //   available = new Set(session.getAllTools().map(t => t.name))                 // source-agnostic
  //   missing = extensionTools.filter(n => !available.has(n))
  //   if missing: dispose(); throw self-correcting error (lists grantable non-builtin names)
  //   session.setActiveToolsByName([...tools, ...extensionTools])                 // exact subset
  //   prompt; dispose (finally)
  ```
- Note: a granted tool that throws DURING the run surfaces to the subagent as a normal tool error (no special handling — `session.prompt` already routes tool errors back to the model); the delegation does not auto-terminate solely because a granted tool threw. **Ambiguity is NOT a throw:** pi's tool registry dedupes by name, so a name exposed by two providers is undetectable — it resolves last-wins (see ADR-015, Step 4.1). Do not implement an ambiguity error.

#### Step 2.3: Tests for the grant path

- Modify: `tests/agent/side-run.test.ts`
- What to do: extend the fake session to expose `getAllTools: () => [{ name: "read" }, { name: "grep" }, { name: "find" }, { name: "ls" }, { name: "web_search" }]` and `setActiveToolsByName: vi.fn(...)` (sync or async per the Pre-flight finding). Add cases:
  - "grants a resolved extension tool alongside built-ins" — `run({ tools: ["read"], extensionTools: ["web_search"], … })` → `open` called with `bindSubagentFactories: true`, `bare: true`, `inMemory: true`, and NO `tools` allowlist; `setActiveToolsByName` called with `["read", "web_search"]`; `prompt` called; session disposed.
  - "throws before the prompt when an extension tool does not resolve, listing grantables" — `extensionTools: ["web_srch"]` → `getAllTools` called, `prompt` NOT called, session disposed, rejects with a message matching `/web_srch/` that lists the grantable non-builtin names.
  - "partial resolution fails the whole request before the run" — `extensionTools: ["web_search", "web_srch"]` → throws, no prompt.
  - "an empty `extensionTools` array is treated like omitting" — `extensionTools: []` takes today's built-in-allowlist path: `open` called WITHOUT `bindSubagentFactories` and WITH the `tools` allowlist (never "no tools").
  - "disposes the session even when validation throws" — `dispose` invoked in the error path.
  - "omitting `extensionTools` keeps today's allowlist path" — regression: `run({ tools: ["read"], customTools: [{ name: "myTool" }] })` still opens with `tools: ["read", "myTool"]` and no `bindSubagentFactories`.
- Ambiguity note: a "two providers expose the same name" test is **not** added — the behavior is best-effort last-wins and is documented in the ADR rather than asserted at runtime.

### Out of scope

Feature-doc reconciliation (`feature-specs/skills.md`, `feature-designs/skills.md`) — that is a later `/katachi:reconcile-delta` step.

### Steps

#### Step 4.1: Write ADR-015

- Create: `docs/architecture/ADR-015-subagent-extension-tool-grants.md`
- What to do: follow the ADR format.
  - **Context:** the session-scope model was two-valued (`main`/`background`) with no ADR of its own; delegations are tool-starved by a double-block (no factory binds a bare session + the hard `tools` allowlist masks anything that registers).
  - **Decision:** add a `subagent` session scope (per-factory opt-in via `app.agent.use(f, { sessionScopes: […, "subagent"] })`); resolve requested names source-agnostically at execute time via `AgentSession.getAllTools()`; narrow the active set via `setActiveToolsByName()`; pi-native extensions are grantable because installed = trusted.
  - **Alternatives rejected:** per-tool declaration; re-scoping tools; an `excludeTools` denylist; selective factory binding; registration-time tool-name declaration for advertising; resolving against the main session's tool set; an inclusive `tools` allowlist.
  - **Consequences:** advertising is generic (names are only knowable post-open); pi's registry dedupes by name so resolution is last-wins and the ambiguity case is best-effort (documented, not an error); recursion stays structurally impossible because the skills factory is not scoped to `subagent`; credentials remain out of scope (no secrets plumbing).

#### Step 4.2: Index the ADR

- Modify: `docs/architecture/README.md`
- What to do: add an ADR-015 row to the ADR table.
