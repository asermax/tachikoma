### Steps

#### Step 1: Create workflow definition dataclasses

- Create: `src/tachikoma/workflows/__init__.py` (empty package)
- Create: `src/tachikoma/workflows/definition.py`
- What to do: Define frozen dataclasses for the filesystem-parsed workflow model:
  - `StepDefinition`: id (str, directory name), title (str from frontmatter), instructions_path (Path), references_path (Path | None), scripts_path (Path | None), skippable (bool, default False), properties (dict for extensible frontmatter fields)
  - `WorkflowDefinition`: skill_name (str), workflow_name (str), steps (list[StepDefinition]), path (Path)
- Test: Unit test for dataclass construction and immutability

#### Step 2: Create workflow definition loader

- Create: `src/tachikoma/workflows/loader.py`
- What to do: Implement `load_workflows(skill_dir: Path, skill_name: str) -> dict[str, WorkflowDefinition]`:
  - Discover `workflows/` subdirectories within skill_dir
  - For each workflow dir, discover step subdirectories sorted alphabetically (R17)
  - Parse step `instructions.md` frontmatter using python-frontmatter for title, skippable, extensible fields (R5, R12) — follow the pattern at `src/tachikoma/skills/registry.py:199-208`
  - Steps without instructions.md: log warning, skip step
  - Invalid frontmatter: log warning identifying step and field, skip step
  - Workflow with no valid steps: include with empty steps list (start_workflow will error at runtime)
  - Validate references/ and scripts/ subdirectories exist within step dirs
- Test: Step ordering, frontmatter parsing, missing instructions.md warning, invalid frontmatter handling, optional references/scripts

#### Step 3: Extend SkillRegistry with workflow definitions

- Modify: `src/tachikoma/skills/registry.py`
- What to do:
  - Add `_workflows: dict[tuple[str, str], WorkflowDefinition]` mapping (skill_name, workflow_name) → definition
  - In `_load_skill()`: after loading skill metadata, call `load_workflows()` to discover workflows
  - In last-wins replacement: clear previous workflow entries for the skill name before re-adding
  - Expose `get_workflow(skill_name: str, workflow_name: str) -> WorkflowDefinition | None`
  - Expose `workflows` property
  - In `refresh()`: workflows dict rebuilt alongside skills dict
- Test: Workflow discovery within skills, skill replacement clears workflows, get_workflow lookup

- Create: `src/tachikoma/workflows/model.py`
- What to do:
  - `StepState` type alias: `Literal["pending", "started", "completed", "skipped"]`
  - `WorkflowState` frozen dataclass: id (str UUID), skill_name, workflow_name, current_step (str | None), step_states (dict[str, StepState]), definition_snapshot (list[dict]), scratchpad_path (str), deleted_at (datetime | None), created_at (datetime), updated_at (datetime)

  - `get(workflow_id) -> WorkflowState | None` — non-deleted only
  - `get_active(skill_name, workflow_name) -> WorkflowState | None` — for duplicate prevention
  - `update(workflow_id, **fields) -> WorkflowState | None` — always bumps updated_at
  - `soft_delete(workflow_id) -> bool` — set deleted_at
  - `list_active() -> list[WorkflowState]` — all non-deleted
  - `list_stale(threshold: timedelta) -> list[WorkflowState]` — non-deleted with updated_at older than threshold

### Steps

#### Step 10: Create Pydantic arg models for workflow tools

- Create: `src/tachikoma/workflows/tools.py`
- What to do: Define Pydantic BaseModel subclasses:
  - `StartWorkflowArgs`: skill_name (str), workflow_name (str)
  - `UpdateWorkflowStateArgs`: workflow_id (str), step (str), action (Literal["start", "complete", "skip"])
  - `GetWorkflowStateArgs`: workflow_id (str)
  - `EndWorkflowArgs`: workflow_id (str), action (Literal["complete", "abort"])
  - `ListActiveWorkflowsArgs`: (no fields)
- Test: Pydantic validation for each model

#### Step 11: Implement extracted handler functions

- In: `src/tachikoma/workflows/tools.py`
- What to do: Implement standalone async handler functions (all testable without SDK):
  - `handle_start_workflow(skill_name, workflow_name, registry, repository, workspace_path) -> dict`:
    - Look up workflow definition from registry → error if not found
    - Check for existing active workflow → error with existing ID
    - Validate workflow has steps → error if empty
    - Create scratchpad file at `.tachikoma/scratchpads/workflow-{id}.md`
    - Create WorkflowState record with definition snapshot
    - Return: step list + scratchpad_path + guidance text (template below)
  - `handle_update_workflow_state(workflow_id, step, action, registry, repository) -> dict`:
    - Get state, validate transition (Step 12), update step_states
    - On start/complete: read and return step's instructions.md content
    - Bump updated_at
    - Detect workflow completion → return completion message
  - `handle_get_workflow_state(workflow_id, repository) -> dict`: Return full state
  - `handle_end_workflow(workflow_id, repository, workspace_path) -> dict`: Soft-delete + delete scratchpad
  - `handle_list_active_workflows(repository) -> dict`: Return all active

  **Guidance template for start_workflow** (tunable prompt engineering):
  ```
  Workflow started: {workflow_name}

  ## Steps
  {numbered step list with titles and skippable markers}

  ## Getting Started
  1. Use TodoWrite to create tasks for each step above
  2. Save your workflow ID ({workflow_id}) to your scratchpad file at {scratchpad_path} for recovery if context is lost
  3. Call update_workflow_state with workflow_id="{workflow_id}", step="<step_id>", action="start" to begin a step

  ## Progressing
  - Use action="start" to begin a step (returns its instructions)
  - Use action="complete" to finish a started step
  - Use action="skip" to skip a skippable step

  ## Recovery
  If you lose context, call list_active_workflows() to find your workflow, then get_workflow_state() to resume.
  ```
- Test: Each handler tested independently with mocked registry/repository

#### Step 12: Implement transition validation logic

- In: `src/tachikoma/workflows/tools.py`
- What to do: Implement `validate_transition(step_states, step_id, action, definition_snapshot) -> str | None`:
  - Returns None if valid, error message string if invalid
  - Source of truth: design doc lines 77-83 transition rules:
    - `start`: step must be `pending`
    - `complete`: step must be `started` (not pending — must start before completing)
    - `skip`: step must be `skippable: true` in definition AND `pending`
    - Already completed/skipped step → error with explanation
    - Invalid step ID → error listing valid step IDs
- Test: All transition rules, edge cases, error messages

#### Step 13: Create MCP tool server factory

- What to do: Implement `create_workflow_tools_server(repository, skill_registry, workspace_path) -> McpSdkServerConfig`:
  - Factory function following DES-006 pattern (reference: `src/tachikoma/tasks/tools.py:58-382`)
  - 5 tool functions using @tool decorator, each calling extracted handlers
  - Return `create_sdk_mcp_server(name="workflow-tools", tools=[...])`
- Test: Integration test with real handlers
