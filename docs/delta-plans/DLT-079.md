#### Step 1: Update TOOL_DISPLAY["Bash"] to prefer description over command

- Modify: `src/tachikoma/display.py`
- What to do: Change the `"Bash"` entry in `TOOL_DISPLAY` from always showing `command` to preferring `description` when present. The current entry is:
  ```python
  "Bash": lambda inp: f"Running: {inp.get('command', '...')}",
  ```
  Replace with a lambda that checks for `description` first:
  - If `inp.get("description")` is truthy → return the description text directly (no "Running:" prefix)
  - Else → return `f"Running: {inp.get('command', '...')}"`

  This aligns the live display with `_format_bash_summary()` which already prefers description. Note: this intentionally changes REPL live display behavior for Bash — when both description and command are present, the REPL will now show description instead of command. This is the spec-sanctioned Bash-only exception in R4.
- Test: Run `just test tests/test_display.py` — all existing tests pass (none assert TOOL_DISPLAY Bash with both fields present).

### Steps

#### Step 5: Add code_wrap() utility

- Create: function in `src/tachikoma/telegram.py` (module-level, after constants, before ResponseRenderer)
- What to do: Implement `code_wrap(text: str) -> str`:
  ```python
  # After the EDIT_THROTTLE_INTERVAL constant:

  # If text contains no backticks → wrap in single backticks: `text`
  # If text contains backticks → wrap in double backticks with space padding: `` text ``
  # Space padding per CommonMark 6.1: prevents parser confusion when content starts/ends with backtick
  ```
- Test: Unit tests in Step 9.

#### Step 6: Add TELEGRAM_TOOL_DISPLAY map

- Create: constant in `src/tachikoma/telegram.py` (module-level, after code_wrap)
- What to do: Define `TELEGRAM_TOOL_DISPLAY` dict. The 6 included tools (Read, Grep, Glob, Bash, Edit, Write) apply `code_wrap()` to their extracted arguments. Agent and ToolSearch produce the same output as the shared map (no code wrapping). Unknown tools are handled by the fallback in handle_tool(), not in this map.

  Important: `TELEGRAM_TOOL_DISPLAY["Grep"]` must NOT include single quotes around the pattern — the shared `TOOL_DISPLAY["Grep"]` has quotes (`f"Searching for '{pattern}'"`) but the Telegram version relies on code_wrap for visual grouping instead. Same pattern applies to display (Glob has no quotes in shared but this is noted for clarity).

  ```python
  # TELEGRAM_TOOL_DISPLAY: dict[str, Callable[[dict[str, Any]], str]]
  # Read → f"Reading {code_wrap(inp.get('file_path', '...'))}"
  # Grep → f"Searching for {code_wrap(inp.get('pattern', '...'))}"  (NO single quotes)
  # Glob → f"Globbing {code_wrap(inp.get('pattern', '...'))}"
  # Bash → prefer description: code_wrap(description) if present, else f"Running: {code_wrap(command)}"
  # Edit → f"Editing {code_wrap(inp.get('file_path', '...'))}"
  # Write → f"Writing {code_wrap(inp.get('file_path', '...'))}"
  # Agent → same as shared (no code wrap, with fallback for missing description)
  # ToolSearch → same as shared (no code wrap)
  ```
  Add `from typing import Any` to the imports (needed for the type annotation; `Callable` is already imported from `collections.abc`).
- Test: Unit tests in Step 9.

#### Step 7: Add TELEGRAM_TOOL_SUMMARY map

- Create: constant in `src/tachikoma/telegram.py` (after TELEGRAM_TOOL_DISPLAY)
- What to do: Define `TELEGRAM_TOOL_SUMMARY` with code-wrapped arguments and no single quotes on Grep/Glob (R6). The Bash entry follows the same logic as `_format_bash_summary()` in display.py but with code_wrap applied.
  ```python

  # Glob → f"globbing {code_wrap(pattern)}" or "globbing a pattern"  (NO quotes — R6)
  # Bash → code_wrap(lowercased description) if present, else f"running: {code_wrap(truncated_cmd)}", else "running a command"
  # Edit → f"editing {code_wrap(basename(file_path))}" or "editing a file"
  # Write → f"writing {code_wrap(basename(file_path))}" or "writing a file"
  # Agent → same as shared (no code wrap)
  # ToolSearch → same as shared
  ```
  Add `from os.path import basename` to the imports.
- Test: Unit tests in Step 9.
