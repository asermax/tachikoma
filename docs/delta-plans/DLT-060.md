### Steps

#### Step 5: Create update checker module with core logic

- Create: `src/tachikoma/updates/checker.py`
- What to do:
  - Define `UpdateCheckResult` frozen dataclass: `current_version: str`, `latest_version: str | None`, `update_available: bool`, `latest_is_prerelease: bool`
  - Implement `fetch_latest_version() -> str | None`: synchronous function using `urllib.request.Request` with `User-Agent: TachikomaUpdateChecker` header to GET `https://pypi.org/pypi/tachikoma-agent/json`. Parse JSON, extract `info.version`. Return `None` on any error. Wrap in try/except catching `URLError`, `json.JSONDecodeError`, `KeyError` — log at warning level.
  - Implement `check_for_update() -> UpdateCheckResult`: reads installed version via `importlib.metadata.version("tachikoma-agent")`, calls `fetch_latest_version()`, parses both with `packaging.version.Version`, compares. Returns frozen dataclass with results. Handles: pre-release filtering (`is_prerelease`, `is_devrelease`), dev build ahead of stable, missing latest (None). Logs at debug level only.
  - Implement `async def update_checker_tick(app_state_repo: AppStateRepository, bus: EventBus) -> None`: the scheduled tick function. Calls `check_for_update()` via `asyncio.to_thread()`. If update available and not prerelease: reads `app_state.get("updates.last_notified_version")` → if different from latest: dispatches notification via `dispatch_notification(bus, "Update Checker", f"A new version of tachikoma-agent is available: {current} → {latest}", severity="info", source_id="update_checker", priority=Priority.NORMAL)`, then writes `app_state.set("updates.last_notified_version", latest)`. Catches all exceptions from app_state operations at warning level. Logs at debug level for no-update cases.
- Test: In `tests/test_updates.py`, create `class TestFetchLatestVersion` with tests using `unittest.mock.patch` on `urllib.request.urlopen` — success returns version, network error returns None, malformed JSON returns None, missing key returns None. Create `class TestCheckForUpdate` with mocked `fetch_latest_version()` and `importlib.metadata.version()` — update available, already on latest, dev build ahead, prerelease on PyPI, PyPI unreachable. Create `class TestUpdateCheckerTick` with mocked `check_for_update()`, `AppStateRepository`, and `EventBus` — notify on new version, skip on already notified, skip on no update, handle DB error gracefully.

#### Step 7: Create MCP tool and package init

- Create: `src/tachikoma/updates/tools.py`
- Create: `src/tachikoma/updates/__init__.py`
- What to do (tools.py):
  - Define `CheckUpdatesArgs(BaseModel)` — empty model (no args needed, per DES-006 pattern for tools with no parameters).
  - Define `async def handle_check_updates(app_state_repo: AppStateRepository) -> dict` — extracted handler that calls `check_for_update()` via `asyncio.to_thread()` and returns the `UpdateCheckResult` as a dict. No notification, no dedup update — purely informational.
  - Define `def create_update_tools_server(app_state_repo: AppStateRepository) -> McpSdkServerConfig` — factory that creates a `check_updates` tool using the handler. Returns `create_sdk_mcp_server(name="update-checker", version="1.0.0", tools=[...])`.
- What to do (__init__.py): Re-export public API: `update_checker_tick` from `checker`, `updates_hook` from `hooks`, `create_update_tools_server` from `tools`.
- Test: In `tests/test_updates.py`, create `class TestCheckUpdatesTool` with mocked `check_for_update()` — verify `handle_check_updates()` returns structured dict with correct fields and does NOT call `dispatch_notification` or `app_state.set`. Verify imports work: `from tachikoma.updates import update_checker_tick, updates_hook, create_update_tools_server`.

## Notes

- ADR-013 was created alongside this delta's design — the `app_state` table is a cross-cutting infrastructure piece that future deltas (migration tracking) will also use.
- ETag/If-None-Match caching is explicitly deferred — one GET per day is negligible bandwidth.
- `packaging` is already a transitive dependency (via Pydantic) — no new dependency needed.
- The MCP tool has zero side effects (no notification, no dedup update) — safe for the agent to call at any time.
- DLT-061 (Apply agent update) will consume update detection but is a separate delta.
