## Overview

Collapse is a **renderer-only, payload-composition** feature. The buffer, the baked `_🔧 <summary>_` markers, paragraph gating, throttle, overflow commit, and the broken-render fallback all stay byte-identical. Collapse only changes *how the live message is composed into a `TelegramPayload`* once a boundary count exceeds a threshold. Three batches follow the dependency graph:

```
Batch 1 (entities.ts helpers) ─────────┐
                                       ├──► Batch 3 (collapse-aware compose/finalize)
Batch 2 (config keys + boundary counter)┘
```

Batches 1 and 2 are independent; Batch 3 consumes both.

### Steps

#### Step 1: Add `wrapExpandable(payload)` and tests

- Create/modify: `src/extensions/telegram/entities.ts`
- What to do: Export a pure helper that wraps a converted payload in one `expandable_blockquote` span. The entity is `{ type: "expandable_blockquote", offset: 0, length: payload.text.length }` prepended to `payload.entities`; the text and inner-entity offsets are unchanged (they nest inside). 
  Place it at the bottom of `entities.ts` (after `splitMessageWithEntities`):
  ```ts
  // export const wrapExpandable = (payload: TelegramPayload): TelegramPayload => {
  //   // text unchanged; prepend ONE expandable_blockquote entity { offset: 0, length: payload.text.length }
  //   // over payload.entities — inner entities keep their offsets (they nest validly inside).
  // };
  ```
  The `MessageEntity["type"]` union already includes `"expandable_blockquote"` (spike Q1), so this type-checks with no cast. Do not change the text or the inner entities' offsets.
- Test: in `tests/telegram/entities.test.ts`, add a `describe("wrapExpandable")` block. Assert the blockquote entity is present with `offset: 0, length: payload.text.length`, that inner entities (e.g. an `italic` from a `_🔧 …_` summary) survive with unchanged offsets, and that wrapping plain text (no inner entities) yields exactly one entity. Reuse `toTelegramEntities` to build the input payload so the inner entities are realistic.

#### Step 2: Add `concatPayloads(a, b, sep?)` and tests

- Create/modify: `src/extensions/telegram/entities.ts`
- What to do: Export a pure helper that joins two payloads, rebasing `b`'s offsets after `a.text` + separator. Default `sep = "\n\n"`. **Empty-operand rule:** returns `a` unchanged when `b.text` is empty, `b` unchanged when `a.text` is empty (no separator added in either case); only when both are non-empty does it produce `a.text + sep + b.text` with `b`'s entities rebased by `a.text.length + sep.length`. This empty-operand rule is what makes the all-intensive case (no tail) drop cleanly.
  ```ts
  // export const concatPayloads = (a: TelegramPayload, b: TelegramPayload, sep = "\n\n"): TelegramPayload => {
  //   // empty operand → return the other unchanged (NO separator);
  //   // both non-empty → text = a.text + sep + b.text; rebase each of b.entities by a.text.length + sep.length.
  // };
  ```
- Test: in `tests/telegram/entities.test.ts`, add a `describe("concatPayloads")` block. Assert: (a) `b`'s entities are rebased by exactly `a.text.length + sep.length`; (b) an empty `b` returns `a` unchanged and adds no separator; (c) an empty `a` returns `b` unchanged; (d) a custom `sep` is reflected in the joined text and offset delta; (e) entities from both operands survive and point at the correct substrings of the joined text.

#### Step 5: Add boundary counter + `collapseActive()` predicate to the renderer

- Create/modify: `src/extensions/telegram/streaming.ts`
- What to do: Accept the two new constructor params as **trailing optionals with defaults** (`collapseIntensiveWork = true`, `intensiveWorkThreshold = 4`) so existing tests are unaffected. Store them as private fields. Add private counter state (`boundaryCount`, initialized to `0` on the field — the renderer is per-exchange, so a fresh exchange is a fresh counter). Implement:
  ```ts
  // constructor gains trailing params: collapseIntensiveWork = true, intensiveWorkThreshold = 4
  // private boundaryCount = 0;
  //
  // collapseActive(): enabled && boundaryCount STRICTLY exceeds threshold (trigger, not quota; no floor).
  //   — expose as a non-private internal query (Batch 3's compose/finalize call it; the detection suite reads it).
  //
  // appendText: a boundary forms when text resumes after tools.
  //   — capture (pendingTools.length > 0) BEFORE bakePendingTools() clears them; if true, boundaryCount += 1.
  //   — one increment per tool→text transition regardless of how many tools the block held.
  // showTransient: MUST NOT increment (status is not a boundary).
  // finalize's bake of a trailing tool block (no following text): naturally excluded — the increment
  //   lives only in appendText, so trailing tools add no boundary (R9).
  //
  // resetMessageBoundary(): sets boundaryCount = 0. Call sites:
  //   — commitOverflow: AFTER the full chunks are committed and the tail keeps streaming, so the tail
  //     message is evaluated independently (R9). (Batch 3 refines commitOverflow to evaluate-then-reset.)
  //   — nowhere else: the field initializer covers a fresh renderer, and the renderer is discarded at
  //     finalize, so no reset is needed there.
  ```
- Test: see Step 6. **Verification note:** the counter's entire job is to drive `collapseActive()`, so the detection suite asserts directly on that predicate (and the raw count where helpful) — this is a *complete* verification of detection logic, not a weak intermediate. The *payload-effect* ACs (what the fold looks like) are validated in Batch 3 once the predicate is consumed.

### Steps

#### Step 7: Structured-payload compose in `flush()`

- Create/modify: `src/extensions/telegram/streaming.ts`
- What to do: Add a collapse-aware payload builder and route both the send and edit call sites through it. Define the **positional intermediate/tail split** in markdown terms (per design S3 / Shared Logic):
  - `tailMd` = `this.transient ?? <held trailing paragraph>` — the transient line (running tool/status) when one is showing, else the streaming trailing paragraph (the buffer content after `streamableBuffer()`'s last `\n\n`).
  - `intermediateMd` = `streamableBuffer()` — all settled content (the completed `_🔧 <summary>_` markers and bridging text) chronologically before the tail.
  - Build: `collapsePayload = concatPayloads(wrapExpandable(toTelegramEntities(intermediateMd)), toTelegramEntities(tailMd))`.
  - Introduce `composePayload(): TelegramPayload` returning `collapseActive() ? collapsePayload : toTelegramEntities(this.compose())`, so both branches share one entry point.
  ```ts
  // Add composePayload(): TelegramPayload — returns the collapse payload when collapseActive(),
  //   else toTelegramEntities(this.compose()) (today's path). One entry point for both branches.
  // flush(): keep computing `display` for the empty/unchanged short-circuit guard, then send/edit
  //   composePayload() instead of toTelegramEntities(display) at BOTH call sites (send + edit).
  //   (sendText becomes a payload-taking helper, or inline sendWithFallback here.)
  ```
  Because `compose()` is still called for the inactive branch and for the early `display.length === 0 / === lastRendered` short-circuit, keep computing `display` for that guard and switch only the *payload* construction on `collapseActive()`. This makes the retroactive fold free — the payload is rebuilt from the buffer on every flush, exactly as the header/body are today.
- Test: covered by the behavioral suite in Step 11 (retroactive fold on crossing, in-progress tool stays expanded as the live tail).

#### Step 8: Structured-payload `finalize()` (incl. all-intensive)

- Create/modify: `src/extensions/telegram/streaming.ts`
- What to do: In `finalize()`, after `bakePendingTools()` (which bakes a trailing tool block into the buffer — the all-intensive case) and after the `broken` short-circuit to `finalizeBroken` (unchanged, no collapse), build the finalized payload on the collapse branch. At finalize `transient` is null, so the split is intermediate = everything before the final paragraph, tail = the final paragraph.
  ```ts

  //   body = concatPayloads(wrapExpandable(convert(intermediateMd)), convert(tailMd))
  //     — all-intensive (empty tail): concatPayloads returns wrapExpandable(intermediate) unchanged → whole body is the block (R10).
  //   headerPayload = header ? convert(headerText()) : empty  — prepended via concatPayloads so it anchors ABOVE, never inside the block.
  //   chunk the assembled payload via splitMessageWithEntities and reuse the existing edit-first/send-rest loop.
  // The non-collapse branch (convertAndSplit(header + body)) stays for collapseActive() === false.
  ```
  Reuse the existing per-chunk edit-first/send-rest loop. The empty-text → delete + return null guard still applies first.
- Test: behavioral suite (Step 11) — intensive turn folds to header → block → final answer; all-intensive turn's whole body is the collapsed block (no expanded content outside it); threshold crossed on the final boundary → whole message is the block.

#### Step 9: Overflow / commit collapse evaluation + reset ordering

- Create/modify: `src/extensions/telegram/streaming.ts`
- What to do: This is the most intricate interaction in the delta — the design's **Data Flow → Overflow** + **Cross-Layer Contracts → Renderer→chunker** + **S3** are the authoritative reference; read them before coding. The `commitOverflow()` loop already converts each committed chunk (all but the last) and sends/finalizes it, keeping the tail raw. R9 requires detection to reset at each message split, so the ordering is:
  ```ts
  // commitOverflow(): for each committed chunk (chunks.slice(0, -1)):
  //   payload = collapseActive() ? wrapExpandable(toTelegramEntities(chunk))   // all-intermediate: no tail
  //                              : toTelegramEntities(chunk);                   // today's inline path
  //   edit-in-place or send the chunk (unchanged loop body)
  // AFTER the loop: resetMessageBoundary()   // the tail message starts fresh and is evaluated independently (R9)
  // keep the tail raw and streaming (unchanged)
  ```
  **Ordering decision (reset once, after all commits):** the committed chunks are the accumulated message's content and share the running `collapseActive()` state at commit time; the reset happens **once, after the loop**, so the tail is the only thing re-evaluated from zero. Do not reset per-chunk (the committed chunks share one tally) and do not reset before the loop (the committed chunks would lose their intensiveness).
  **Primary vs fallback case (from the design):** in the common case `commitOverflow` fires *before* the collapse region grows large, so `collapseActive()` is false and committed chunks render exactly as today (inline) — "the collapsed block lives in the tail message." The fallback — a committed chunk that was *already* intensive (`collapseActive()` true at commit) — carries its own collapsed block (`wrapExpandable(convert(chunk))`); prepend the header on the first committed chunk per the existing header-rides-first-chunk rule (DES-009). A committed message is never edited again, so it is never retroactively collapsed (R9). The collapsed block lives within one ≤4096 message, so `splitMessageWithEntities` (drops only entities with `length > limit`) never drops the `expandable_blockquote`.
  If per-chunk boundary attribution proves ambiguous in practice, resolve conservatively: treat the running count as the committed message's count and reset for the tail, favoring the design's "collapse block lives in the tail" statement. Note any deviation in the plan's Notes.
- Test: behavioral suite (Step 11) — a long intensive turn split at the 4096 limit: each message evaluated independently; an already-committed message never retroactively collapsed; a single committed chunk that itself exceeded the threshold carries its own collapsed block; the tail re-accumulates boundaries from zero and can independently become intensive.

#### Step 10: Header anchoring above the block + best-effort overflow drop order

- Create/modify: `src/extensions/telegram/streaming.ts`
- What to do: Ensure the decision header (DES-009) anchors **outside and above** the collapsed block on every compose/finalize — it is converted separately (`toTelegramEntities(headerText())`) and prepended via `concatPayloads`, **never** nested inside the `expandable_blockquote` span (design S6). For the over-limit case, apply the existing best-effort drop order (DES-009): the transient is part of the live tail; if header + body exceeds the edit limit, drop in priority order and log the descriptor — the collapsed block is part of the body. The completion-push copy-delete, `error`/`status` transient lines, and the `finalizeBroken` → `sendChunked` plain fallback are **untouched** (collapse is skipped on the broken path so a blockquote-entity failure can never block delivery).
- Test: behavioral suite (Step 11) — header anchored above the block and recomposed across edits; `collapseIntensiveWork === false` and below-threshold turns render exactly as today; broken-render fallback delivers plain inline text with no block.

## Notes

- The constructor params are trailing + defaulted (`collapseIntensiveWork = true`, `intensiveWorkThreshold = 4`) so the existing `StreamRenderer` and DLT-181 header suites pass unchanged — below-threshold turns render byte-identically (R8).
- "tool→text segment" names the *completing* transition (text resumes after tools); real segments read "text + tools." Counting is direction-robust; collapse is positional. See design → Modeling.
- The boundary increment lives in `appendText` (text resumes after tools), so a trailing tool block baked only at `finalize` is naturally excluded from the count — no special-case needed for R9's "trailing tools add none."
- `expandable_blockquote` is renderer-driven; the markdown→entity converter still emits only `blockquote` for `>` (S4 / spike). `>` continues to map to an expanded blockquote.

- **Batch 3 fakeApi entity capture:** the `ApiCall` fixture records `other?.entities` only when non-empty, so plain-text calls stay field-free and the existing strict `toEqual` assertions keep passing untouched. Four existing assertions whose rendered text carries an italic span (the `_🔧 …_` marker / `_Compacting…_` / the DLT-181 header) were switched from `toEqual` to `toMatchObject` — semantically equivalent (they still assert `{type, text, messageId}`) but tolerant of the now-captured entity list. In the common case (collapse inactive at commit) chunks render inline exactly as today and the header stays on the tail.
