#### Step 1.2: Implement source models in `plugins/sources.py`

- Create: `src/tachikoma/plugins/sources.py`.
- What to do:
  - Define three frozen Pydantic models (`extra="forbid"`, `frozen=True`):
    - `GitPluginSource` — fields `git: str`, `subdir: str | None = None`, `ref: str`. Add `field_validator("git", mode="before")` that expands `gh:<owner>/<repo>` and `github:<owner>/<repo>` to `https://github.com/<owner>/<repo>.git`. Add `field_validator("ref", mode="after")` that rejects SHA-shaped refs via regex `^[0-9a-f]{7,40}$` (AC-PSD-11).

    - Dispatches to the matching variant; lets variant validators raise the field-specific errors (AC-PSD-4 covers missing `ref`).

#### Step 2.3: Implement `parse_manifest` with native-takes-precedence

- Modify: `src/tachikoma/plugins/manifest.py`.
- What to do:
  - `parse_manifest(plugin_dir: Path) -> PluginManifest | None`:
    1. If `plugin_dir / "tachikoma-plugin.toml"` exists: read with `tomllib` (stdlib), validate via `TachikomaManifest`, resolve `skills` to absolute paths inside `plugin_dir`, run the resolve-stays-within check, return `PluginManifest(source_format="tachikoma", …)`.

    4. Return `None` only if neither manifest exists (Step 2.4 handles the resulting `failed` status diagnostic).
  - When both manifests are present, the Tachikoma one wins (AC-MP-5); the CC one is skipped entirely with no INFO log emitted for ignored CC contribution types in that case.

One test per contribution type permutation (e.g., only `commands`; `commands + mcpServers`; native + CC together → returns empty list because native-takes-precedence skips CC entirely).

### Steps

#### Step 3.1: Implement `_atomic_replace_dir` helper

- Create: `src/tachikoma/plugins/materializer.py` with the helper.
- What to do:
  - Function signature: `def _atomic_replace_dir(new: Path, dst: Path) -> None`.
  - Three-step rename pattern with rollback:
    1. If `dst` exists, `os.rename(dst, dst.with_suffix(dst.suffix + ".old"))` (or use a sibling with `dst.parent / f"{dst.name}.old"`).
    2. `os.rename(new, dst)`. If this raises, rename `dst.old` back to `dst` and re-raise.
    3. `shutil.rmtree(dst.with_name(dst.name + ".old"), ignore_errors=True)`.
  - All staging directories (`new`, `dst.old`) live alongside `dst` in the same filesystem (the bootstrap hook ensures the staging area sits under `.tachikoma/plugins/.staging/`).
- Code-snippet placement:

```python

#     # If dst exists, rename to "<dst>.old" first
#     # Rename new → dst; on failure, restore dst from .old and re-raise
#     # shutil.rmtree(.old, ignore_errors=True) — non-atomic but post live-path stable
```

#### Step 3.3: Implement `materialize_git`

- Modify: `src/tachikoma/plugins/materializer.py`.
- What to do:
  - Use `tempfile.TemporaryDirectory` for the clone destination.
  - Call `await run_git("clone", "--depth", "1", "--branch", source.ref, source.git, tmp_clone, cwd=...)`. The existing `run_git` raises `RuntimeError` on failure — wrap into `MaterializeError`.
  - If `source.subdir` is set, copy `tmp_clone / source.subdir` into `staging`; else copy `tmp_clone`.
  - Reject `subdir` paths that contain `..` segments or resolve outside `tmp_clone` (defense-in-depth — not a spec AC; mirrors the manifest path-traversal protection in Step 2.2 to harden against malicious or buggy config).
- Test: covers happy path with mocked `run_git`; failed clone; missing subdir; subdir traversal rejection (defense-in-depth).

#### Step 3.4: Implement `materialize_url` with auto-strip

- Modify: `src/tachikoma/plugins/materializer.py`.
- What to do:
  - Stream `urllib.request.urlopen(source.url)` into a tempfile inside `tempfile.TemporaryDirectory()`. Wrap blocking calls in `loop.run_in_executor`. (HTTPS verification is on by default per PEP 476.)
  - Detect format by suffix: `.tar.gz`/`.tgz` → `tarfile.open(filepath, mode="r:gz")` with `extraction_filter="data"` (or set `tar.extraction_filter = tarfile.data_filter` if compatibility requires); `.zip` → `zipfile.ZipFile`.
  - Extract into a sibling `extract_root` temp directory.
  - Auto-strip: if `extract_root` contains exactly one entry and it is a directory, rebind `extract_root = extract_root / single_entry`. Otherwise keep `extract_root` as-is (AC-REC-12).
  - If `source.subdir` is set, resolve `extract_root / source.subdir` (rejecting `..` traversal); else use `extract_root` as the install root (AC-REC-13).
  - Copy that root into `staging` via `shutil.copytree`.
  - Errors (HTTP non-2xx, archive corruption, network failure): wrap as `MaterializeError`.
- Test: `tests/plugins/test_materializer.py`:
  - Happy path with a fixture-built `.tar.gz` (single top-level dir → auto-strip applied).
  - Multi-top-level-entry archive → no auto-strip.
  - `subdir` composes after auto-strip.
  - Mock `urlopen` for non-2xx and connection errors.
  - `.zip` variant exercise.
  - Path-traversal entry inside the archive → rejected by tarfile data filter / explicit zipfile guard.

#### Step 3.5: Implement the reconciler

- Create: `src/tachikoma/plugins/reconciler.py`.
- What to do:
  - Define `ReconcileOutcome` (frozen dataclass): `alias`, `status: Literal["loaded", "stale-fallback", "failed"]`, `diagnostic: str | None`. Define `ReconciliationReport` (frozen dataclass): `outcomes: list[ReconcileOutcome]`.
  - `async def reconcile(workspace_path: Path, plugins: dict[str, PluginSource]) -> ReconciliationReport`:
    1. Compute `install_dir = workspace_path / ".tachikoma" / "plugins"`. Create if missing (idempotent — but the hook does this too; reconciler is robust to either ordering).
    2. Compute orphan set: existing immediate subdirectories of `install_dir` (excluding `.staging/`) minus configured aliases. Remove each via `shutil.rmtree(orphan, ignore_errors=False)`; on permission error, log WARNING and continue (orphan removal is best-effort).
    3. For each `(alias, source)` in config: dispatch to materializer per variant inside `try/except MaterializeError, Exception`. On success → `_atomic_replace_dir(staging, install_dir / alias)`; record `loaded`. On materialize failure: invoke `_handle_stale_fallback`.
  - `_handle_stale_fallback(alias, install_dir, error) -> ReconcileOutcome`:
    - If `(install_dir / alias).exists()`, run `parse_manifest` on it. If a `PluginManifest` returns and `manifest.name == alias` → log WARNING with the original error, return `stale-fallback` outcome carrying the diagnostic.
    - Else log ERROR, return `failed` with the diagnostic.
- Code-snippet placement:

#### Step 3.6: Implement discovery (loader)

- Create: `src/tachikoma/plugins/loader.py`.
- What to do:
  - Define `LoadedPlugin` (frozen dataclass): `alias`, `source: PluginSource`, `manifest: PluginManifest | None`, `status: Literal["loaded", "stale-fallback", "failed"]`, `diagnostic: str | None`, `plugin_dir: Path`, `contributed_skills: list[Skill] = field(default_factory=list)`. **Note**: `contributed_skills` is a mutable `list` field — the skills listener (Step 5.4) extends it in place after registry registration so the manager's reference and the listener's reference point to the same list object. Frozen dataclasses still permit in-place mutation of mutable field values; this is the chosen pattern instead of `dataclasses.replace` to keep the manager's ref live.
  - `def discover(install_dir: Path, report: ReconciliationReport, plugin_sources: dict[str, PluginSource]) -> list[LoadedPlugin]`:
    1. For each `outcome` in `report.outcomes`:
       - For `failed`: build a `LoadedPlugin(status="failed", manifest=None, diagnostic=…)`.
       - For `loaded` or `stale-fallback`: call `parse_manifest(plugin_dir)`. If parse fails, downgrade to `failed` with the parse diagnostic.
       - Validate each declared skill dir exists; missing dirs WARN and are excluded; if all are missing, plugin still loads with empty `skill_dirs` (AC-MP-8).
       - Build the `LoadedPlugin`.
       - Call `log_ignored_cc_contributions(alias, manifest)` from Batch 2.

## Notes

- The design notes that `_append_missing_entries` is currently private in `git/hooks.py`. Step 7.1 chooses the lightweight option: inline a tiny `_ensure_gitignore_entry(path, entry)` in `plugins/hooks.py` rather than touching `git/hooks.py`. If the implementer prefers to lift the helper to a shared utility (e.g., `tachikoma/workspace.py` or a new `tachikoma/utils/gitignore.py`), that is also acceptable — both options preserve idempotency and avoid a cross-module private import.
- The `EventBus` is hoisted to before `bootstrap.run()` per Step 7.3 (currently constructed post-bootstrap at `__main__.py:275`). The hoisted instance is stashed in `bootstrap.extras["event_bus"]` and reused by every downstream consumer — no second `EventBus()` construction.
- The session-registry's `get_active_session()` (async, registry.py:184) returns `Session | None`. The listener early-returns when `None` (no active session — common during background-task processing or before any user message). Step 5.4 covers this case in tests.
- Per the design's "MCP tools — install" flow, the manager's collision check covers BOTH the in-memory `_loaded` map AND the on-disk config (defensive — should be in sync but a double-check costs nothing and protects against drift).
- The `_skill_sources` / `_namespaced_source_paths` split is a hard contract: `_skill_sources` holds only default-namespace paths, `_namespaced_source_paths` holds plugin paths. `add_namespaced_source` never touches `_skill_sources`, and `refresh()` (Step 4.7) re-scans both lists separately — this prevents `mark_dirty()` followed by `refresh()` from silently un-namespacing plugin skills.
- All new modules follow DES-002 logging conventions: bind a per-component logger at module level; `bind(plugin=alias)` per-call to tag every error to its plugin.
- All tests follow DES-001: mirror src structure; class-based per feature; AC IDs in docstrings; `mocker` fixture for patching; `time-machine` if any time-sensitive logic appears (none expected here). Loguru output is verified by **return values from helpers** (e.g., `log_ignored_cc_contributions` returns the list it logged), not via `caplog` (loguru does not propagate to stdlib logging).
