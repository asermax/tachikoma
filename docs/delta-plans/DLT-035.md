#### Step 2: Implement descriptor table with metadata builders and resolve_media

- Modify: `src/tachikoma/media.py`
- What to do:
  - Implement metadata builder functions for each of the 8 media types, extracting type-specific fields into description lines per spec (R1–R7):
    - Photo: dimensions (width × height), file size
    - Voice: duration (seconds), MIME type
    - Audio: title, performer, duration — omit missing fields (not "Unknown")
    - Document: original filename, MIME type, file size
    - Sticker: emoji, format (regular/animated/video)
    - Video: duration, dimensions
    - Video note: duration, diameter (length field)
    - Animation: duration, dimensions
  - Define the ordered descriptor sequence `MEDIA_DESCRIPTORS` with correct priority: animation → sticker → video_note → photo → voice → video → audio → document
  - Each descriptor's accessor extracts the media object from the message (e.g., `msg.photo[-1]` for photos)
  - Extension resolvers per the design: Photo → `.jpg`, Voice → `.ogg`, Sticker → `.tgs`/`.webm`/`.webp` by flags, Audio → from `file_name` or `.mp3`, Document → from `file_name` or empty, Video → from `file_name` or `.mp4`, Video note → `.mp4`, Animation → `.mp4`
  - Implement `resolve_media(message)` — iterate `MEDIA_DESCRIPTORS` in order, return `(media_object, descriptor)` for the first match where the message field is not None. Return `None` if no match

```python
# In src/tachikoma/media.py, after constants/types:

# _photo_metadata(media) -> ["1280 × 720", "245 KB"]
# _voice_metadata(media) -> ["12 seconds", "audio/ogg"]
# ... etc per design Modeling section

# MEDIA_DESCRIPTORS: ordered sequence — animation first, document last
# resolve_media(message) -> (media_object, descriptor) | None
```

#### Step 3: Implement download_media with size pre-check and error handling

- Modify: `src/tachikoma/media.py`

  - Define `MediaTooLargeError` exception class with a `file_size` attribute for the error message
  - Implement `download_media(bot, media_object, dest_path)` → `Path`:

    - Call `await bot.download(media_object, destination=dest_path)` to save the file
    - On `TelegramAPIError` / `TelegramBadRequest`: let the exception propagate (handler catches it)
    - Return the destination path on success

#### Step 9: Add \_handle\_media handler and register media filter

- Modify: `src/tachikoma/telegram.py`
- What to do:
  - Import from `media.py`: `resolve_media`, `download_media`, `build_description`, `generate_media_filename`, `MediaTooLargeError`, `MEDIA_TEMP_DIR`
  - In `TelegramChannel.__init__`, after the text handler registration, register the media handler:
    ```python
    self._router.message(
        F.photo | F.voice | F.audio | F.document | F.sticker | F.video | F.video_note | F.animation
    )(self._handle_media)
    ```
  - Add `_handle_media(self, message: Message) -> None` to `TelegramChannel`:
    1. Call `resolve_media(message)` → `(media_object, descriptor)` or `None`
    2. If `None` (defensive): return
    3. Generate filename: `generate_media_filename(descriptor, media_object)`
    4. Build destination path: `MEDIA_TEMP_DIR / filename`
    5. Try `await download_media(self._bot, media_object, dest_path)`:
       - Catch `MediaTooLargeError`: send error message to user with actual size (e.g., "This file is too large to download (XX MB). Telegram bots can only download files up to 20 MB."), return
       - Catch `TelegramAPIError`: log error, send "Failed to download the file. Please try again." to user, return
    6. Build metadata lines: `descriptor.build_metadata(media_object)`
    7. Build description: `build_description(descriptor.label, metadata_lines, dest_path, message.caption)`
    8. `self._coordinator.enqueue(description)`
    9. If `self._is_processing`: return (buffered, same as text)
    10. `await self._process_through_coordinator()`
