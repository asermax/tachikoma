#### Step 1: Create RestartRequested event type

#### Step 2: Create editable install detection function

- Create: `src/tachikoma/updates/apply.py`
- What to do: Implement `_is_editable_install() -> bool` that reads `direct_url.json` via `importlib.metadata.distribution("tachikoma-agent").read_text("direct_url.json")`. Parse JSON, check `dir_info` → `editable`. Return `False` if file missing or malformed (fallback = assume non-editable). Log warnings on parse failures.
- Test: Unit test — mock `importlib.metadata.distribution` to return editable JSON, non-editable JSON, missing file, malformed JSON

#### Step 3: Create upgrade execution function

- In: `src/tachikoma/updates/apply.py`
- What to do: Define `@dataclass(frozen=True) class UpgradeResult:` with fields: `old_version: str`, `new_version: str | None`, `already_up_to_date: bool`, `error: str | None`, `changed: bool`. Implement `run_upgrade() -> UpgradeResult`. Logic:
  1. Call `_is_editable_install()` → if True, return error result with `error="editable install"`
  2. Capture `old_version = importlib.metadata.version("tachikoma-agent")`
  3. `subprocess.run(["uv", "tool", "upgrade", "tachikoma-agent"], capture_output=True, text=True, timeout=120)`
  4. If returncode != 0 → return error result with stderr
  5. Capture `new_version = importlib.metadata.version("tachikoma-agent")`
  6. If `new_version == old_version` → `already_up_to_date=True`, `changed=False`
  7. If `new_version != old_version` → `changed=True`
  8. Return result
- Test: Unit test with mocked `subprocess.run` and `importlib.metadata.version` — cover: success, already up to date, failure (non-zero exit), failure (FileNotFoundError for uv), timeout

#### Step 4: Update __init__.py exports

- Modify: `src/tachikoma/updates/__init__.py`
- What to do: Add imports: `from tachikoma.updates.events import RestartRequested` and `from tachikoma.updates.apply import run_upgrade`. Add both to `__all__`. Keep existing exports unchanged.
- Test: `python3 -c "from tachikoma.updates import RestartRequested, run_upgrade"` should not error

## Batch 3: Channel restart integration (S2, S6) — ⧗ Pending
Depends on: Batch 1, Batch 2

### Context & Research

- `docs/delta-designs/DLT-061.md` — Shape parts S2, S6; System Behavior scenarios (Successful upgrade step-by-step); Key Decisions for restart signaling and execv placement
- `src/tachikoma/updates/events.py` (from Batch 1) — `RestartRequested` event type imported by channel subscription handlers
- `src/tachikoma/repl.py` lines 123-165 — `run()` method with while loop and `prompt_async`. The flag check must go at the top of the while loop (before `prompt_async`)
- `src/tachikoma/telegram/__init__.py` lines 615-703 — `run()` method with polling. Event handler calls `stop_polling()` (same pattern as SIGINT handler at line 636)
- `src/tachikoma/__main__.py` lines 264-426 — try/finally block structure. The `async with Coordinator` block starts at line 269, `await active_channel.run(coordinator)` at line 382, `except` at line 384, `finally` at line 388 ending with `await database.close()` at line 425. `restart_needed` goes before `try` (line 264), set after `active_channel.run()` returns (inside `async with`, before it exits), `os.execv` goes after the `finally` block (after line 425)
- `src/tachikoma/buffer/events.py` — event subscription pattern: `self._bus.on(EventType, handler_method)` (used in both REPL line 134 and Telegram line 627)
- Design rationale for execv placement: `os.execv` must run after the `finally` block completes because the finally block releases all async resources (buffer stop, scheduler cancel, bus stop, DB close). This is documented in Key Decision "os.execv after the finally block"
- Concurrency guarantee: The MCP tool runs inside the SDK's tool execution context. The restart only triggers after: (1) tool returns result, (2) SDK finishes generating agent response, (3) channel renders all events to user, (4) then channel run loop checks the restart flag. This guarantees the current message exchange completes before restart.

### Out of scope
- System prompt changes (Batch 4)
- Tests (Batch 5)

### Steps

#### Step 7: Add restart support to REPL

- Modify: `src/tachikoma/repl.py`
- What to do:
  1. Add `from tachikoma.updates.events import RestartRequested` import at top
  2. Add `self._restart_requested: bool = False` in `__init__` method
  3. In `run()`, after the existing `self._bus.on(BufferedDelivery, ...)` line, add subscription: `self._bus.on(RestartRequested, self._handle_restart_requested)`
  4. Add handler method: `async def _handle_restart_requested(self, event: RestartRequested) -> None: self._restart_requested = True`
  5. At the top of the `while True` loop (line 138), before `prompt_async`: add `if self._restart_requested: break`
- Concurrency guarantee: The flag check runs at the top of the while loop, which is only reached after the current `prompt_async` + full message exchange completes. The tool returns → SDK generates response → channel renders events → loop iteration ends → flag checked. This satisfies the "restart waits for current message exchange" acceptance criterion.
- Test: `just typecheck` passes

#### Step 8: Add restart support to Telegram channel

- Modify: `src/tachikoma/telegram/__init__.py`
- What to do:
  1. Add `from tachikoma.updates.events import RestartRequested` import
  2. Add `self._restart_requested: bool = False` in `__init__`
  3. In `run()`, after the existing `self._bus.on(BufferedDelivery, ...)` line, add subscription and handler inline:
     ```python
     async def _on_restart_requested(event: RestartRequested) -> None:
         self._restart_requested = True
         await self._dispatcher.stop_polling()
     self._bus.on(RestartRequested, _on_restart_requested)
     ```
  4. Use a closure or bound method — keep it local to `run()` like the existing signal handlers
- Concurrency guarantee: `stop_polling()` causes the polling loop to exit after the current poll cycle finishes. The tool's response is rendered before the next poll iteration, so the message exchange completes before the loop exits.
- Test: `just typecheck` passes

#### Step 9: Add restart flag check and os.execv to main loop

- Modify: `src/tachikoma/__main__.py`
- What to do:
  1. Add `import os` at top (if not already present — check existing imports)
  2. Add `restart_needed: bool = False` before the `try:` block (around line 264, after `background_runner` declaration)
  3. After `await active_channel.run(coordinator)` returns (line 382, still inside `async with Coordinator`), set: `restart_needed = getattr(active_channel, '_restart_requested', False)`. This reads the flag before the `async with` block exits and `Coordinator.__aexit__` runs session cleanup.
  4. After the entire `finally:` block completes (after line 425 `await database.close()`), add:
     ```python
     if restart_needed:
         _log.info("Restarting after update...")
         os.execv(sys.argv[0], sys.argv)
     ```
     This is after all cleanup: buffer stop, scheduler cancel, background runner shutdown, bus stop, and DB close — identical to the normal quit flow, then replaces the process in-place.
- Test: `just typecheck` passes; `just lint` passes
