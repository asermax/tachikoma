### Steps

#### Step 7: Add target_session_id field to all envelope subtypes

- Create/modify: `src/tachikoma/message.py`
- What to do: Add `target_session_id: str | None = None` as a dataclass field on **all three** concrete subtypes: `TextMessage` (after `force_new`), `ButtonTapMessage` (after `value`), and `ReactionMessage` (after `removed`). This is necessary because `MessageEnvelope` is an ABC (not a dataclass), so it cannot declare instance attributes — frozen dataclass subtypes generate their own `__init__` from declared fields only, and `object.__setattr__` is blocked outside `__post_init__`. The field defaults to `None` on every subtype, so all envelope types can carry a routing instruction without callers needing to know which subtype they hold. This is consistent with DES-013: `target_session_id` is data (a routing instruction), not a behavioral hook. All consumers access it uniformly through the concrete instance.
- Test: Verify `TextMessage(text="hi").target_session_id is None`, `TextMessage(text="hi", target_session_id="abc").target_session_id == "abc"`, `ButtonTapMessage(value="x").target_session_id is None`, `ReactionMessage(added=frozenset({"👍"}), removed=frozenset()).target_session_id is None`

### Steps

#### Step 9: Add target_session_id short-circuit in send_message

- Create/modify: `src/tachikoma/coordinator.py`
- What to do: In `send_message()`, between the session creation block (ends ~line 491) and the `force_new` block (line 492), add a new block:
  ```
  # target_session_id routing: close current + reopen target
  if msg.target_session_id is not None and active is not None:
      if active.id != msg.target_session_id:
          await self._close_and_fire_postprocessing(active)
          reopened = await self._registry.reopen_session(msg.target_session_id)
          if reopened is not None:
              self._set_sdk_session_id(reopened.sdk_session_id)
              active = reopened
              is_new_session = False
          else:
              # Reopen failed — create fresh session as fallback
              _log.warning("target_session_id reopen failed, creating fresh session")
              self._clear_session_state()
              active = await self._registry.create_session()
              is_new_session = True
      # else: target is current session, no-op
  elif msg.target_session_id is not None and active is None:
      # No active session — try to open the target directly
      reopened = await self._registry.reopen_session(msg.target_session_id)
      if reopened is not None:
          self._set_sdk_session_id(reopened.sdk_session_id)
          active = reopened
          is_new_session = False
      else:
          active = await self._registry.create_session()
          is_new_session = True
  ```
  This block must come BEFORE the `force_new` check. When `target_session_id` is set, boundary detection is skipped entirely (the handler already determined the target session).
- Test: Unit test with mock registry — verify close + reopen called when target differs; verify fallback when reopen fails; verify no-op when target is current session

#### Step 15: Add session lookup to reaction handler

- Create/modify: `src/tachikoma/telegram/__init__.py`
- What to do: In `_handle_reaction()` (line 972), after computing the emoji diff:
  - Construct `ReactionMessage(added=added, removed=removed, external_id=str(event.message_id))`
  - Look up the target session: `target_id = await self._coordinator._registry.find_session_by_external_id("telegram", str(event.message_id))` if `self._coordinator._registry is not None`, else `None`
  - Get the current active session ID: `active = await self._coordinator._registry.get_active_session()` if `self._coordinator._registry is not None`
  - If `target_id` is not None and `active` is not None and `target_id != active.id`: set `target_session_id=target_id` on the envelope (construct a new frozen instance via `dataclasses.replace`)
  - If `target_id` is None or matches current session or registry is None: no `target_session_id`, route normally (graceful degradation per R6)
  - Rationale for direct `_registry` access: Telegram channel and coordinator are tightly coupled by design; adding a coordinator facade method would add surface area without meaningful encapsulation benefit.
- Test: Unit test with mock registry — reaction on message from different session sets `target_session_id`; same session or unknown ID produces no `target_session_id`

#### Step 16: Defer reactions needing session switch

- Create/modify: `src/tachikoma/telegram/__init__.py`
- What to do: Modify `_handle_reaction()` routing logic. Currently (line 989-997):
  - If delivery lock is locked → enqueue as steering (no change for session-switching reactions — per spec AC, reactions on past-session messages while busy steer into current session)
  - If delivery lock is free:
    - If `target_session_id` is set → `enqueue_deferred(envelope)`, then acquire lock + `_process_through_coordinator()` + `_drain_deferred_queue()`. This reuses the same deferred pattern as `/queue` — the message waits for the current turn to complete, then is processed between turns, ensuring the session switch never happens mid-response.
    - If no `target_session_id` → existing path (enqueue + process normally)
- Test: Integration test — reaction on past-session message triggers deferred processing and session switch
