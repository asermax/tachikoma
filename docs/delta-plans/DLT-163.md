### Steps

#### Step 1: Wrap send_message() body in re-queue loop

- Modify: `src/tachikoma/coordinator.py` lines 399–733
- What to do: After the existing guard clause (lines 410-411), wrap the body from line 413 through line 733 in a `while True:` loop. After the per-message post-processing block (after line 733), add: `if self._message_buffer.empty(): break`. This breaks the loop when no leftover messages exist. The guard clause and break are two distinct checks: the guard prevents spurious calls from entering; the break exits after an exchange completes.
- Verify: `just test tests/test_coordinator.py` — existing tests pass (loop runs exactly once when no teardown messages)

#### Step 2: Move pending task await inside the loop

- Modify: `src/tachikoma/coordinator.py`
- What to do: Move the pending task await block (currently lines 428-437, before any loop) to the beginning of the loop body, before the dequeue. On the first iteration `_pending_msg_task` is `None` (no-op). On subsequent iterations it awaits the previous iteration's post-processing task. The final iteration's task is NOT awaited before the generator returns — it runs as a background task, awaited at the start of the next `send_message()` call (Step 2) or in `Coordinator.__aexit__` on shutdown (lines 289-295).
- Verify: `just test tests/test_coordinator.py` passes

#### Step 3: Move status_queue and on_status creation inside the loop

- Modify: `src/tachikoma/coordinator.py`
- What to do: Move the `status_queue` and `on_status` definitions (currently lines 422-425) inside the while loop, before the pending task await. Each iteration gets its own status queue. This is safe because each iteration's background tasks (cold_start_resume, boundary detection, pre-processing) are completed via `_drain_status_while_running` before the iteration reaches the buffer check — the queue is empty when we move to the next iteration.
- Verify: `just test tests/test_coordinator.py` passes

#### Step 4: Move pipeline/session/boundary variables inside the loop

- Modify: `src/tachikoma/coordinator.py`
- What to do: Move `active`, `is_new_session`, `cold_start_resumed` declarations (currently lines 440-442) inside the loop. Each iteration runs its own session lookup and boundary detection. `_sdk_session_id` is an instance attribute preserved across iterations — resume works correctly.
- Verify: `just test tests/test_coordinator.py` passes

#### Step 5: Move response accumulation and SDK setup inside the loop

- Modify: `src/tachikoma/coordinator.py`
- What to do: Move `response_chunks`, `final_text_group`, `had_tool_activity` declarations (currently lines 621-623), the `sdk_inbox`/`message_source`/`transport`/`client` creation (lines 625-628), and `forwarder_task` creation (lines 630-632) inside the loop. Each iteration creates its own SDK exchange with fresh queues and client.
- Verify: `just test tests/test_coordinator.py` passes

#### Step 6: Move per-message post-processing inside the loop

- Modify: `src/tachikoma/coordinator.py`
- What to do: The per-message post-processing block (lines 704-733) stays at the end of each loop iteration (after the try/finally, before the buffer check). The `_last_message_time` update and `_maybe_emit_idle()` call also stay per-iteration. The final iteration's `_pending_msg_task` is not awaited before the generator returns — it runs as a background task and is awaited at the start of the next `send_message()` call (Step 2) or in `Coordinator.__aexit__` on shutdown (lines 289-295).
- Verify: `just test tests/test_coordinator.py` passes

#### Step 7: Verify error handling satisfies design S5

- Modify: `src/tachikoma/coordinator.py`
- What to do: Review that the existing error path (try/except for `CLIConnectionError`/`ProcessError` at lines 673-685) correctly handles re-queue failures. When a re-queue exchange fails: (1) the except clause yields `Error(recoverable=True)`, (2) the finally block runs `drain_back()` recovering any messages from the failed exchange's `sdk_inbox`, (3) the loop continues to check the buffer. No new error handling code is needed — the existing path covers S5.
- Verify: Confirm by code inspection that the error path handles re-queue correctly. `just test tests/test_coordinator.py` passes

## Notes

- The change is primarily structural: wrapping existing code in a loop and moving variable declarations inside it
- `send_message()` now yields a continuous stream spanning potentially multiple exchanges, but channels see the same `AsyncIterator[AgentEvent]` interface
- `_sdk_session_id` is preserved across iterations as an instance attribute — resume works correctly
- `_drain_back()` and `_forwarder()` are unchanged
- `enqueue()` is unchanged
- `has_pending_messages` property is unchanged but primary consumer shifts to coordinator's re-queue loop
- Each iteration's `status_queue` is safe to recreate because `_drain_status_while_running` drains it completely for each background task before the buffer check
