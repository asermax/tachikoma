### Steps

#### Step 1: Create `plugins/config_schema.py` with data types

- Create: `src/tachikoma/plugins/config_schema.py`
- What to do: Define `ConfigFieldSchema` (frozen Pydantic model, `extra="forbid"`), `ConfigDiagnostic` (frozen dataclass), and `ConfigValidationResult` (frozen dataclass with `is_valid` property). `ConfigFieldSchema` has `type: Literal["string", "integer", "boolean", "float"]`, `description: str`, `default: str | int | bool | float | None = None`, `required: bool = False`. Add a `model_validator(mode="after")` that checks: (1) `required=true` and `default is not None` → `ValueError`, (2) `default is not None` and type doesn't match declared type → `ValueError` (use `_TYPE_CHECKERS` map). `ConfigDiagnostic` has `field: str | None` and `message: str`. `ConfigValidationResult` has `values: dict`, `diagnostics: list[ConfigDiagnostic]`, `unknown_keys: list[str]`, and `is_valid` property (True when diagnostics is empty).
- Test: Unit tests for `ConfigFieldSchema` valid construction, unsupported type rejection, required+default conflict, default type mismatch, missing description. Unit tests for `ConfigDiagnostic` and `ConfigValidationResult` construction and `is_valid` property.

#### Step 2: Implement `validate_config()` in `config_schema.py`

- Modify: `src/tachikoma/plugins/config_schema.py`
- What to do: Add `validate_config(schema: dict[str, ConfigFieldSchema], user_values: dict[str, Any]) -> ConfigValidationResult`. The function: (1) checks each schema field — if required and missing from user_values → add diagnostic; if present, type-check against `_TYPE_CHECKERS` (float→integer coercion for zero-fraction values via `isinstance(v, float) and v.is_integer()`), non-zero-fraction float for integer → diagnostic; (2) applies defaults for missing optional fields that have defaults; (3) skips optional fields without defaults and without user values (key absent from result); (4) logs WARNING for unknown user keys and collects them in `unknown_keys` — these are NOT diagnostics (not errors). Always returns a result — never raises. **Important edge case**: empty string (`""`) is a valid present value of type string — it must NOT be treated as "missing" or trigger required-field checks. Only key absence (no user value provided at all) triggers the "missing required field" path.
- Test: Unit tests covering all acceptance criteria in the "Validation (R3)" section — required missing, type mismatch, boolean with int, boolean with string "true" (no coercion), float→integer coercion for 30.0, rejection for 30.5, default application, optional no-default absent, empty string as valid value (distinct from unset), unknown key warning. Also test: empty schema + empty values → valid empty result, empty schema + unknown keys → valid with warnings.

#### Step 3: Write tests for config_schema in isolation

- Create: `tests/plugins/test_config_schema.py`
- What to do: Comprehensive test file following DES-001 class-based organization. Classes: `TestConfigFieldSchema` (valid minimal, valid full, all four types, unsupported type, required+default conflict, default type mismatch, missing description), `TestValidateConfig` (happy path with all types, required field missing, type mismatch, float→integer coercion, string-to-bool rejection, unknown keys with warning, defaults applied, optional without default absent from result, empty string as valid value, empty schema, empty values).
- Test: Run `just test tests/plugins/test_config_schema.py`
