### Steps

#### Step 8: Implement handler validation helper functions

- Modify: `src/tachikoma/plugins/loader.py`
- What to do: Add private helpers:
  - `_import_handler_module(path: Path, module_key: str) -> types.ModuleType` — wraps `importlib.util` dance (spec_from_file_location → module_from_spec → exec_module) with descriptive error on import failure. Registers in `sys.modules` under `module_key`.
  - `_count_positional_params(func: Callable) -> int` — counts `POSITIONAL_OR_KEYWORD` parameters from `inspect.signature`
  - `_validate_bare_module_name(name: str) -> None` — rejects `..`, `/`, `\\`, empty (defense-in-depth; already validated at manifest level)
- Test: Unit tests for each helper: import success with a valid .py file, import failure with syntax error, param counting with various signatures (0, 1, 2, *args, keyword-only), bare name validation.

#### Step 9: Implement hook validation in `_validate_handlers()`

- Modify: `src/tachikoma/plugins/loader.py`
- What to do: Add `_validate_handlers(manifest: PluginManifest, plugin_dir: Path, alias: str) -> tuple[Callable | None, dict[type[BaseEvent], Callable]]` function. First, handle hook validation:
  - For each `(hook_type, module_name)` in `manifest.hooks`:
    - Resolve path `plugin_dir / "hooks" / f"{module_name}.py"`, check exists
    - Import via `_import_handler_module` with unique key `tachikoma_plugin.{alias}.hooks.{module_name}`
    - Verify module has a callable attribute matching `hook_type` name (e.g., `init`)
    - Count positional-or-keyword params via `_count_positional_params` → must be exactly 1
    - Store as `init_hook`
  - On any validation failure, raise `ValueError` with descriptive diagnostic
- Test: Test hook validation success. Test missing file, import error, missing callable, wrong signature.

#### Step 10: Implement event validation in `_validate_handlers()`

- Modify: `src/tachikoma/plugins/loader.py` (same function)
- What to do: Extend `_validate_handlers()` with event validation:
  - For each `(event_name, module_name)` in `manifest.events`:
    - Look up `event_name` in event registry via `get_event_type()` — fail if unknown, diagnostic listing valid names
    - Resolve path `plugin_dir / "events" / f"{module_name}.py"`, check exists
    - Import via `_import_handler_module` with unique key `tachikoma_plugin.{alias}.events.{module_name}`
    - Verify module has a `handle` callable attribute
    - Count positional-or-keyword params → must be exactly 2
    - Store as `event_type → callable` in `event_handlers`
  - Return `(init_hook, event_handlers)`
- Test: Test event validation success. Test unknown event type, missing file, import error, missing `handle`, wrong signature.

#### Step 11: Wire `_validate_handlers()` into `_discover_one()`

- Modify: `src/tachikoma/plugins/loader.py`
- What to do: After config validation in `_discover_one()`, call `_validate_handlers()` for Tachikoma-native manifests (`source_format == "tachikoma"`). On failure, return `LoadedPlugin` with `status="failed"` and diagnostic. On success, pass `init_hook` and `event_handlers` to the `LoadedPlugin` constructor. Skip handler validation for CC manifests (they have no hooks/events support).
- Test: Test that a valid plugin with hooks/events gets `init_hook` and `event_handlers` populated. Test that invalid handlers cause `status="failed"`.

#### Step 12: Test handler validation acceptance criteria

- Create: `tests/plugins/test_handler_validation.py`
- What to do: Write tests covering all AC from the "Manifest Extension" AC block:
  - Valid `[hooks] init = "init"` + `[events] coordinator_idle = "on_idle"` → `LoadedPlugin` has `init_hook` callable and `event_handlers` mapping
  - CC plugin with `"hooks"` contribution → silently ignored (INFO logged)
  - CC plugin with `"events"` contribution → silently ignored (INFO logged)
  - Module name with `..` or path separators → fails with diagnostic
  - Missing handler file → fails with diagnostic naming file

### Steps

#### Step 13: Create `plugins/lifecycle.py` — init hook executor

- Create: `src/tachikoma/plugins/lifecycle.py`
- What to do: Implement `run_plugin_init_hooks(plugins: list[LoadedPlugin], bus: EventBus) -> None`:
  - Sort plugins with `status="loaded"` by alias alphabetically
  - For each plugin with `init_hook`:
    - Create `PluginContext(config=plugin.config, bus=bus, alias=plugin.alias, install_path=plugin.plugin_dir)`
    - Wrap in `try/except` with `asyncio.timeout(30)`
    - On success: call `subscribe_plugin_events(plugin, bus, ctx)`
    - On `TimeoutError`: log WARNING with alias and duration
    - On `Exception`: log ERROR with alias; skip subscriptions
  - For plugins without `init_hook` but with `event_handlers`: subscribe immediately
  - Log summary: initialized N, M failures
  - Implement `_invoke_handler(func, *args)` shared helper: call `func(*args)`, if result is coroutine then `await`
- Test: Test sequential alphabetical execution. Test timeout cancellation. Test error isolation (plugin A fails, B succeeds). Test plugins without init hooks get events subscribed immediately.

#### Step 14: Implement event subscription and unsubscription

- Create: `src/tachikoma/plugins/lifecycle.py` (same file)
- What to do: Implement:
  - `subscribe_plugin_events(plugin: LoadedPlugin, bus: EventBus, ctx: PluginContext) -> None` — for each `(event_type, handler)` in `plugin.event_handlers`, create a wrapper via `_make_event_wrapper(handler, ctx, plugin.alias, event_type)`, call `bus.on(event_type, wrapper)`, append wrapper to `plugin.event_wrappers`
  - `_make_event_wrapper(handler, ctx, alias, event_type) -> Callable` — returns a closure that: checks `_active` flag, calls `_invoke_handler(handler, event, ctx)`, catches exceptions and logs at ERROR level with alias and event type
  - `unsubscribe_plugin_events(wrappers: list) -> None` — sets `_active = False` on each wrapper
  - The wrapper stores `_active = True` and `_event_type` attributes for deactivation and debugging
- Test: Test that subscribed handler receives dispatched events with correct arguments (event payload + PluginContext). Test error isolation (handler A raises, handler B still called). Test deactivation (wrapper becomes no-op after unsubscribe).

#### Step 15: Wire init hooks into `__main__.py`

- Modify: `src/tachikoma/__main__.py`
- What to do: After `await bootstrap.run()` succeeds and before channel construction (before the `settings = settings_manager.settings` line), add:
  ```python
  from tachikoma.plugins.lifecycle import run_plugin_init_hooks

  plugin_manager = bootstrap.extras["plugin_manager"]
  await run_plugin_init_hooks(plugin_manager.list_plugins(), bus)
  ```
  This runs after all subsystems are bootstrapped but before the coordinator processes any message.
- Test: Extend `tests/plugins/test_hooks.py` with an integration test verifying init hooks run after bootstrap completes.

#### Step 16: Test lifecycle acceptance criteria

- Create: `tests/plugins/test_lifecycle.py`
- What to do: Write tests covering "Init Hook Execution", "Event Subscription", "Error Isolation", and "Timeout" AC blocks:
  - Init hook runs with PluginContext before coordinator
  - Multiple init hooks run in alphabetical order
  - Successful init enables event subscriptions
  - Failed init prevents event subscriptions but other plugins proceed
  - PluginContext contains correct fields (config, bus, alias, install_path)
  - Plugin with no hooks but events → subscribed immediately
  - Plugin with hooks but no events → init runs, no subscriptions
  - Event handler receives typed event payload and PluginContext
  - Event handler error isolated per-plugin
  - Multiple event types routed to correct handlers
  - Init hook timeout at 30s → cancelled, logged
  - Failed init plugin not invoked on subsequent events
  - Handler return values ignored
- Test: `just test tests/plugins/test_lifecycle.py`

## Notes

- The handler import uses `importlib.util.spec_from_file_location` with unique module keys (`tachikoma_plugin.{alias}.{hooks|events}.{module_name}`) to avoid `sys.modules` collisions.
- `asyncio.timeout()` (Python 3.11+) only enforces timeouts for async handlers. Sync blocking handlers bypass the timeout — documented as a known limitation.
- bubus `EventBus` has no `off()` API, so unsubscription uses an active-flag wrapper pattern (wrapper checks `_active` flag before dispatching).
- The event registry is built by importing all known event modules and walking `BaseEvent.__subclasses__()` recursively, then deriving snake_case names from CamelCase class names.
