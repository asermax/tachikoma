### Steps

#### Step 6: Implement _validate_providers function

- Create: logic in `src/tachikoma/plugins/loader.py`
- What to do: Add `_validate_providers(manifest, plugin_dir, alias, validated_config) -> tuple[list[ContextProvider], list[MessageContextProvider]]`. For each `(name, module_name)` in `manifest.context_providers`:
  1. Resolve `plugin_dir / "context_providers" / f"{module_name}.py"`, check exists (else `ValueError` naming the missing file)
  2. Import via `_import_handler_module()` with module key `"tachikoma_plugin.{alias}.context_providers.{module_name}"`
  3. Scan module for concrete provider classes: iterate `dir(module)`, skip non-class (`inspect.isclass`), skip abstract (`inspect.isabstract`), check `issubclass(cls, (ContextProvider, MessageContextProvider))`
  4. If no concrete class found: raise `ValueError("No concrete class implementing ContextProvider or MessageContextProvider found in module '{module_name}'")`
  5. For each discovered class: validate `__init__` accepts `"config"` via `inspect.signature` (check `config` in parameters), instantiate with `config=validated_config`, catch `TypeError` specifically from unimplemented abstract methods (re-raise as `ValueError` naming class and missing methods)
  6. Route instance: `ContextProvider` subclass → session_providers, `MessageContextProvider` subclass → message_providers, both → same instance in both lists
  7. If manifest has no context_providers: return `([], [])`
- Test: Unit test `_validate_providers` directly with a temp plugin directory containing provider modules

#### Step 7: Integrate provider validation into _discover_one

- Modify: `src/tachikoma/plugins/loader.py`
- What to do: In `_discover_one()`, after config validation and handler validation, add provider validation block: if `validated_manifest.context_providers`, call `_validate_providers(validated_manifest, plugin_dir, alias, validated_config)`. On `ValueError`, return `LoadedPlugin(status="failed", diagnostic=f"Provider validation error: {exc}")`. Pass resulting provider lists to the `LoadedPlugin` constructor.
- Test: Discover a plugin with a valid context provider; discover a plugin with invalid provider (missing file, bad ABC, wrong signature) — verify failure with diagnostic

#### Step 8: Integrate provider validation into _update_locked

- Modify: `src/tachikoma/plugins/manager.py`
- What to do: In `_update_locked()`, after handler validation (line ~239) and before atomic swap, add provider validation. The update flow doesn't re-validate user config — use the source config from the existing plugin to construct validated_config. If provider validation fails, `_cleanup(staging)` and return `UpdateResult(status="failed")`. Include provider lists in the `LoadedPlugin` constructor.
- Test: Update a plugin that adds/removes context providers; update with invalid new provider

#### Step 9: Integrate provider validation into _install_locked

- Modify: `src/tachikoma/plugins/manager.py`
- What to do: In `_install_locked()`, after handler validation (line ~499), add provider validation: call `_validate_providers(manifest, target, resolved_alias, {})`. Config not yet available at install materialization stage — empty dict passed. Include provider lists in the `LoadedPlugin` constructor. Like handler validation, provider validation failure during install is logged as warning (not fatal) per existing pattern.
- Test: Install a plugin with valid context providers; install with invalid provider

## Notes

- Manager's `_update_locked()` doesn't re-validate user config during updates (config comes from the existing source). Provider validation during update uses the source config from the existing plugin. This is consistent with how `_discover_one()` has the config available from validation.
- The `__main__.py` wiring point is after pipeline creation but before Coordinator construction, ensuring providers are registered before any message processing begins.
- Provider listener needs `plugin_manager` reference (not just event data) because `PluginRemoving` event only carries `alias` and `namespaced_skill_names`, not provider instances.
