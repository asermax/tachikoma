#### Step 7: Add episodic maintenance tick function and prompt

- Modify: `src/tachikoma/memory/maintenance.py`
- Add `EPISODIC_MAINTENANCE_PROMPT` — Detailed prompt instructing the agent to:
  - Read all files in `$WORKSPACE/memories/episodic/`
  - If no files exist, exit immediately with no changes (R9 empty store)
  - Skip malformed or empty files (R9 error handling)
  - Categorize by age into tiers using injected threshold values:
    - Recent daily (last N days): clean verbosity (remove repeated info, excessive implementation detail) without deleting files or substantive content (R8)
    - Weekly consolidation (N days to M months): consolidate daily files into weekly summaries (`YYYY-WNN.md`), merge into existing summaries when they already exist
    - Monthly consolidation (M months to 12 months): consolidate into monthly summaries (`YYYY-MM.md`), merge into existing
    - Deletion (older than 12 months): delete files
  - Handle partial groups at boundaries (single summary for partial week/month)
  - Be idempotent — check for work that needs doing before acting (R7)
  - Do not modify files being actively written — no locking needed (R9)
- Add `episodic_maintenance_tick(agent_defaults: AgentDefaults, maintenance_settings: MaintenanceSettings) -> None`:
  1. Build scoped allow rules for episodic directory
  2. Build prompt with threshold values from `maintenance_settings`
  3. Replace `$WORKSPACE` placeholder in prompt with `str(agent_defaults.cwd)` (DES-008)
  4. Call `query_and_consume(prompt, agent_defaults, tools=MAINTENANCE_TOOLS, allow=rules, pre_tool_use_hooks=[MAINTENANCE_BASH_HOOK], model=agent_defaults.processor_model)`
  5. Call `git_commit_memory_changes(agent_defaults, "episodic")`
- Verify: `just typecheck` passes.

#### Step 8: Add facts maintenance tick function and prompt

- Modify: `src/tachikoma/memory/maintenance.py`
- Add `FACTS_MAINTENANCE_PROMPT` — Prompt instructing the agent to:
  - Read all files in `$WORKSPACE/memories/facts/`
  - If no files exist, exit immediately (R9)
  - Skip malformed/empty files (R9)
  - Evaluate each file for: staleness (outdated dates, completed projects, contradicted info), redundancy (same info in different files), overlap (related topics split across files)
  - Stale entries: remove or update
  - Redundant entries: keep most complete version, remove duplicates
  - Overlapping files: merge into single consolidated file, remove originals
  - Entirely obsolete files: delete
  - Be idempotent (R7)
- Add `facts_maintenance_tick(agent_defaults: AgentDefaults) -> None` — Same structure as episodic but no threshold params. Call `git_commit_memory_changes(agent_defaults, "facts")`.
- Verify: `just typecheck` passes.

#### Step 9: Add preferences maintenance tick function and prompt

- Modify: `src/tachikoma/memory/maintenance.py`
- Add `PREFERENCES_MAINTENANCE_PROMPT` — Prompt instructing the agent to:
  - Read all files in `$WORKSPACE/memories/preferences/`
  - If no files exist, exit immediately (R9)
  - Skip malformed/empty files (R9)
  - Evaluate for: redundancy (same preference stated multiple times across/within files), overlap (related preferences split across files)
  - Redundant entries: deduplicate, keep most complete version
  - Overlapping files: merge into single consolidated file, remove originals
  - Entirely superseded/obsolete files: delete
  - Be idempotent (R7)
- Add `preferences_maintenance_tick(agent_defaults: AgentDefaults) -> None` — Same structure as facts. Call `git_commit_memory_changes(agent_defaults, "preferences")`.

## Notes

- The `query_and_consume` promotion is a pure refactor — no behavioral changes. Both import sites continue working identically.
- The maintenance prompts are the core intellectual work. They must encode strategies from the spec (R2-R5, R7-R9) clearly enough that the agent makes good editorial decisions. Following DLT-148's guidance, prompts should include concrete positive and negative examples.
- Error handling for empty stores and malformed files is handled at the prompt level (instructing the agent to skip/no-op). This is consistent with the design's agent-driven approach — the agent exercises judgment. Code-level guards aren't needed because: (a) `query_and_consume` handles SDK errors, (b) the scheduler provides error isolation per job, (c) git provides rollback for partial/mistaken changes.
- The `rm` prefix in `MAINTENANCE_BASH_PREFIXES` is not path-scoped by the bash gate — it only checks command prefixes, not arguments. This is a conscious trade-off documented in the design: mitigated by prompt restrictions (agent is told to only delete in the target directory) and git rollback.
- No external libraries needed — purely internal wiring using existing SDK and scheduler infrastructure.
