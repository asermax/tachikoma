#### Step 3: Add MaterializationResult return type to materializers

- Modify: `src/tachikoma/plugins/materializer.py`
- What to do:
  - Define `MaterializationResult` dataclass at module top: `staging_dir: Path`, `version: str | None`
  - Update `materialize_local` to create `os.symlink(source.path, staging)` instead of `shutil.copytree`. Return `MaterializationResult(staging_dir=staging, version=None)`.
  - Update `materialize_git` to run `git rev-parse HEAD` after clone (via `run_git_capture`) to capture commit SHA. Return `MaterializationResult(staging_dir=staging, version=sha)`.
  - Update `materialize_url` to compute SHA-256 of archive via `hashlib.file_digest(archive_path.open("rb"), "sha256").hexdigest()` after download. Return `MaterializationResult(staging_dir=staging, version=content_hash)`.
- Test: unit tests verifying version hash is captured correctly for each source type; test symlink creation for local source

#### Step 4: Refactor reconciler for first-time-only install + symlink migration

- Modify: `src/tachikoma/plugins/reconciler.py`
- What to do:
  - Change `reconcile()` signature to accept `state_repo: PluginStateRepository` parameter
  - In `_reconcile_one`: before materialization, check if `install_dir / alias` exists and is a valid plugin directory (has manifest) → if yes, handle symlink migration for local sources, then skip

  - For skipped (already-installed) plugins: ensure PluginState row exists (create if missing, for existing installations predating this delta)
  - Keep orphan cleanup unchanged

Return list of aliases with available updates. Log warnings for errors, retain previous status.

#### Step 8: Add update methods and lock map to PluginManager

- Modify: `src/tachikoma/plugins/manager.py`
- What to do:
  - Add `state_repo: PluginStateRepository` parameter to `PluginManager.__init__`; store as `self._state_repo`
  - Add `_update_locks: dict[str, asyncio.Lock]` to `__init__`
  - Add `_get_update_lock(alias) -> asyncio.Lock`: return existing or create new lock for alias
  - Add `_cleanup_update_lock(alias)`: remove lock from map (called on plugin removal)
  - Define `UpdateResult` and `UpdateSummary` dataclasses in `updater.py` (from Batch 3):
    - `UpdateResult(alias, status: Literal["updated", "failed", "skipped"], error, message)`
    - `UpdateSummary(total, updated, skipped, failed, results: list[UpdateResult])`
  - Define `async def update(alias: str) -> UpdateResult`:
    1. Validate alias exists in `_loaded`; if not, raise `PluginNotFoundError`
    2. If source is `LocalPluginSource`, return skipped result with message "Local plugins are always current"
    3. Acquire per-plugin lock via `_get_update_lock(alias)` with non-blocking `lock.locked()` check — if held, return error "Update already in progress"
    4. Re-materialize via materializer (returns `MaterializationResult` with version hash)
    5. Parse manifest, validate handlers (reuse `_validate_handlers` from `loader.py`)
    6. On validation failure: clean up staging, return error
    7. Atomic swap via `_atomic_replace_dir`
    8. Update `PluginState` via `state_repo.upsert()` with new installed_version, `update_status="up-to-date"`, clear available_version
    9. Re-register plugin (see Step 10)
    10. Release lock
    11. Return result
  - Define `async def update_all() -> UpdateSummary`:
    1. Collect all plugins; filter to those with `update_status="update-available"` or non-local plugins that the user explicitly wants checked
    2. Iterate sequentially: call `update(alias)` for each
    3. Continue on failure (don't abort remaining)
    4. Return aggregated `UpdateSummary`
  - Update `remove_locked` to call `_cleanup_update_lock(alias)` after removal
- Test: unit tests for update flow with mock materializer and state_repo; test lock contention returns error; test local plugin returns skipped; test update_all with mixed results

#### Step 9: Add MCP tools for update_plugin and update_all_plugins

- Modify: `src/tachikoma/plugins/tools.py`
- What to do:
  - Define `UpdatePluginArgs(BaseModel)`: `alias: str`
  - Define `handle_update_plugin(args, manager) -> dict`: delegate to `manager.update(args.alias)`, format result as JSON
  - Define `handle_update_all_plugins(manager) -> dict`: delegate to `manager.update_all()`, format summary as JSON
  - Add `update_plugin` and `update_all_plugins` tools to `create_plugin_tools_server`:
    ```python
    @tool("update_plugin", "Update a single plugin...", UpdatePluginArgs.model_json_schema())
    async def update_plugin(args: dict) -> dict:
        parsed = UpdatePluginArgs.model_validate(args)
        return await handle_update_plugin(parsed, manager)

    @tool("update_all_plugins", "Update all plugins with available updates...", {})
    async def update_all_plugins(args: dict) -> dict:
        return await handle_update_all_plugins(manager)
    ```
  - Append both to the `tools=[...]` list in `create_sdk_mcp_server`
- Test: unit tests for `handle_update_plugin` and `handle_update_all_plugins` handlers with mock manager

#### Step 10: Implement re-registration flow

- Modify: `src/tachikoma/plugins/manager.py`
- What to do:
  - Extract re-registration into `_reregister_plugin(old_plugin, new_plugin_dir) -> LoadedPlugin`:
    1. Dispatch `PluginRemoving` event (listeners mark active session entries)
    2. Call `unsubscribe_plugin_events(old_plugin.event_wrappers)` from `lifecycle.py`
    3. Dispatch `PluginRemoved` event (listeners remove namespaced skills from SkillRegistry via `remove_namespaced_source`)
    4. Re-discover: parse manifest at new_plugin_dir, validate handlers via `_validate_handlers`, create new `LoadedPlugin`
    5. Store new plugin in `_loaded[alias]`
    6. Dispatch `PluginInstalled` event (listeners register namespaced skills via `add_namespaced_source`)
    7. Run `init_plugin(new_plugin, self._bus)` from `lifecycle.py` (subscribe events)
    8. Return new `LoadedPlugin`
  - On re-registration failure (step 4-7 exceptions):
    1. Keep new materialized version on disk (atomic swap already completed)
    2. Retain old skills and event subscriptions (old `LoadedPlugin` stays in `_loaded`)
    3. Update `PluginState` with diagnostic describing the failure
    4. Log the error
    5. Return error result
  - Integrate `_reregister_plugin` into the `update()` method (Step 8, step 9)
- Test: unit tests for successful re-registration (old skills removed, new skills added); test failure path (old skills retained, diagnostic stored); test event handler re-subscription

## Notes

- The daily check uses `CronTrigger` on the central scheduler (DES-010), NOT a `TaskDefinition`. This is a system-internal housekeeping operation — no task-instance bookkeeping needed.
- Annotated tag dereferencing (`refs/tags/<tag>^{}`) is critical for correct SHA comparison. Without it, annotated tags return the tag object SHA, not the commit SHA.
- The per-plugin lock map is lazily populated and cleaned up on plugin removal, avoiding pre-allocating locks for plugins that never get updated.
- `hashlib.file_digest()` is a Python 3.11+ addition that handles streaming internally. The project targets 3.11+ so this is safe.
- Existing databases will get the `plugin_state` table created via the inline migration in `_run_migrations()`. Pre-existing plugins will get `PluginState` rows created during their first reconciliation (status "unknown").
