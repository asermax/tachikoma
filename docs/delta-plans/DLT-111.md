#### Step 1: Change `_message_source` signature and add cancellation recovery (S1, S4)

- Create/modify: `src/tachikoma/coordinator.py`
- What to do: Change the module-level function to read from a per-turn inbox and re-enqueue a locally held item on cancellation.

```python
# src/tachikoma/coordinator.py — replace existing _message_source (around L73)

async def _message_source(
    initial: str,
    inbox: asyncio.Queue[str],
) -> AsyncIterator[dict[str, Any]]:
    """Long-lived generator feeding messages from per-turn inbox to SDK.

    Yields the enriched initial message first, then reads subsequent
    messages from the per-turn `inbox` queue (populated by _forwarder).
    """
    # Yield the initial message (no pending local yet)
    yield _user_message(initial)

    # Subsequent iterations: pull from inbox; on cancellation mid-step,
    # re-enqueue any locally held item into the same inbox so drain-back
    # (S3) can recover it. See KD-4 "Happens-before chain".
    pending: str | None = None
    try:
        while True:
            pending = await inbox.get()
            text_to_yield = pending
            pending = None  # cleared once we commit to yielding
            yield _user_message(text_to_yield)
    finally:
        if pending is not None:
            inbox.put_nowait(pending)
```

#### Step 2: Add the `_forwarder` method with S4b recovery (S2, S4b)

- Create/modify: `src/tachikoma/coordinator.py`
- What to do: Add a private async method on `Coordinator` that forwards items from `_message_buffer` to a per-turn inbox. Wrap its loop in `try/finally` that re-enqueues a locally held item to `_message_buffer` on `CancelledError` (KD-4b). Per the S2 atomicity argument in §Open Questions, recovery is belt-and-suspenders.

```python
# src/tachikoma/coordinator.py — new method on Coordinator

async def _forwarder(self, inbox: asyncio.Queue[str]) -> None:
    """Forward items from _message_buffer to the per-turn SDK inbox.

    Single suspension point on _message_buffer.get() — put_nowait is
    synchronous, so a CancelledError cannot land between get() returning
    and put_nowait() executing (§Open Questions). The try/finally makes
    the recovery explicit for readability and robustness to future edits.
    """
    pending: str | None = None
    try:
        while True:
            pending = await self._message_buffer.get()
            inbox.put_nowait(pending)
            pending = None
    finally:
        if pending is not None:
            self._message_buffer.put_nowait(pending)
```

- Test: method is exercised indirectly by Step 5 tests; no isolated unit test needed.

#### Step 3: Add `_drain_back` synchronous helper (S3)

- Create/modify: `src/tachikoma/coordinator.py`
- What to do: Add a sync method that drains both `inbox` and `_message_buffer` via `get_nowait` and re-enqueues them (inbox items first) into `_message_buffer` via `put_nowait`. No `await` anywhere in the body — this is the atomicity argument from KD-3.

```python
# src/tachikoma/coordinator.py — new method on Coordinator

def _drain_back(self, inbox: asyncio.Queue[str]) -> None:
    """Recover items from per-turn inbox and re-populate _message_buffer in order.

    Synchronous; runs in a single atomic block so concurrent enqueue()
    cannot interleave. Must be called AFTER the forwarder has awaited
    to completion and AFTER client.disconnect() has returned (KD-2, KD-3).
    """
    recovered: list[str] = []
    while not inbox.empty():
        recovered.append(inbox.get_nowait())

    pending: list[str] = []
    while not self._message_buffer.empty():
        pending.append(self._message_buffer.get_nowait())

    for text in recovered + pending:
        self._message_buffer.put_nowait(text)
```

- Test: covered by the teardown race test (Step 5).

#### Step 4: Restructure `send_message()` to own `_sdk_inbox` + `_forwarder` lifecycle (S1, S2, KD-2, KD-3)

- Create/modify: `src/tachikoma/coordinator.py`
- What to do: At the point where `message_source` is constructed (around L532), create the per-turn inbox and start the forwarder. In the `finally` at L589, execute the exact teardown sequence from §Components/Coordinator. **Do not touch** the post-`finally` block at L594–622 (per-message post-processing + `_last_message_time` + `_maybe_emit_idle`) — those stay exactly as they are today.

```python
# src/tachikoma/coordinator.py — inside send_message(), replacing the
# block around L532-L591.

# After transport/client construction, before client.connect():
sdk_inbox: asyncio.Queue[str] = asyncio.Queue()
# Note: client.connect() consumes `message_source` as its prompt source
# (DES-005). The generator's lifetime is therefore tied to the SDK's
# internal task group and cancellation comes from client.disconnect().
message_source = _message_source(text, sdk_inbox)
transport = FilePromptTransport(prompt=message_source, options=options)
client = ClaudeSDKClient(options, transport=transport)

forwarder_task: asyncio.Task[None] = asyncio.create_task(
    self._forwarder(sdk_inbox),
)

try:
    await client.connect(message_source)
    self._client = client

    async for sdk_message in client.receive_response():
        # ... existing event handling unchanged ...

except (CLIConnectionError, ProcessError) as exc:
    # ... existing error handling unchanged ...

finally:
    # KD-2: cancel forwarder BEFORE client.disconnect so _message_buffer
    # has no consumer during SDK teardown.
    forwarder_task.cancel()
    with contextlib.suppress(asyncio.CancelledError):
        try:
            await forwarder_task
        except Exception:
            _log.exception("Forwarder failed")

    await client.disconnect()

    # KD-3: drain-back + _client=None form a single synchronous block so
    # has_pending_messages is accurate at the exact moment _client flips.
    self._drain_back(sdk_inbox)
    self._client = None
```

- Note on idiom: `contextlib.suppress(asyncio.CancelledError)` matches design §Components. The inner `try/except Exception` logs non-cancellation forwarder failures (§System Behavior "Error paths") without re-raising.
