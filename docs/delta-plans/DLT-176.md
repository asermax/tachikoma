#### Step 10: Create workflow step tools MCP server factory

  - Define extracted handler functions (testable without SDK):
    - `handle_complete_step(workflow_id, handoff, repository, task_repository, skill_registry, workspace_path)` — validates handoff (max 4000 chars, empty string = no handoff), reads workflow state, runs cascade via `run_cascade()`, applies mutations, creates next step TaskInstance if cascade produces one, stores handoff on workflow state, returns result dict

#### Step 18: Create WorkflowFailureProcessor

- Create: `src/tachikoma/workflows/failure_processor.py`
- What to do:
  - Define `WorkflowFailureProcessor` implementing `PostProcessor` (not extending `PromptDrivenProcessor` — this is a direct DB/notification operation, no SDK forking needed)
  - Constructor receives: `TaskInstance`, `WorkflowStateRepository`, `EventBus`
  - `process()` method:
    1. Self-select: only acts when `instance.workflow_id is not None` AND `instance.status == "failed"`
    2. Call `repository.abort_cascade(instance.workflow_id)` to atomically soft-delete workflow state and descendants
    3. Call `delete_scratchpad()` with the scratchpad path from the workflow state
    4. Dispatch failure notification via `dispatch_notification()` describing which step failed and why
  - **"Completed without calling workflow tool" path**: When a step agent reaches max iterations without calling `complete_step`/`skip_step`/`abort_workflow`, the executor marks the instance as failed (existing behavior). The `WorkflowFailureProcessor` then picks it up in post-processing and triggers the abort cascade. No special handling needed — the existing max_iterations failure path in the executor + the failure processor in post-processing covers this automatically
  - Errors within the processor are logged and swallowed — matching post-processing error isolation semantics (failure to clean up workflow state should not prevent executor from completing its error handling)
- Test: Unit test with mock repository verifying abort cascade called on failed workflow instance; test that non-workflow instances and non-failed instances are no-ops

#### Step 19: Integrate failure processor into executor

- Modify: `src/tachikoma/tasks/executor.py`
