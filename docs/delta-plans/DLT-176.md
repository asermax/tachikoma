#### Step 3: Implement `ReactionMessage.sdk_input` rendering

- Modify: `src/tachikoma/message.py`
- What to do: Implement the property body covering all six canonical diff shapes from the design's "Rendered prose canonical forms" table. Use `sorted()` on each frozenset for deterministic iteration. Use the join policy `", "` between non-last items and `" and "` before the last (no Oxford comma) for N≥2 emojis. No guard is needed for empty/empty — that input never reaches this property in production (producer-enforced).

The six branches to render (with `A`, `B`, `C` as sorted-emoji placeholders):

| Shape | Condition | Output |
|-------|-----------|--------|
| Added (N=1) | `len(added)==1, removed==∅` | `The user reacted with A. Interpret it in the context of the last exchange and respond accordingly.` |
| Added (N≥2) | `len(added)>=2, removed==∅` | `The user reacted with A and B. Interpret these in the context of the last exchange and respond accordingly.` |
| Removed (N=1) | `added==∅, len(removed)==1` | `The user removed their A reaction. Interpret it in the context of the last exchange and respond accordingly.` |
| Removed (N≥2) | `added==∅, len(removed)>=2` | `The user removed their A and B reactions. Interpret these in the context of the last exchange and respond accordingly.` |
| Replacement (1↔1) | `len(added)==1, len(removed)==1` | `The user changed their reaction from A to B. Interpret it in the context of the last exchange and respond accordingly.` |
| Mixed (any other) | else | `The user reacted with A and B and removed their C reaction. Interpret these in the context of the last exchange and respond accordingly.` |

For the mixed shape, the `removed` segment uses singular "reaction" for N=1 and plural "reactions" for N≥2.

- Test: in `TestReactionMessage`, parameterize across all six shapes. Use distinct frozenset inputs and assert exact prose output. Include a 3-emoji case (e.g. `{🤔, 👍, ❤}`) to verify the join policy (output contains `❤, 👍 and 🤔` after sort). **R10 explicit assertion**: across all rendered outputs, assert the prose contains none of: `"your message"`, `"the agent"`, `"my message"`, `"message #"`, or any digit substring — confirming the prose never references a specific message target. **R4 explicit assertion**: assert the prose never contains semantic-mapping wording like `"approval"`, `"agree"`, `"disagree"`, `"confused"` — the agent does the interpretation. `just test tests/test_message.py -k ReactionMessage` passes.

```python
# src/tachikoma/telegram/__init__.py — inside class TelegramChannel

async def _handle_reaction(self, event) -> None:
    """Handle an incoming message_reaction update from the authorized chat."""
    # Step a: extract emoji-typed entries from old/new reactions
    old_emojis = _emoji_set(event.old_reaction)
    new_emojis = _emoji_set(event.new_reaction)

    # Step b: compute the diff (set arithmetic)
    added = new_emojis - old_emojis
    removed = old_emojis - new_emojis

    # Step c: drop no-op updates (R9 first AC) and uninterpretable-only updates
    # (R9 second AC). Same early-return covers both: in either case the
    # post-filter diff is empty.
    if not added and not removed:
        _log.debug("Reaction update with no interpretable change; dropping")
        return

    # Step d: construct envelope. No message-ID, no chat-ID; only the diff (KD-7).
    env = ReactionMessage(added=frozenset(added), removed=frozenset(removed))

    # Step e: DES-009 busy/idle branching — mirrors _handle_callback_query.
    # Reactions never use enqueue_deferred (no force-new analog).
    if self._delivery_lock.locked():
        _log.debug("Mid-stream reaction steering")
        self._coordinator.enqueue(env)
        return

    async with self._delivery_lock:
        self._coordinator.enqueue(env)
        await self._process_through_coordinator()
        await self._drain_deferred_queue()
```

## Notes

- The `_emoji_set` helper, `_handle_reaction` method, and conditional handler registration are tightly coupled (handler calls helper; registration installs handler). The `ReactionMessage` import is added in Step 11 alongside the helper so the file stays import-clean before the handler in Step 12 references the type.
- The "in-handler filtering" (KD-4) and "no-op drop" (R9) decisions both live in the same early-return guard of `_handle_reaction`. The guard fires whenever the post-filter diff is empty — that's how a single check covers both "Telegram resent the same set" and "the only changes were custom/paid emoji we don't interpret."
- Default rendering iteration order uses `sorted()` on the frozenset. Deterministic; harmless to the agent; the test suite asserts exact strings.
- Batch 2 and Batch 3 both depend on Batch 1 but not on each other; in principle they could be implemented in parallel. The plan presents them sequentially because that's how a single implementing agent will pick them up.
- Reconciliation impacts (post-implementation): the design's "Detected Impacts" section names seven feature documents to update. Reconciliation is a separate step (`/katachi:reconcile-delta`), not part of this plan.
