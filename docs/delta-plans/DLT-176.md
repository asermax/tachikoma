### Steps

#### Step 1: Create `src/tachikoma/memory/index.py` with prompt constants and rebuild helper

- Create: `src/tachikoma/memory/index.py`
- What to do:
  - Define `DESCRIPTION_WORKER_PROMPT` — system prompt for lightweight haiku sub-agents. Each worker receives a batch of file paths, reads them with the Read tool, and returns one-line descriptions as structured XML: `<file path="./filename.md">description</file>`. Prompt specifies: read each file, generate a concise one-line description (under 80 chars), return all descriptions in XML format. Workers are custom agents (not Explore) — focused task with Read tool only.
  - Define `HEAVY_INDEX_REBUILD_PROMPT` — orchestrator prompt for the full rebuild. Instructions: (1) Glob all `.md` files in `$WORKSPACE/memories/<type>/` (excluding `MEMORY.md`), (2) group files into batches of 5–8 (final batch may be smaller), (3) for each batch, spawn a description worker via the Agent tool with `DESCRIPTION_WORKER_PROMPT` as system prompt and haiku model, (4) collect all descriptions from worker XML output, (5) analyze descriptions for structural improvements — merge files with similar descriptions, rename files violating naming patterns, (6) perform identified merges/renames, (7) write `MEMORY.md` from scratch with entries in format `[Name](./filename.md): Description`, (8) header is `# Memory Index`. Prompt uses `$WORKSPACE` placeholder. Includes permissions section explaining tool access.
  - Define `async def run_index_rebuild(agent_defaults: AgentDefaults, memory_type: str) -> None` — calls `query_and_consume` with `HEAVY_INDEX_REBUILD_PROMPT` (with `$WORKSPACE` replaced), tools including `["Read", "Glob", "Grep", "Bash", "Edit", "Write", "Agent"]`, scoped allow rules for `memories/<memory_type>/` (following `extraction_allow_rules` pattern with `include_agent=True`), `UTILITY_BASH_HOOK` for bash gating, and `processor_model`. Replaces `$WORKSPACE` with `str(agent_defaults.cwd)` and `<type>` with `memory_type` in the prompt before calling.
  - Follow DES-004 patterns for tool scoping and permission configuration.
- Test: `tests/test_memory_index.py` — verify `DESCRIPTION_WORKER_PROMPT` contains XML output format instructions and file reading guidance; verify `HEAVY_INDEX_REBUILD_PROMPT` contains batch grouping, Agent tool spawning, structural analysis, and MEMORY.md format instructions; verify `run_index_rebuild` calls `query_and_consume` with correct tools (including Agent), scoped allow rules (Edit/Write scoped to target directory), `UTILITY_BASH_HOOK`, and `processor_model` (all mocked).

#### Step 2: Add `INDEX_UPDATE_SECTION` to `src/tachikoma/memory/prompts.py`

- Modify: `src/tachikoma/memory/prompts.py`
- What to do:
  - Define `INDEX_UPDATE_SECTION` as a module-level string constant. Content:
    - Header: `## Memory Index`
    - Instructions: When you create, modify, or delete a memory file, you MUST also update `MEMORY.md` in the same directory to keep the index in sync.
    - Entry format: `[Human-readable Name](./filename.md): One-line description of contents`
    - Rules: CREATE → add entry with description; MODIFY → update description if content changed; DELETE → remove entry; always preserve `# Memory Index` header; descriptions under 80 characters.
    - Example entries showing correct format.
  - Export in `__all__` alongside existing sections.
- Test: Verify `INDEX_UPDATE_SECTION` contains the entry format (`[Name](./file.md): Description`), all three update rules (create, modify, delete), the 80-char description limit, and at least one example entry.

#### Step 5: Modify `MEMORY_SEARCH_PROMPT` for index-based discovery with fallback

- Modify: `src/tachikoma/memory/context_provider.py`
- What to do:
  - Locate the "Search Strategy" section within `MEMORY_SEARCH_PROMPT`.
  - For facts and preferences directories, replace the Glob-based discovery instructions with:
    1. **First**, Read `MEMORY.md` in the target directory.
    2. Evaluate each entry's description against the user message to determine relevance.
    3. Select files whose descriptions suggest relevance, then Read only those selected files.
    4. If no descriptions are relevant, return `NO_RELEVANT_MEMORIES` without reading individual files.
    5. **Fallback**: If `MEMORY.md` does not exist, is empty, or contains no parseable entries, fall back to Glob → Grep → Read (the current pattern).
  - For episodic directory: keep the existing Glob → Grep → Read strategy unchanged. Episodic memories are date-organized and do not have a `MEMORY.md` index.
  - Keep the existing classification section (Skip/Shallow/Full) and output format (XML `<memory>` elements) unchanged.
  - Ensure the fallback instructions are explicit and prominent so the agent handles missing/stale indexes gracefully.
- Test: Verify `MEMORY_SEARCH_PROMPT` contains index-based discovery instructions for facts/preferences. Verify Glob fallback instructions are present. Verify episodic search instructions are unchanged (still uses Glob). Verify classification section and output format are unchanged.

#### Step 6: Add `INDEX_LIGHT_MAINTENANCE_SECTION` to `src/tachikoma/memory/prompts.py`

- Modify: `src/tachikoma/memory/prompts.py`
- What to do:
  - Define `INDEX_LIGHT_MAINTENANCE_SECTION` as a module-level string constant. Content:
    - Header: `## Memory Index Consistency`
    - Instructions: Verify index consistency between `MEMORY.md` and actual files in the directory.
    - Steps: (1) Glob all `.md` files in the directory (excluding `MEMORY.md`), (2) Read `MEMORY.md` entries, (3) For files without an index entry: add a placeholder entry with format `[Topic](./filename.md): Description pending update`, (4) For index entries referencing files that no longer exist: remove those entries, (5) Do NOT regenerate or modify existing descriptions — leave them unchanged even if stale.
    - Preserve the `# Memory Index` header.
  - Export in `__all__`.
- Test: Verify `INDEX_LIGHT_MAINTENANCE_SECTION` contains consistency verification instructions (Glob files, cross-reference with MEMORY.md), the placeholder entry format (`Description pending update`), the "do not regenerate existing descriptions" constraint, and instructions to remove stale entries.

#### Step 7: Add day-of-week dispatch to facts and preferences tick functions

- Modify: `src/tachikoma/memory/maintenance.py`
- What to do:
  - Import `datetime` and the new constants: `INDEX_LIGHT_MAINTENANCE_SECTION` from `tachikoma.memory.prompts`, `HEAVY_INDEX_REBUILD_PROMPT` and `run_index_rebuild` from `tachikoma.memory.index`.
  - In `facts_maintenance_tick`:
    - After building the base prompt (and appending skill catalog + cross-store sections), check `datetime.now().weekday()`:
      - **Mon–Sat** (`weekday() != 6`): Append `INDEX_LIGHT_MAINTENANCE_SECTION` to the prompt. Proceed with normal `_run_maintenance_tick` call using `MAINTENANCE_TOOLS`.
      - **Sunday** (`weekday() == 6`): Append `HEAVY_INDEX_REBUILD_PROMPT` to the prompt (with `$WORKSPACE` and `<type>` replaced). Extend tools to include `"Agent"` alongside `MAINTENANCE_TOOLS`. Update allow rules to include `Agent` permissions (following `extraction_allow_rules` pattern with `include_agent=True`). Call `_run_maintenance_tick` (or `query_and_consume` directly if the shared helper's tool config is too rigid) with the extended tools.
    - **R2 coverage**: Both the light maintenance section and the heavy rebuild prompt must instruct the maintenance agent to update `MEMORY.md` when it performs file operations (consolidation, merge, rename, deletion). The light section already covers removing stale entries and adding placeholders; the heavy rebuild prompt writes `MEMORY.md` from scratch. Verify both prompt sections include explicit instructions for keeping the index in sync with file changes during maintenance.
  - In `preferences_maintenance_tick`:
    - Same pattern as facts: day-of-week check, light section Mon–Sat, heavy rebuild prompt + Agent tool on Sunday. Same R2 coverage — verify the prompt sections include index update instructions.
  - For the shared `_run_maintenance_tick` helper: extend its signature to accept optional `extra_tools: list[str] | None = None` and `extra_sections: str | None = None` parameters (or the implementer may choose a different pattern if it fits the existing codebase better). When provided, `extra_tools` are appended to `MAINTENANCE_TOOLS` and `extra_sections` is appended to the prompt before the `$WORKSPACE` replacement. This avoids duplicating the full tick infrastructure in each function.
  - Episodic and context tick functions remain unchanged — they don't have MEMORY.md indexes.
- Test: Extend `tests/test_memory_maintenance.py`:
  - Test that `facts_maintenance_tick` appends `INDEX_LIGHT_MAINTENANCE_SECTION` to prompt on weekdays (mock `datetime.now().weekday()` to return 0–5).
  - Test that `facts_maintenance_tick` appends `HEAVY_INDEX_REBUILD_PROMPT` to prompt on Sunday (mock `weekday()` to return 6).
  - Test that Sunday tick passes `Agent` in tools alongside `MAINTENANCE_TOOLS`.
  - Test same for `preferences_maintenance_tick`.
  - Test that weekday tick uses standard `MAINTENANCE_TOOLS` (no Agent).
  - Test that episodic and context ticks are unchanged (no day-of-week logic).
  - Test that both light and heavy index prompt sections include instructions for updating `MEMORY.md` when performing file operations (R2 coverage).

#### Step 8: Extend bootstrap hook for index creation

- Modify: `src/tachikoma/memory/hooks.py`
- What to do:
  - Import `run_index_rebuild` from `tachikoma.memory.index`.
  - In `memory_hook`, after the existing directory creation block:
    - For each of `memories/facts/` and `memories/preferences/`:
      - Check if `MEMORY.md` exists in the directory.
      - **If exists**: skip (idempotent — no rebuild).
      - **If missing**:
        - Check if the directory contains any `.md` files (excluding `MEMORY.md` itself).
        - **If empty**: create `MEMORY.md` with header only (`# Memory Index\n`).
        - **If has files**: call `await run_index_rebuild(ctx.agent_defaults, memory_type)` where `memory_type` is `"facts"` or `"preferences"`.
  - Access `agent_defaults` from the `BootstrapContext` (`ctx` parameter). If `agent_defaults` is not available on the context, it needs to be added to `BootstrapContext` or passed through another mechanism — verify availability and adapt accordingly.
  - Follow the idempotency pattern from DES-003 (self-determine if action is needed).
- Test: Add tests for bootstrap hook index behavior:
  - Test that empty directories get `MEMORY.md` with header only.
  - Test that directories with existing `.md` files trigger `run_index_rebuild` (mocked).
  - Test that existing `MEMORY.md` is left alone (idempotent).
  - Test that episodic directory does NOT get a `MEMORY.md` created (R5 exclusion).
  - Test that transcripts directory is unaffected.

> The prompt constant is the shared artifact; `run_index_rebuild` is a convenience for contexts
> without an existing agent call.
