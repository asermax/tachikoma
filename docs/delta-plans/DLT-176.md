## Batch 1: Cgroup Manager Module — ⧗ Pending
Depends on: — (none)

### Context & Research
- `docs/delta-designs/DLT-176.md` (Shape S1, Cross-Layer Contracts: cgroup_manager public API) — defines the function signatures and contracts for all cgroup lifecycle operations
- `docs/design/DES-002-logging-conventions.md` — structured logging with `.bind(component=...)` and `.warning()`/`.exception()` for cgroup fallback warnings
- Linux kernel cgroup v2 documentation — the implementing agent should follow `katachi:research-docs` guidance to verify current semantics for `memory.max`, `memory.current`, `memory.events`, `cgroup.procs`, and `/proc/self/cgroup` parsing before writing code

### Steps

#### Step 1: Create `cgroup_manager.py` with probe and discovery functions

- Create: `src/tachikoma/detached_processes/cgroup_manager.py`
- What to do:
  - Add module-level bound logger: `_log = logger.bind(component="cgroup_manager")`
  - Implement `probe_cgroup_support() -> bool` — check `/sys/fs/cgroup/` is mounted and the `memory` controller is accessible (check for `memory` in `/sys/fs/cgroup/cgroup.controllers` or that `memory.max` is writable in the self cgroup)
  - Implement `discover_parent_cgroup_path() -> str | None` — read `/proc/self/cgroup`, parse the v2 path (line starting with `0::`), resolve to absolute path under `/sys/fs/cgroup`, verify the directory exists and `cgroup.procs` is writable
  - Both functions return gracefully on any failure (log warning, return `False`/`None`)
- Test: Unit test each function with mocked filesystem (`mocker.patch` on `Path.exists`, `Path.read_text`, etc.)

#### Step 2: Add cgroup creation and PID assignment functions

- Create/modify: `src/tachikoma/detached_processes/cgroup_manager.py`
- What to do:
  - Implement `create_process_cgroup(parent_path: str, record_id: str, memory_limit_bytes: int) -> str | None`
    - `mkdir` under parent as `{parent_path}/tachikoma-{record_id}`
    - Write `memory_limit_bytes` to `memory.max` (as string of integer bytes)
    - Return the cgroup path on success, `None` on any failure (log warning)
  - Implement `assign_pid(cgroup_path: str, pid: int) -> bool`
    - Write `str(pid)` to `{cgroup_path}/cgroup.procs`
    - Return `True` on success, `False` on failure (log warning)
  - Both functions catch `OSError`/`PermissionError` and never raise
- Test: Unit test with mocked `os.mkdir`/`Path.mkdir` and file writes; test permission error returns `None`/`False`

#### Step 3: Add memory reading, OOM detection, and cleanup functions

- Create/modify: `src/tachikoma/detached_processes/cgroup_manager.py`
- What to do:
  - Implement `read_memory_current(cgroup_path: str) -> int | None`
    - Read `{cgroup_path}/memory.current`, parse as int
    - Return bytes or `None` on failure
  - Implement `check_oom_kill(cgroup_path: str) -> bool | None`
    - Read `{cgroup_path}/memory.events`, parse key-value pairs
    - Find `oom_kill` count; return `True` if > 0, `False` if 0, `None` if unreadable
  - Implement `cleanup_cgroup(cgroup_path: str) -> None`
    - `os.rmdir(cgroup_path)` — remove the cgroup directory (only works if empty)
    - Log warning on failure, never raise
- Test: Unit test each function with mocked file reads; test `cleanup_cgroup` with `os.rmdir` mock that raises `OSError`

### Steps

#### Step 7: Add `DetachedProcessesConfig` Pydantic model

- Modify: `src/tachikoma/config.py`
- What to do:
  - Add new Pydantic model after the existing settings models:
    ```python
    class DetachedProcessesConfig(BaseModel):
        model_config = ConfigDict(frozen=True, extra="ignore")

        default_memory_limit_mb: int = Field(
            default=1024,
            ge=1,
            description="Default memory limit in MB for detached processes (0/negative values rejected)",
        )
    ```
  - Add to `Settings` model:
    ```python
    detached_processes: DetachedProcessesConfig = Field(default_factory=DetachedProcessesConfig)
    ```
  - Per the design's "no default limit" decision: if the `[detached_processes]` section is absent from config, Pydantic uses `default_factory=DetachedProcessesConfig` which sets `default_memory_limit_mb=1024`. The tool handler in Batch 4 will check whether the `[detached_processes]` section was explicitly present — if absent, no default limit is applied (preserving current behavior). The `ge=1` Pydantic validation rejects explicit 0/negative values with a clear `ValidationError` at startup, consistent with all other config validation in the project (see `load_settings()` in config.py)
- Test: Verify `Settings()` picks up defaults; verify `Settings(detached_processes={"default_memory_limit_mb": 0})` raises `ValidationError`

    ```python
    doc.add(tomlkit.comment("[detached_processes]"))
    ```

    ```python
    # [NEW] Probe cgroup v2 availability
    ```
