#### Step 2: Add deferred queue infrastructure to Coordinator

- Modify: `src/tachikoma/coordinator.py`
- What to do:
  - Add `_deferred_queue: asyncio.Queue[IncomingMessage]` (unbounded, same as `_message_buffer`) in `__init__()` alongside `_message_buffer`
  - Add `enqueue_deferred(msg: IncomingMessage) -> None` — puts message into `_deferred_queue` with debug log
  - Add `has_deferred() -> bool` — returns `not self._deferred_queue.empty()`
  - Add `promote_next_deferred() -> None` — moves one item from `_deferred_queue` to `_message_buffer` via `self._message_buffer.put_nowait(self._deferred_queue.get_nowait())`
  - Update `is_busy` property: add `or self.has_deferred` so the coordinator reports busy while deferred items exist
- Test: Unit test each method in isolation; test `is_busy` returns True when deferred queue has items; test `promote_next_deferred()` moves items correctly.

#### Step 3: Add force_new routing in Coordinator.send_message()

- Modify: `src/tachikoma/coordinator.py`
- What to do: In `send_message()`, after dequeuing `msg` from `_message_buffer` (line 436), add a check for `msg.force_new` before the existing boundary detection block (lines 491–541):
  ```python
  # After: msg = self._message_buffer.get_nowait()
  # Before: will_detect_boundary = ...

  if msg.force_new and active is not None:
      # Skip boundary detection — force fresh session
      resumed = await self._handle_transition(active)
      active = await self._registry.get_active_session()
      is_new_session = not resumed
  ```
  `_handle_transition()` handles closing the current session (firing async post-processing), clearing the SDK session ID, and creating a fresh session. The `active.summary` state doesn't matter — `_handle_transition()` handles both cases. When `force_new` is True but `active is None`, skip this block entirely; boundary detection is also skipped (no active session → no detection needed), and the message proceeds normally into a new session.
- Test: Integration tests with mock SDK:
  - Active session exists: enqueue `IncomingMessage(text="hello", force_new=True)` and verify boundary detection is skipped, `_handle_transition` is called, and the message is processed in a new session.
  - No active session: with `get_active_session()` returning None, enqueue `IncomingMessage(text="fresh start", force_new=True)` and verify a new session is created without calling `_handle_transition()`.

### Steps

#### Step 4: Add _detect_command() method to TelegramChannel

- Modify: `src/tachikoma/telegram/__init__.py`
- What to do: Add a private method `_detect_command(self, message: Message) -> tuple[str | None, str]`:
  - Check `message.entities` for the first entity of type `"bot_command"` at offset 0
  - Extract command name from `message.text[entity.offset:entity.offset + entity.length]`, stripping leading `/` and any `@botname` suffix
  - Extract args from `message.text[entity.offset + entity.length:]` and strip whitespace
  - If command is `"new"` or `"queue"` and args is non-empty after strip: return `(command_name, args)`
  - All other cases (no entity, unrecognized command, bare command with no args, whitespace-only args): return `(None, message.text or "")`
  - First command wins: `/new /queue msg` → `("new", "/queue msg")`
- Test: Unit tests covering: `/new hello` → `("new", "hello")`, `/queue remind me` → `("queue", "remind me")`, `/new` → `(None, "/new")`, `/new   ` → `(None, "/new   ")`, `/new /queue msg` → `("new", "/queue msg")`, plain text → `(None, text)`, no entities → `(None, text)`.

#### Step 5: Modify _handle_message() routing logic

- Modify: `src/tachikoma/telegram/__init__.py`
- What to do: Restructure `_handle_message()` to add command detection before the existing busy/idle routing:
  ```python
  # At the top of _handle_message:
  cmd_name, cmd_args = self._detect_command(message)
  is_command = cmd_name is not None

  # In the busy branch (delivery_lock.locked()):
  #   if is_command → enqueue_deferred(IncomingMessage(text=cmd_args, force_new=(cmd_name == "new")))
  #   else → enqueue(IncomingMessage(...))  # unchanged steering behavior

  # In the idle branch (async with delivery_lock):
  #   if is_command → enqueue(IncomingMessage(text=cmd_args, force_new=(cmd_name == "new")))
  #   else → enqueue(IncomingMessage(...))  # unchanged
  #   await _process_through_coordinator()
  #   await _drain_deferred_queue()  # new — see Step 6
  ```
- Test: Integration-style test with mock coordinator verifying `enqueue_deferred` called for commands when busy, `enqueue` with correct `force_new` when idle.

#### Step 6: Add drain loop after delivery

- Modify: `src/tachikoma/telegram/__init__.py`
- What to do: Add private method `_drain_deferred_queue(self) -> None`:
  ```python
  async def _drain_deferred_queue(self) -> None:
      while self._coordinator.has_deferred():
          self._coordinator.promote_next_deferred()
          await self._process_through_coordinator()
  ```
  Each iteration wraps only the `_process_through_coordinator()` call in try/except — log error and continue to next item. Renderer or infrastructure errors propagate normally. The method is called after every `_process_through_coordinator()` call in `_handle_message` (Step 5) and `_deliver` (Step 8). Note: `promote_next_deferred()` uses `get_nowait()`/`put_nowait()` and is infallible for non-empty queues, so the loop cannot spin indefinitely.
- Update `_deliver()` method to also drain after delivery (for buffered delivery events that may produce deferred items).
- Test: Unit test verifying FIFO processing order, error resilience (one failing item doesn't block others), empty queue is no-op. Integration test for boundary detection outcomes on promoted messages: (a) `/queue` that continues current session, (b) `/queue` that triggers topic shift to new session, (c) `/queue` that resumes previous session, (d) boundary detection error defaults to continuation.

#### Step 7: Register /new and /queue commands via set_my_commands()

- Modify: `src/tachikoma/telegram/__init__.py`
- What to do: In `run()`, after `_log.info("Starting Telegram bot...")` and before the signal handlers, call `await self._bot.set_my_commands([...])`:

- Test: Verify `set_my_commands` called with correct arguments in a mock test. Mock `set_my_commands` to raise `TelegramAPIError` and verify warning is logged but bot continues running.

#### Step 8: Add graceful shutdown drain

- Modify: `src/tachikoma/telegram/__init__.py`
- What to do: In `run()`, add deferred queue drain in the `finally` block, after `_flush_buffer_on_shutdown()`:
  ```python
  # After buffer flush, before signal handler cleanup:
  await self._drain_deferred_queue()
  ```
  This ensures queued messages are processed even if shutdown begins while messages are deferred. The drain reuses the same `_drain_deferred_queue()` method from Step 6.
- Test: Integration test verifying deferred messages are processed during shutdown sequence.
