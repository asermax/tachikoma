## Notes

- The startup path is deliberately separate from `_handle_transition()` — there is no previous session to close and no post-processing to fire. Reusing `_handle_transition()` would require null-guarding it, adding complexity to an already nuanced method.
- `_persist_bridging_context()` is reused as-is — it doesn't depend on whether the resume happened during a transition or at startup.
- The `ended_at` capture from `get_recent_closed()` results is a critical sequencing detail: `reopen_session()` clears `ended_at` on the DB record, so it must be retained before the reopen call.
- Feature documentation reconciliation (boundary-detection.md, sessions.md, core-architecture.md) happens after implementation via `/katachi:reconcile-delta`.
