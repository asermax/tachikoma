## Working Notes

- A fresh worktree has no `node_modules`. Run `pnpm install --frozen-lockfile` before any gate.
- On a host with about 2 GB of RAM, `tsc` dies at the default heap. Check `free -m`, then prefix the gates with `NODE_OPTIONS=--max-old-space-size=1024`. `just check` inherits it.
- Run every `pnpm` command from the worktree root. Running `pnpm --dir <worktree> install` from another directory has been seen here to skip `pnpm-workspace.yaml`, after which pnpm rewrites `allowBuilds` with placeholder text.
- After any `pnpm install`, run `git status --short pnpm-workspace.yaml`. With an explicit `minimumReleaseAge`, the release-age gate never writes the file. `allowBuilds` is a second write path: an install that meets a package pnpm treats as needing a build, which is one that declares an install script, ships a root `binding.gyp` or ships files under `.hooks/`, and that `allowBuilds` does not rule on, makes pnpm write a placeholder entry and fail with `ERR_PNPM_IGNORED_BUILDS`. Placeholder text under `allowBuilds` means such a package is not ruled on.
- `katachi:doc-researcher` cannot spawn in this harness. Verify library facts against the shipped package (`docs/`, `dist/*.d.ts`, `CHANGELOG.md`) at the locked version, and against the official docs through WebSearch/WebFetch.
- The design's scratch tree at the target versions may still be at `/tmp/dlt-186-design/trial`. It is a read-only reference for `.d.ts` files and probe output. Do not depend on it.
- The gate does not type-check tests (`tsconfig.json` includes only `src`). Anything proved at type level lives in `src`.
- Not type-checking tests also lets a wrong type pass at runtime. For a new or heavily edited test file, run a one-off `tsc` from the worktree root: a config in `/tmp` that `extends` the repo's `tsconfig.json`, sets `noEmit`, `typeRoots` to the repo's `node_modules/@types` and a `rootDir` that contains the files, and lists the test files plus `src/types/*.d.ts` under `include`, without which `src/log.ts` reports a missing declaration for `pino-roll`. Take the baseline with `HEAD`'s version of the file at its real path. A copy outside the worktree cannot resolve its imports.

Inventory the resolved tree with pnpm's rule to confirm, from the worktree root:

```js
// node, from the worktree root: every resolved package pnpm treats as needing a build.
// The rule is pkgRequiresBuild in pnpm 11.3.0's dist/worker.js: an install script, a
// root binding.gyp, or files under .hooks/.
import { readdirSync, readFileSync } from "node:fs";
import { join } from "node:path";

const store = "node_modules/.pnpm";
const requiresBuild = new Map();

const hasFilesUnder = (dir) => {
  try {
    for (const entry of readdirSync(dir, { withFileTypes: true })) {
      if (!entry.isDirectory() || hasFilesUnder(join(dir, entry.name))) return true;
    }
  } catch {
    // not a directory
  }
  return false;
};

const record = (dir) => {
  try {
    const pkg = JSON.parse(readFileSync(join(dir, "package.json"), "utf8"));
    const scripts = pkg.scripts ?? {};
    const names = readdirSync(dir);
    const reasons = [
      ...["preinstall", "install", "postinstall"].filter((hook) => scripts[hook]),
      ...(names.includes("binding.gyp") ? ["binding.gyp"] : []),
      ...(names.includes(".hooks") && hasFilesUnder(join(dir, ".hooks")) ? [".hooks/"] : []),
    ];
    if (reasons.length > 0) requiresBuild.set(`${pkg.name}@${pkg.version}`, reasons);
  } catch {
    // not a package directory
  }
};

for (const entry of readdirSync(store, { withFileTypes: true })) {
  if (!entry.isDirectory()) continue;
  const modules = join(store, entry.name, "node_modules");
  let names = [];
  try {
    names = readdirSync(modules);
  } catch {
    continue;
  }
  for (const name of names) {
    if (name.startsWith("@")) {
      for (const scoped of readdirSync(join(modules, name))) record(join(modules, name, scoped));
    } else {
      record(join(modules, name));
    }
  }
}

for (const [name, reasons] of [...requiresBuild].sort()) {
  console.log(`${name}  ${reasons.join(", ")}`);
}
```

On the upgraded tree, from a clean install, the script prints six lines for four names: `@google/genai`, `esbuild` three times, `protobufjs` and `better-sqlite3`. The last is there for its `binding.gyp` alone. It has to run on a clean install, because an in-place one leaves the directories of replaced packages in place.
