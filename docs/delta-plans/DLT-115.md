#### Step 6: Add `psutil` runtime dependency

- Test: `uv run python -c "import psutil; print(psutil.__version__)"` prints `6.x`.

#### Step 7: Implement `is_alive`

- Create: `src/tachikoma/detached_processes/spawn.py`
- What to do: Define `is_alive(record: ProcessRecord) -> bool`. Build a `psutil.Process(record.pid)`; return `False` on `psutil.NoSuchProcess` / `psutil.AccessDenied`; otherwise return `proc.create_time() == record.process_create_time and proc.is_running()`. Single source of truth; no other module computes liveness.
- Test: `tests/detached_processes/test_spawn.py::test_is_alive_*` — spawn a short-lived `sleep` child for the happy path (fresh PID, fresh create_time → `True`), kill and verify `False`, mock `psutil.Process` for `NoSuchProcess` / `AccessDenied` / PID-reuse (mismatched create_time → `False`).

#### Step 8: Implement `spawn_process`

- Modify: `src/tachikoma/detached_processes/spawn.py`
- What to do: Async helper that wraps subprocess launch, identity capture, and DB persistence. Per P2 / Spawn flow in the design:
  - Validate `name` / `command` non-whitespace; validate `cwd` exists when provided; validate log directory is writable (re-check; don't rely on the bootstrap hook alone — per P4).
  - Build `wrapper = f"{command}; echo $? > {exit_path}"`. Use `shlex.quote` on the `exit_path` portion to tolerate paths with unusual characters.
  - Open `log_path` in `"ab"`; pass the fd as `stdout`; `stderr=asyncio.subprocess.STDOUT`; `stdin=asyncio.subprocess.DEVNULL`. No `os.set_inheritable` needed — `subprocess.Popen` marks the stdin/stdout/stderr fds inheritable internally. Close the parent's copy of the log file immediately after `create_subprocess_exec` returns (the child has its own descriptor) to avoid leaking fds.
  - Call `asyncio.create_subprocess_exec("sh", "-c", wrapper, start_new_session=True, env={**os.environ, **(env_overrides or {})}, cwd=target_cwd)`.
  - Capture `pid = proc.pid`; immediately `process_create_time = psutil.Process(pid).create_time()` — do this synchronously right after spawn before anything can race.
  - Persist `ProcessRecord` via `repository.create(...)`. On DB failure: `os.killpg(os.getpgid(pid), signal.SIGKILL)` inside a `try/except` that swallows errors (best-effort cleanup per P2); re-raise the original DB error.
  - Return the persisted `ProcessRecord`.
- Test: `test_spawn.py::test_spawn_*` covering: happy path (spawn `sleep 10`, assert record fields match reality), invalid `cwd`, whitespace `name`/`command`, environment merge (base env + overrides), sh-features (`pipes && redirects`) work end-to-end, DB-failure cleanup kills the child (simulate via a repo stub that raises), log dir permission failure surfaces clearly.

#### Step 9: Implement `terminate`

- Modify: `src/tachikoma/detached_processes/spawn.py`
- What to do: `async def terminate(record, *, signal=SIGTERM, timeout=10) -> None`.
  - Use `os.killpg(os.getpgid(record.pid), signal)` — signal the whole process group, not just the wrapper.
  - If `timeout == 0`: return immediately after signalling.
  - Otherwise poll `is_alive(record)` every ~100ms up to `timeout` seconds via `asyncio.sleep`. If still alive, send `SIGKILL` to the group and poll briefly to confirm.
  - Translate `ProcessLookupError` into a clean no-op (the process died between our last check and this call).
  - Raise `PermissionError` as-is — the caller (tool handler) translates it into the "OS rejected the signal" error per the Termination AC.
- Test: `test_spawn.py::test_terminate_*` — spawn a quick `sh -c 'sleep 5'`, send SIGTERM, assert it exits and the group is cleaned. Spawn an ignoring child (`trap '' TERM; sleep 60`), assert escalation to SIGKILL within the timeout. `timeout=0` returns without polling. PermissionError propagates (monkey-patch `os.killpg` to raise).

#### Step 10: Implement log readers

- Create: `src/tachikoma/detached_processes/log_io.py`
- What to do:
  - `read_tail(path: Path, n: int = 100) -> list[str]` — reverse-seek chunked reader; never load the entire file. Use `file.seek(0, 2)` for size, then walk backward in fixed-size chunks (e.g. 8 KiB), splitting on newlines, until `n` lines collected or file start reached. Return lines oldest-first.
  - `read_window(path: Path, line_offset: int, line_count: int) -> list[str]` — sequentially read line by line from the start (or via a bounded scan) to satisfy the offset/count window; this is the paging path and does not need to be fast for gigabyte files.
  - Raise `FileNotFoundError` if the path is missing; raise `OSError` on IO failures — the tool handler wraps these into clear errors.
- Test: `test_log_io.py` — tail on a 1000-line file returns the last N (verify ordering and count), tail handles files smaller than `n`, `read_window` returns the correct slice, both raise `FileNotFoundError` when missing, memory-usage sanity check (don't load a 100MB test fixture to tail 10 lines — use a moderately sized fixture and assert `read_tail` doesn't read the whole thing by monkey-patching `file.read`).

## Batch 3: Shared reconciler — ✓ Done
Depends on: Batch 1, Batch 2

### Context & Research

- Spec R13, R15 (especially: watcher is sole producer, priority mapping, exit-code nullability)
- Design P10, P11c; "Accepted Edge-Case Tradeoffs" (sidecar flush race handled via single 100ms retry; conditional-UPDATE race winner)
- `src/tachikoma/notifications.py` — `dispatch_notification` signature (note `severity` is `"info" | "error"`, `priority` is a `Priority` enum value), `Notification` event
- `src/tachikoma/buffer/priority.py` — `Priority.NORMAL`, `Priority.URGENT`

**Decision pinned here (referenced by Batch 6):** `reconcile_exit` takes `bus: EventBus | None`. When `dispatch_notification=True`, `bus` must not be `None` (assert this at the top of the function). When `dispatch_notification=False` (crash-recovery / stop_process paths), `bus` may be `None` and is never used. This keeps the bootstrap hook's bus-less call path clean without introducing two APIs.

### Steps

#### Step 12: Implement `reconcile_exit`

- Create: `src/tachikoma/detached_processes/reconcile.py`
- What to do: `async def reconcile_exit(record, *, repository, bus: EventBus | None, log_dir, dispatch_notification: bool = True) -> None`. Precondition: `assert bus is not None or not dispatch_notification`.
  - Compute `exit_path = log_dir / f"{record.id}.exit"`.
  - Read `exit_path`: if missing, `await asyncio.sleep(0.1)` once and retry; if still missing, `exit_code = None`; if present but unparseable, also `None` (log a warning).
  - Call `repository.reconcile_to_exited(record.id, exited_at=datetime.now(UTC), exit_code=exit_code)`. If it returns `False` (lost the race), return silently — don't dispatch.
  - Determine notification severity/priority: `code == 0 → severity="info", priority=Priority.NORMAL`; otherwise `severity="error", priority=Priority.URGENT` (including `None`).
  - If `dispatch_notification` is True: call `dispatch_notification(bus, source=f"Detached process: {record.name}", content=<one-line summary with exit_code>, severity=..., priority=..., source_id=record.id)`.
  - Wrap the whole body in a per-record `try/except Exception` that logs via `_log.exception` and returns — reconciler errors must never crash the watcher loops.
- Test: `tests/detached_processes/test_reconcile.py`:
  - Sidecar present with `"0\n"` → record updated, `dispatch_notification` called with NORMAL/info.
  - Sidecar present with `"1\n"` → URGENT/error.
  - Sidecar absent → retry + None + URGENT.
  - `dispatch_notification=False` → no dispatch call.
  - Lost conditional-UPDATE race (stub repo returns False) → no dispatch.
  - Exception inside reconciler → logged, not raised.

#### Step 14: Implement the event-driven watcher

- Create: `src/tachikoma/detached_processes/watcher.py`
- What to do: `async def event_driven_watcher(repository, bus, log_dir) -> None`.

  - Reconciler exception is caught and the loop continues.

#### Step 15: Implement the fallback polling watcher

  - Empty `list_running()` → single sleep tick, no reconcile calls.

#### Step 18: Implement extracted handlers with lazy reconciliation

- Modify: `src/tachikoma/detached_processes/tools.py`
- What to do: For every tool that operates on an existing record (`list_processes`, `get_process`, `read_process_output`, `stop_process`), the handler must:
  - Fetch the record(s).
  - For each `status="running"` record, run `is_alive(record)`; if `False`, call `await reconcile_exit(record, ..., dispatch_notification=True)` inline **before** running tool-specific logic. Use default `dispatch_notification=True` since the watcher is the canonical producer, but lazy reconciliation legitimately observes an exit the watcher hasn't reached yet — R15 AC covers this path.
  - Re-fetch after reconciliation so the response reflects the current state.
- Handler responsibilities per tool:
  - `handle_start_process`: validate, call `spawn_process(...)`, return `{id, pid, log_path}` in a formatted text block. Surface spawn errors (invalid `cwd`, empty fields, spawn-exec failure, DB write failure with orphan cleanup) as `is_error` responses.
  - `handle_list_processes(archived=False)`: `list_running()` or `list_exited()` from the repo; run lazy reconciliation on the running set before returning. Display via timezone-aware strftime of `started_at`/`exited_at` using the configured timezone (same pattern as `tasks/tools.py`).
  - `handle_get_process(process_id)`: `repository.get(...)`, lazy reconcile if running, return full detail text. 404 when missing.
  - `handle_read_process_output(process_id, offset?, count?)`: look up the record, call `read_tail(log_path, 100)` when no offset/count given, otherwise `read_window(log_path, offset, count)`. Empty/missing-yet log → explicit "no output yet" message. Missing-after-exit or unreadable → `is_error` with a clear message.
  - `handle_stop_process(process_id, signal?, timeout?)`:
    - Parse the signal string (`"SIGTERM"`, `"SIGKILL"`, etc. via `signal.Signals[name]`); default `SIGTERM`.
    - 404 if record missing.
    - Lazy reconcile; if the record is already exited (either already-exited in DB or reconciled just now), return "already stopped" — and pass `dispatch_notification=False` **only** for the reconciliation call made by stop_process itself (R15 "stop_process does not dispatch" / P11c suppression). Note the design's accepted race: if the watcher already fired in parallel, a notification from the watcher is acceptable.
    - Otherwise call `terminate(record, signal=sig, timeout=timeout)`, then `await reconcile_exit(record, ..., dispatch_notification=False)`.
    - Translate `PermissionError` into the "OS rejected signal" AC response without mutating the record.
    - Per design's "Accepted Edge-Case Tradeoffs": no attempt is made to block the watcher from firing a notification if it observes the same exit first — that would require a `stopping` intermediate state which is out of scope (R15 literal wording is still satisfied: `stop_process` itself does not dispatch).
  - `handle_rename_process(process_id, name)`: strip, reject empty, 404 missing, call `repository.update(id, name=new_name)`.
- All handlers follow DES-006's error contract: `ProcessRepositoryError` → `{"is_error": True, "content": [{"type": "text", "text": f"{exc}{cause}"}]}`; other exceptions logged with `_log.exception` and surfaced via a generic "Unexpected error".
- Test: `tests/detached_processes/test_tools.py` — one test class per handler covering every AC branch (happy path, validation errors, 404, lazy-reconciliation, `stop_process` with `timeout=0`, `stop_process` already-dead, `read_process_output` empty/missing/large, rename whitespace rejection, etc.). Explicitly include `test_start_process_allows_duplicate_names` covering R16 (two records with identical names coexist without error). Use a real `ProcessRepository` against an in-memory database fixture; stub `spawn_process`/`terminate` with monkey-patches to avoid actually spawning subprocesses in handler-level unit tests (integration coverage lives in Batch 2 tests).
