#### Step 3: Create `create_pinning_server()` factory in `pinning.py`

- Modify: `src/tachikoma/telegram/pinning.py`
- What to do: Add `create_pinning_server(bot: Bot, chat_id: int, get_last_message_id: Callable[[], int | None]) -> McpSdkServerConfig` factory function. Define both `pin_message` and `unpin_message` tools inside the factory body using `@tool()` decorator with closure-captured state. Return `create_sdk_mcp_server(name="telegram-pinning", tools=[pin_message, unpin_message])`.
- Test: `just lint && just typecheck`

#### Step 4: Register pinning server in `get_mcp_servers()`

- Modify: `src/tachikoma/telegram/__init__.py`
- What to do:
  - Add import for `create_pinning_server` from `tachikoma.telegram.pinning` (near line 47, alongside the `tools` import)
  - Define a getter lambda in `get_mcp_servers()` that resolves to the current renderer's message ID:
    ```python
    get_msg_id = lambda: (
        self._active_renderer.get_last_message_id()
        if self._active_renderer is not None
        else None
    )
    ```
  - Add `"telegram-pinning"` entry: `create_pinning_server(self._bot, self._settings.authorized_chat_id, get_msg_id)`
  - Return both servers: `return {"send-file": server, "telegram-pinning": pinning_server}`
- Why the lambda works: `_active_renderer` is set per-response (line 844) and cleared in `finally` (line 893). The lambda captures `self`, so at tool execution time it reads the current `_active_renderer`. Between responses it returns `None`, which makes `pin_message` return "No message available to pin" — correct behavior for background tasks with no active renderer.
- Test: `just lint && just typecheck`
