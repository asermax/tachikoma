## Shape

| Part | Mechanism | Flag |
|------|-----------|:----:|
| **S1** | Message ID getter on ResponseRenderer: expose `_current_message_id` via a `get_last_message_id() -> int \| None` method, set after each `_send_chunks()` / `finalize()` call; the MCP server factory captures this getter and `pin_message` calls it to determine which message to pin | |
| **S2** | `pin_message` tool: calls the renderer getter, pins the returned message ID silently (`disable_notification=True`), returns success with the ID; idempotent; returns error if no message ID available or API call fails | |
| **S3** | `unpin_message` tool: accepts a `message_id: int` argument (Pydantic-validated), unpins that message; idempotent; returns error on API failure | |
| **S4** | MCP server factory: `create_pinning_server()` following existing `create_send_file_server()` pattern — captures bot, chat_id, and message ID getter via closures | |
| **S5** | Integration: register "telegram-pinning" server in `get_mcp_servers()` alongside "send-file" | |
