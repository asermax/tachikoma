## Shape

| Part | Mechanism | Flag |
|------|-----------|:----:|
| **S1** | Version tracking model — add `installed_version` field to plugin record (git: full 40-char commit SHA, url: SHA-256 content hash, local: null). Persisted alongside plugin state. | |
| **S2** | Git update detector — fetch remote ref, compare HEAD SHA to stored version. Return update-available or up-to-date. Handle network errors gracefully. | |
| **S3** | URL content hasher — compute SHA-256 content hash of downloaded archive. Compare to stored hash to detect changes. | |
| **S4** | Local source symlink materializer — replace copytree with symlink creation for local sources. Handle existing copies (migrate on next reconciliation). | |
| **S5** | Startup reconciliation refactor — change reconciler to skip already-installed plugins. Only materialize on first install. Keep orphan cleanup. | |
| **S6** | update_plugin MCP tool — single-plugin update: re-materialize, update version hash, trigger re-registration. Handle each source type. Per-plugin lock to prevent concurrent updates. | |
| **S7** | update_all_plugins MCP tool — bulk update: iterate plugins with update-available status, apply updates sequentially, return structured summary. | |
| **S8** | Daily update check task — system task definition (cron) created during plugins bootstrap. Runs git update detection for all git-source plugins, sends notification via existing notification system if updates found. | |
| **S9** | Plugin re-registration on update — on successful update: unregister skills, unsubscribe events, re-parse manifest, re-validate hooks, re-register skills, re-subscribe events. On failure: keep new materialized version, retain old skills/subscriptions, attach diagnostic. | |
| **S10** | Update status in list_plugins — extend list_plugins output to include update availability status and version info. | |
