# Design: DLT-076 - Re-evaluate memory context per message

**Delta Spec**: [../delta-specs/DLT-076.md](../delta-specs/DLT-076.md)
**Status**: Draft

## Purpose

This document explains the design rationale for this delta: how to move the memory context provider from session-gated to per-message evaluation, including session forking, prompt updates, and individual entry management.

## Shape

| Part | Mechanism | Flag |
|------|-----------|:----:|
| **S1** | Convert `MemoryContextProvider` from `ContextProvider` to `MessageContextProvider`, register in per-message pipeline instead of session-gated pipeline | |
| **S2** | Accept SDK session ID in the per-message provider and use `fork_session=True` when available (first message: standalone query, subsequent: fork) | ⚠️ |
| **S3** | Update prompt to instruct the agent to evaluate conversation context and decide whether new memories are needed before searching | |
| **S4** | Return `list[ContextResult]` with one entry per memory file, each with tag "memories" and metadata containing the memory file path | |
| **S5** | Check `existing_entries` metadata to skip memories already present in context | |

### Flagged Unknowns

#### S2 — SDK session ID passing
The `MessageContextProvider.provide()` currently accepts `(message, existing_entries)`. The SDK session ID is held by the coordinator (`self._sdk_session_id`) and isn't passed through the per-message pipeline. Need to determine how to pass it — extend the pipeline interface, extend the provider signature, or set it on the provider instance before running the pipeline.
