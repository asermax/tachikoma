## Shape

| Part | Mechanism | Flag |
|------|-----------|:----:|
| **S1** | Replace the `is_relative_to(workspace)` check in `validate_file_path` with a membership check against a resolved allowed-roots set (workspace + system temp dir + configured extras); preserve the existing existence and regular-file checks; unqualified paths still prefixed with workspace | |
| **S2** | Add a new field on `TelegramSettings` for extra allowed absolute roots (default `[]`); apply `~` expansion and absoluteness validation at load; thread the resolved list into the `create_send_file_server` factory | |
| **S3** | Rewrite the rejection error message to list the allowed roots (workspace, system temp directory, configured extras) so the agent can self-correct | |
| **S4** | Update `src/tachikoma/telegram/skill/SKILL.md` to describe the new accepted locations and replace the "file must exist in the workspace" constraint | |
| **S5** | Extend tests in `tests/telegram/` to cover: temp-dir absolute accepted, workspace absolute accepted, workspace-relative accepted, directory rejected, outside-allowed-roots rejected, symlink to outside rejected (and the inverse), configured extra root accepted, relative config entry fails validation | |
