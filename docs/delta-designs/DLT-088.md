## Shape

| Part | Mechanism | Flag |
|------|-----------|:----:|
| **S1** | Three built-in task definitions (episodic, facts, preferences), registered during bootstrap as system-owned background tasks with nightly cron schedules | |
| **S2** | Episodic maintenance agent: reads episodic directory, applies tiered consolidation strategy (clean → weekly → monthly → delete) based on file dates, produces consolidated summaries and removes originals | |
| **S3** | Facts maintenance agent: reads all fact files, identifies stale/redundant/overlapping content, edits within files, merges files, or removes obsolete ones | |
| **S4** | Preferences maintenance agent: reads all preference files, identifies redundancy and overlap, consolidates by editing within files, merging, or removing | |
| **S5** | Time window thresholds sourced from configuration with sensible defaults | ⚠️ |

### Flagged Unknowns

#### S5 — Configuration shape for time window thresholds
The configuration shape for time window thresholds (where in config.toml, naming conventions, whether all three tasks share a `[memory.maintenance]` section or each has its own) needs investigation during design to align with the existing config patterns.
