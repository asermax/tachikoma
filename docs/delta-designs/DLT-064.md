### Flagged Unknowns

#### S4 — Expandable-blockquote entity emission path

The markdown→entity converter (`src/extensions/telegram/entities.ts`) emits `blockquote` for `>` markdown but has **no path that produces a `expandable_blockquote` entity** — the agent's markdown never expresses "collapsible," so the collapse region is a renderer concept, not a markdown construct. The design phase must resolve HOW the collapsed content becomes an `expandable_blockquote` payload:

- **Option A — renderer-driven payload**: the renderer builds the collapsed region as a structured `{ text, entities }` payload directly (emitting the `expandable_blockquote` span over the baked `_🔧 <summary>_` summaries), bypassing `toTelegramEntities` for that region and splicing it into the surrounding converted payload.
- **Option B — sentinel convention**: introduce a markdown sentinel the converter maps to `expandable_blockquote`, so the renderer can keep composing raw markdown strings in its buffer and let the existing convert-then-split pipeline handle it.

Investigation questions: which option composes cleanly with `compose()`/`finalize()` (which rebuild from a markdown buffer) and with `splitMessageWithEntities` (entity-safe chunking across the 4096 limit); whether the `expandable_blockquote` entity needs a minimum line count to actually collapse in Telegram and how that interacts with the threshold floor; and whether the existing `blockquote` emission path can be generalized or whether a separate builder is cleaner. May surface a new requirement (e.g. a minimum-content guard for the collapsed block).

## Detected Impacts

### Affected Feature Designs

- **[../feature-designs/telegram.md](../feature-designs/telegram.md)** - Modifies: the `streaming.ts` component description and the "Progressive paragraph-gated rendering with baked tool markers" key decision (intensive-work detection, the threshold trigger, the retroactive fold in `compose()`, expandable-blockquote emission); a new key decision records the collapse mechanism (expandable blockquote over spoiler) and the "threshold as trigger, not quota" model.

### Notes for Reconciliation

- The Telegram feature spec gains a new requirement for intensive-work collapse and accompanying acceptance criteria; the existing inline tool-summary behavior is preserved as the below-threshold / disabled case.
- Two new config keys under `[extensions.telegram]`: `collapseIntensiveWork` (boolean, default true) and `intensiveWorkThreshold` (number, default 4).
- `expandable_blockquote` is added to the set of entities the renderer can emit; the markdown→entity converter (`entities.ts`) currently has no path producing it, so this is a new emission path driven by collapse state rather than agent markdown (see S4).

## Notes

- This is a rendering-only delta with no new Tachikoma-controlled screens or navigation; the spec deliberately omits a User Flow / breadboard section, and this design omits a UI Layout section (the expand/collapse is a Telegram-native affordance).
