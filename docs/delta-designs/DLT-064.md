| Part | Mechanism | Flag |
|------|-----------|:----:|
| **S1** | Boundary counter + segment tracking in `StreamRenderer` — increments once per **tool→text transition** within the current uncommitted message (a contiguous block of one or more tool calls followed by *any* text = one boundary; a trailing tool block with no following text adds none, its summary baking into the all-intensive case at finalize). Resets at each message boundary (overflow commit / finalize split). Drives whether collapse is active (`count > threshold`). | |
| **S2** | Threshold + enable-flag config — two new `[extensions.telegram]` keys (`collapseIntensiveWork` default `true`, `intensiveWorkThreshold` default `4`) threaded from `index.ts` → channel → renderer constructor. The threshold is a **trigger** (collapse only once the count *exceeds* it), never a quota of segments kept visible; turns at or below it render exactly as today. | |
| **S3** | Retroactive fold in `compose()`/`flush()` — once the count exceeds the threshold, rebuild the live message so **all intermediate segments** (every completed `_🔧 <summary>_` marker and bridging-text segment chronologically before the live tail) fold into one collapsed block, leaving only the **live tail** (the streaming paragraph or the currently-running tool) expanded. Applied only at boundaries (never mid-tool); on the crossing boundary, segments that had rendered inline fold in retroactively (rebuilt from the buffer). A committed overflow chunk evaluated as intensive carries its own collapsed block; a committed message is never retroactively collapsed. | |
| **S4** | Expandable-blockquote payload emission — **renderer-driven structured payload** (see [SPIKE-DLT-064](../spikes/SPIKE-DLT-064-expandable-blockquote.md)). Add two pure helpers to `entities.ts`: `wrapExpandable(payload)` (prepend one `{ type: "expandable_blockquote", offset: 0, length }` span over a converted payload) and `concatPayloads(a, b, sep?)` (join two payloads, rebasing offsets). When collapse is active, build the payload as `wrapExpandable(convert(intermediate)) ⊕ convert(tail)` instead of `toTelegramEntities(display)`; the markdown-buffer model is otherwise unchanged. Inner italic/code/bold summary-marker entities nest validly inside the blockquote. | |
| **S5** | Finalize layout — render **header (DES-009) → collapsed block → final answer tail** in chronological order; the all-intensive case (no final text, or the threshold crossed on the final boundary) makes the whole message the collapsed block, still carrying the per-segment summaries so it is never empty. The threshold-as-trigger guarantees a multi-marker (multi-line) block, satisfying Telegram's collapse requirement. | |
| **S6** | Composition guards — the decision header ([DES-009](../design/DES-009-turn-scoped-anchored-header.md)) anchors above the collapsed block on every recompose (never overwritten); completion-push copy-delete copies the finalized message as-is; `error`/`status` transient lines and the broken-render plain fallback (`finalizeBroken` → `sendChunked`, no entities) are unaffected. | |

### Spike Resolution

S4's flagged unknown (how the collapsed content becomes an `expandable_blockquote` payload) is resolved in [SPIKE-DLT-064](../spikes/SPIKE-DLT-064-expandable-blockquote.md): the renderer drives a structured payload via two `entities.ts` helpers rather than a markdown sentinel (GFM has no expandable-blockquote construct). grammY `1.43.0` / `@grammyjs/types@3.27.3` type `"expandable_blockquote"` directly, so `Renderer.beginSpan` accepts it with no cast. No spec change resulted (the multi-line collapse constraint reinforces R10 rather than altering it).

## Detected Impacts

### Affected Feature Designs

- **[../feature-designs/telegram.md](../feature-designs/telegram.md)** - Modifies: the `streaming.ts` component description and the "Progressive paragraph-gated rendering with baked tool markers" key decision (intensive-work detection, the threshold trigger, the retroactive fold in `compose()`, expandable-blockquote emission); a new key decision records the collapse mechanism (expandable blockquote over spoiler) and the "threshold as trigger, not quota" model.

### Notes for Reconciliation

- The Telegram feature spec gains a new requirement for intensive-work collapse and accompanying acceptance criteria; the existing inline tool-summary behavior is preserved as the below-threshold / disabled case.
- Two new config keys under `[extensions.telegram]`: `collapseIntensiveWork` (boolean, default true) and `intensiveWorkThreshold` (number, default 4).
- `expandable_blockquote` is added to the set of entities the renderer can emit; the markdown→entity converter (`entities.ts`) currently has no path producing it, so this is a new emission path driven by collapse state rather than agent markdown (see S4).

## Notes

- This is a rendering-only delta with no new Tachikoma-controlled screens or navigation; the spec deliberately omits a User Flow / breadboard section, and this design omits a UI Layout section (the expand/collapse is a Telegram-native affordance).
