## Shape

| Part | Mechanism | Flag |
|------|-----------|:----:|
| **S1** | Extend `TachikomaManifest` and `PluginManifest` with `hooks` and `events` fields; resolve module names to file paths during parsing | |
| **S2** | Handler validator in loader: verify each declared hook/event entry — file exists, module imports, expected function present with correct signature; validate event type names against registry | |
| **S3** | Event type registry: a central mapping of event type names (strings) to their `BaseEvent` subclasses | |
| **S4** | Frozen `PluginContext` dataclass: carries validated config dict, event bus reference, plugin alias, and install path | |
| **S5** | Init hook executor: runs after all plugins discovered, before coordinator starts; iterates loaded plugins alphabetically, imports and calls each init function with PluginContext, wraps in try/except with 30-second timeout | |
| **S6** | Event subscription registrar: after init hooks complete (or immediately for plugins without init hooks), subscribes handlers on event bus via `bus.on(EventType, wrapped_handler)` where the wrapper provides error isolation and passes PluginContext | |
| **S7** | Hook lifecycle manager: orchestrates init + subscribe at startup, runtime install (run init + subscribe before `PluginInstalled` dispatch), and runtime remove (unsubscribe during `PluginRemoving` phase) | |
