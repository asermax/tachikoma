# Design: DLT-114 - Set TZ environment variable for agent subprocesses

**Delta Spec**: [../delta-specs/DLT-114.md](../delta-specs/DLT-114.md)
**Status**: Approved

## Purpose

This document explains the design rationale for this delta: the modeling choices, data flow, system behavior, and architectural approach.

After implementation, the "Detected Impacts" section will guide reconciliation into feature design docs.

## Problem Context

Shell commands executed by the agent (e.g., `date`) inherit the subprocess environment, which currently has no `TZ` variable. The user's configured timezone (`settings.tasks.timezone`) is only used for cron evaluation and system prompt rendering — it never reaches the subprocess env. This means `date` output reflects the host's system timezone rather than the user's configured one.

**Constraints:**
- The existing `merge_env()` function merges `HARDCODED_ENV` with user `[agent.env]` config, rejecting collisions. Hardcoded defaults (like `CLAUDE_CODE_DISABLE_AUTO_MEMORY`) must never be silently overridden.
- `TZ` needs a different override model: it should be auto-injected but user-overridable via `[agent.env]` without raising an error.
- The system prompt currently includes `TZ='{timezone}'` as a prefix to the `date` command — once `TZ` is in the environment, this prefix is redundant.

**Interactions:**
- `agent_defaults.py` provides `merge_env()` and `HARDCODED_ENV`, consumed by `__main__.py`
- `context/loading.py` renders the system preamble template with `{timezone}` placeholders
- All SDK construction sites (coordinator, processors, providers) receive the merged env via `AgentDefaults`

## Design Overview

Introduce a second category of environment defaults — **auto-injected defaults** — alongside the existing hardcoded defaults. Auto-injected defaults are layered *before* user env so the user can silently override them, while hardcoded defaults continue to reject collisions. The `merge_env()` function gains a generic `auto_injected` dict parameter. The call site in `__main__.py` passes `{"TZ": settings.tasks.timezone}`. The system prompt date command drops the now-redundant `TZ=` prefix.

## Modeling

No new entities or domain models. This delta modifies the env merging logic (a pure function) and a template string.

**Env var categories** (conceptual model, not a new type):

| Category | Collision behavior | Override model | Example |
|----------|--------------------|----------------|---------|
| Hardcoded | Rejects collision with user env (startup error) | Cannot be overridden | `CLAUDE_CODE_DISABLE_AUTO_MEMORY` |
| Auto-injected | No collision check | User env silently wins | `TZ` |
| User env | N/A (user-provided) | Source of truth for overridable keys | Anything in `[agent.env]` |

## Data Flow

Merge expression: `{**(auto_injected or {}), **config_env, **HARDCODED_ENV}`

Priority (highest wins): hardcoded > user config_env > auto-injected

Collision check: `set(HARDCODED_ENV) & set(config_env)` — only user keys checked against hardcoded (unchanged from current code).

**User overrides TZ:**

```
auto_injected                config_env                 HARDCODED_ENV
{"TZ": "America/..."}     {"TZ": "UTC", "X": "1"}    {"CLAUDE_CODE_..._MEMORY": "1"}
        │                         │                            │
        │   collision check: set(HARDCODED) & set(config_env)  │
        │   {"CLAUDE_..._MEMORY"} & {"TZ", "X"} = {} → OK     │
        │                         │                            │
        └─────────────────────────┴────────────────────────────┘
                                  │
                         {**auto, **config, **HARDCODED}
                                  │
                                  ▼
            {"TZ": "UTC", "X": "1", "CLAUDE_CODE_..._MEMORY": "1"}
```

**User does not override TZ:**

```
auto_injected                config_env                 HARDCODED_ENV
{"TZ": "America/..."}         {"X": "1"}              {"CLAUDE_CODE_..._MEMORY": "1"}
        │                         │                            │
        │   collision check: {"CLAUDE_..._MEMORY"} & {"X"} = {} → OK
        │                         │                            │
        └─────────────────────────┴────────────────────────────┘
                                  │
                         {**auto, **config, **HARDCODED}
                                  │
                                  ▼
       {"TZ": "America/...", "X": "1", "CLAUDE_CODE_..._MEMORY": "1"}
```

## Key Decisions

### Generic `auto_injected` dict over specific `timezone` parameter

**Choice**: `merge_env()` accepts `auto_injected: dict[str, str] | None` rather than `timezone: str | None`
**Why**: Establishes a general-purpose extensibility point. Future auto-injected defaults (if any) just add entries to the dict at the call site — `merge_env()` doesn't need to change. The function stays focused on merging logic rather than knowing about specific env vars.
**Alternatives Considered**:
- Specific `timezone: str | None` parameter: Simpler but couples `merge_env()` to the TZ use case; signature grows with each new auto-injected default
- New constant `AUTO_INJECTED_ENV`: Module-level dict like `HARDCODED_ENV` — less flexible since values are dynamic (come from config at runtime)

**Consequences**:
- Pro: `merge_env()` remains a generic merging function
- Pro: Adding future auto-injected defaults requires no signature changes
- Con: Slightly more abstract than a named parameter (minor — the call site makes intent clear)

### Collision check unchanged — `config_env` only

**Choice**: The collision check remains `set(HARDCODED_ENV) & set(config_env)` — unchanged from the current implementation. Auto-injected keys are not included in the collision check. The merge expression `{**auto_injected, **config_env, **HARDCODED_ENV}` means hardcoded always has highest priority: if a future auto-injected key happened to share a name with a hardcoded key, hardcoded would silently win (by design — hardcoded keys are system invariants).
**Why**: Auto-injected defaults are intentionally overridable by users. Hardcoded defaults protect system invariants. The collision check's purpose is to catch user misconfiguration (`[agent.env]` colliding with hardcoded), not to police internal auto-injection.

**Consequences**:
- Pro: Two distinct override models coexist cleanly in one function
- Pro: No change to existing collision behavior — zero risk to current callers
- Pro: Hardcoded keys always win, even over auto-injected (defense in depth)

### System prompt removes only the TZ prefix, not the timezone display

**Choice**: The `date` command in the system preamble changes from `TZ='{timezone}' date '...'` to just `date '...'`, but the line `Your configured timezone is **{timezone}**` is preserved.
**Why**: The agent still needs to know its timezone context (for scheduling, time references). The `TZ` prefix was only needed because the env didn't carry it — now it does. The timezone name in the prompt provides context without duplicating the env mechanism.

**Consequences**:
- Pro: Cleaner prompt — no shell env prefix in instructions
- Pro: Agent still knows its timezone for contextual understanding

## System Behavior

### Scenario: Default TZ injection

**Given**: User has `tasks.timezone = "America/Buenos_Aires"` and no `TZ` in `[agent.env]`
**When**: `merge_env(config_env={}, auto_injected={"TZ": "America/Buenos_Aires"})` is called
**Then**: Returned env includes `TZ=America/Buenos_Aires` alongside hardcoded defaults
**Rationale**: Auto-injected defaults fill in when user hasn't specified a value

### Scenario: User overrides TZ

**Given**: User has `tasks.timezone = "America/Buenos_Aires"` and `TZ = "UTC"` in `[agent.env]`
**When**: `merge_env(config_env={"TZ": "UTC"}, auto_injected={"TZ": "America/Buenos_Aires"})` is called
**Then**: Returned env has `TZ=UTC` — user value wins, no collision error raised
**Rationale**: Auto-injected defaults are silently overridable by design

### Scenario: Hardcoded collision still rejects

**Given**: User has `CLAUDE_CODE_DISABLE_AUTO_MEMORY = "0"` in `[agent.env]`
**When**: `merge_env(config_env={"CLAUDE_CODE_DISABLE_AUTO_MEMORY": "0"}, auto_injected={"TZ": "..."})` is called
**Then**: `ValueError` is raised listing the colliding key
**Rationale**: Hardcoded defaults protect system invariants — collision rejection is unchanged

### Scenario: System prompt date command

**Given**: The system preamble is rendered with timezone `"America/Buenos_Aires"`
**When**: The agent reads the date command instruction
**Then**: It sees `date '+%A, %B %d, %Y at %H:%M:%S %Z (%z)'` (no `TZ=` prefix) and `Your configured timezone is **America/Buenos_Aires**`
**Rationale**: `TZ` is now in the subprocess environment, so the prefix is unnecessary
