| Part | Mechanism | Flag |
|------|-----------|:----:|
| **P1** | Extend the `Skill` dataclass with a `depends_on: tuple[str, ...]` field; parse and validate the frontmatter value in `_load_skill` (must be a list of strings; malformed → warn + treat as empty). | |
| **P2** | Add `SkillRegistry.resolve_chain(skill_name) -> list[Skill]`: depth-first traversal, deps-first ordering with the anchor skill included last, a visited-set to break cycles (including self-references) and dedup, unknown dep names silently skipped during traversal. | |
| **P3** | At registry load/refresh, for each skill with declared deps, collect the set of names that don't resolve to a registered skill and emit a single warning per dependent skill listing all of its missing dep names. | |
| **P4** | Memoize `resolve_chain` results on the registry (keyed by skill name); clear the cache during `refresh()` alongside the swap-on-success dict rebuild so subsequent resolutions reflect the fresh state. | |
| **P5** | `SkillsContextProvider` expands each classification-detected skill via `resolve_chain`, filters the combined chain against skills already present in `existing_entries` (via `extract_skill_names`), and emits one `ContextResult` per remaining skill — preserving the existing `<skill>` XML shape and `skill_name` metadata so agent derivation treats dep-loaded and classification-loaded skills uniformly. | |

### Flagged Unknowns

_None at this stage — all mechanisms are understood. Design phase may still refine implementation details (e.g., exact cache invalidation hook point, whether to surface a `resolved_chain` diagnostic)._
