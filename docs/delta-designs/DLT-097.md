## Key Decisions

### Conflict Resolution Execution Model

**Choice**: Python code orchestrates git operations; agent resolves file-level conflicts
**Why**: Keeps git state management in Python where it's testable and predictable. Agents are unreliable at interactive git operations.
**Alternatives Considered**:
- Agent runs git commands directly: Unreliable for interactive operations like rebase conflict resolution
- Mechanical rebase only: Cannot intelligently merge markdown content (memories, context files)

**Consequences**:
- Pro: Git state transitions are deterministic and testable
- Con: More Python-side orchestration code to maintain

## System Behavior

### Scenario: Fast-forward push (no divergence)

**Given**: Local commits to push, remote has not advanced
**When**: Smart push runs
**Then**: Fetch → detect no divergence → push directly
**Rationale**: Most common case, should be as fast as current behavior

### Scenario: Diverged push with resolvable conflicts

**Given**: Local commits to push, remote has new commits that touch overlapping files
**When**: Smart push runs
**Then**: Fetch → detect divergence → spawn agent to resolve conflicts → rebase local on remote → push
**Rationale**: Agent understands file content and can intelligently merge

### Scenario: Diverged push with unresolvable conflicts

**Given**: Local commits to push, remote has new commits that conflict irreconcilably
**When**: Smart push runs
**Then**: Fetch → detect divergence → spawn agent → agent fails → abort and preserve local → log warning
**Rationale**: Safe fallback — local commits preserved for next sync opportunity

### Scenario: Network failure during sync

**Given**: Remote is unreachable
**When**: Any sync operation runs
**Then**: Fetch fails → log warning → continue (non-blocking)
**Rationale**: System degrades gracefully, operates on local state

## Notes

- The scope was narrowed during spec interview from "pre-message pull + session-close push" to "session-close-only + startup sync" — pre-message sync was deemed unnecessary since the agent is typically the only writer during an active session
- Conflict resolution uses Haiku model (same as commit agents) for cost efficiency
- Workspace startup sync lives in the existing `git_hook` bootstrap hook (same domain)
