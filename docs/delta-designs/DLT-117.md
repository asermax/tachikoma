## Shape

| Part | Mechanism | Flag |
|------|-----------|:----:|
| **S1** | **TaskDefinition model extension** — Add `skills: tuple[str, ...]` field to the dataclass, serialized as JSON array in the ORM column. `to_domain()` deserializes from JSON. | |
| **S2** | **Schema migration** — Add `skills` column to `task_definitions` table, defaulting to `"[]"` for existing rows. | |
| **S3** | **MCP tool parameter updates** — Add `skills: list[str] \| None` to `CreateTaskArgs` and `UpdateTaskArgs`. Wire into handlers with registry validation (warn on unknown names in response text). Update `get_task` and `list_tasks` output to display skills. | |
| **S4** | **Background task pinned skill loading** — In `BackgroundTaskExecutor._run_preprocessing()`, resolve pinned skills from the definition via the registry, create `ContextResult` entries, and include them in the final `_PreprocessingResult`. | |
| **S5** | **Session task pinned skill injection** — Carry pinned skills through the session task delivery path: resolve from definition at scheduler enqueue time, inject as context entries via BufferedItem metadata before the coordinator processes the message. | |
| **S6** | **Skill authoring update** — Update the built-in skill authoring guide to document that skills can be pinned to task definitions via the `skills` parameter. | |
