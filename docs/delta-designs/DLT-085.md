## Shape

| Part | Mechanism | Flag |
|------|-----------|:----:|
| **S1** | `schema_migrations` table: `revision` (VARCHAR PK), `name` (VARCHAR), `applied_at` (DATETIME). Created with `CREATE TABLE IF NOT EXISTS` before any migration logic. | |
| **S2** | Migration registry: ordered list of `Migration(revision, down_revision, name, statements)` dataclasses. Module-level constant in a dedicated file. | |
| **S3** | Migration runner: query applied revisions, diff against registry, execute pending in order. Each migration wrapped in its own transaction. Stamp initial migration without execution for both fresh and existing installs. | |
| **S4** | Initial migration (`001`): single revision containing all current ALTER TABLE / CREATE TABLE SQL from the pragma checks. Never auto-executed — stamped as applied. Serves as baseline documentation. | |
| **S5** | Existing DB detection: if `schema_migrations` is empty, check whether core tables exist. If yes → existing install, stamp initial as applied. If no → fresh install, `create_all()` + stamp initial as applied. | |
| **S6** | Remove all pragma-based checks from `_run_migrations()`. Replace with migration runner invocation. | |
