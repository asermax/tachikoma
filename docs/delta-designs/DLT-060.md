## Shape

| Part | Mechanism | Flag |
|------|-----------|:----:|
| **S1** | Scheduled job registered in the scheduler that runs the version check at the configured interval | |
| **S2** | PyPI version fetcher: HTTP call to `https://pypi.org/pypi/tachikoma-agent/json` to get latest version | |
| **S3** | Version comparison: read installed version from package metadata, compare against PyPI latest stable | |
| **S4** | Notification dedup: track last notified version — persistence mechanism TBD (database vs file) | ⚠️ |
| **S5** | Notification dispatch: emit a `Notification` event via the event bus at Normal priority | |
| **S6** | `[updates]` config section: `enabled` (bool, default true) and `check_interval` (int seconds, default 86400) | |
| **S7** | Bootstrap hook: register the scheduled job on startup when updates are enabled | |
| **S8** | MCP tool `check_updates`: on-demand version check returning structured result to the agent | |

### Flagged Unknowns

#### S4 — Dedup state persistence
Where to persist the last-notified version so it survives restarts. Database is the natural fit (survives restarts, no git churn), but a simple file under `.tachikoma/state/` is an alternative. Needs evaluation during design.
