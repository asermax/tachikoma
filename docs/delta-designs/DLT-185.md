### Flagged Unknowns

#### S3 — Extraction prompt, schema, and unusable-goal threshold

The extraction prompt wording and `GoalSchema` shape need drafting — likely a structured goal (end state + stated check + invariants) mirroring the recommended goal structure in spec R13, produced via `side.classify` (mirroring the existing side-classifier structured-extraction pattern). Specific questions:

- What is the exact extraction prompt, and what is the `GoalSchema` shape (free-text goal vs. structured end-state/check/invariants)?
- What is the validation threshold for an "unusable" extracted goal (spec R15) — a minimum-length/structure heuristic, or a classifier self-check?
- Is a goal that is trivially satisfiable from the task prompt alone (no real work) treated as unusable, or accepted and left for the agent to self-declare against?

#### S5 — Goal-status tool name and parameter/output shape

The tool's exact name and parameter shape. Specific questions:

- Tool name: `complete_task` (leaning — though it also handles not-completable), `declare_goal_outcome`, or `update_goal_status`?
- Parameter shape: a discriminated union (status enum + conditional fields) versus two separate tools. `completed` needs goalRestated + evidence + summary; `not_completable` needs a reason.
- Where is an invalid declaration (missing evidence/summary) rejected — inside the tool's execute handler (returns an error to the agent so it retries) or by the loop after the turn?
- What exact shape does the pending-declaration flag carry so the loop can source the instance `result` (spec R10)?

#### S7 — Nudge wording

The exact user-message wording injected between non-terminal turns. Specific questions:

- How to word the nudge so it reliably steers the agent toward declaring (or continuing) without causing premature declarations, while staying goal-oriented rather than a bare "continue"?
- Tone and length, matching the brevity of the existing continuation nudge it replaces.
