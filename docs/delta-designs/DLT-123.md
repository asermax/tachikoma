### Flagged Unknowns

#### S5 — Draft→permanent lifecycle (recurrence detection & promotion semantics)

The user explicitly asked to research this further during design. The structure choice is settled — **two sections per slug file** (`## Drafts` tentative / `## Confirmed` permanent) — but the mechanism and its reliability are open:

- **Recurrence detection reliability.** The leading mechanism is: the extraction agent, folding one branch's transcript, *reads existing learnings files* and recognizes whether the branch's friction matches an existing draft (same subject + same kind of problem). A match promotes the draft; no match creates a new draft. Open question: how reliably does a single-branch-transcript agent perform this read-and-match? Does it need an explicit "grep the learnings store for this friction before deciding" instruction, or does the existing "read existing files before creating" pattern (from topics extraction) suffice? A spike should validate this against realistic sessions.
- **Promotion-trigger semantics.** Is promotion purely extraction-time (the agent that sees the repeat promotes immediately), purely maintenance-time (a maintenance pass scans drafts and promotes ones it can corroborate), or both? Extraction-time promotion is the elegant default but may be unreliable if the agent doesn't consistently re-read; maintenance-time is a safety net. Decide which (or both) and what "corroboration" means.
- **Section ↔ index interaction.** How do the `## Drafts` / `## Confirmed` sections interact with the `MEMORY.md` index and its descriptions? Should the index entry flag whether a file holds only drafts vs. confirmed learnings? How does the Sunday full-index-rebuild describe a file whose confirmed section is empty? The maintenance prompt (S6) needs a clear rule here so the index stays meaningful.
- **Contradiction vs. recurrence.** When a later session observes the *opposite* of a draft (the friction was resolved), the spec says the contradiction is resolved/removed, not promoted. Confirm the agent can distinguish "same friction, recurring" from "same subject, now contradicted" during the read-and-match.

A spike (e.g. `docs/spikes/SPIKE-DLT-123-draft-promotion.md`) should answer these before the extraction/maintenance prompts are finalized. If the spike surfaces new requirements (e.g. a structured front-matter marker for draft vs. confirmed rather than section headers), feed them back into the spec.

## Key Decisions

### Shared topics+learnings extraction agent

**Choice**: One extraction fork classifies each signal as topic content or learning content and writes to both stores, rather than a separate learnings fork.
**Why**: Prevents duplication between `topics/` and `learnings/` — the agent decides inline, once per signal.
**Alternatives Considered**:
- Separate per-store learnings fork (iterate `MEMORY_STORES` uniformly): rejected — would let the same signal be written to both stores with no shared decision.
**Consequences**:
- Pro: No duplication; single classification decision.
- Con: Breaks the uniform per-store extraction loop; requires splitting the loop into episodic + topics+learnings forks (S3).

### Draft→permanent lifecycle enforces "recurring"

**Choice**: Capture broadly as drafts; promote to permanent only on cross-session recurrence.
**Why**: Nothing valuable is lost on first sighting, but only repetition earns permanence — keeping the store focused on real patterns.
**Alternatives Considered**:
- Gating at capture time (only record recurring friction): rejected — loses one-off high-value lessons before they recur.
**Consequences**:
- Pro: No lost lessons; the store self-curates toward confirmed patterns.
- Con: The store carries drafts that may never recur; promotion reliability depends on S5 (flagged).

## System Behavior

### Scenario: First sighting of a friction

**Given**: A session surfaces a friction not yet in `learnings/`.
**When**: The shared extraction agent folds the branch.
**Then**: The friction is written as a **draft** (tentative), not a confirmed learning.
**Rationale**: Single occurrence does not yet establish a recurring pattern.

### Scenario: Recurring friction

**Given**: A draft exists for friction X.
**When**: A later session's extraction agent reads existing learnings files and recognizes the same friction X.
**Then**: The draft is promoted to **permanent**.
**Rationale**: Repetition is the signal that this is a real, recurring learning.
