## Shape

| Part | Mechanism | Flag |
|------|-----------|:----:|
| **S1** | Static index injection into foundational context — read `memories/facts/MEMORY.md` and `memories/preferences/MEMORY.md` at startup during the context bootstrap hook. Format each as a section with: a type description (what this memory type stores), usage guidance (browse entries, Read relevant files on demand), and the index entries from MEMORY.md. Append to foundational context entries alongside SOUL.md/USER.md/AGENTS.md with owner tag `"memory_index"`. Missing or empty MEMORY.md files are skipped silently. Malformed entries within a valid MEMORY.md are skipped with a debug log warning; well-formed entries are still included. | |
| **S2** | System preamble expansion — expand the existing `## Memories` subsection in `SYSTEM_PREAMLE_TEMPLATE` with general episodic memory documentation: naming conventions (daily `YYYY-MM-DD.md`, weekly `YYYY-WNN.md`, monthly `YYYY-MM.md`), retention tier descriptions (daily = recent detail, weekly = consolidated summaries, monthly = long-term arcs), content expectations (summaries not transcripts), and guidance on when episodic is useful vs facts/preferences. No hard retention numbers. | |
| **S3** | Remove agentic search infrastructure — delete `MemoryContextProvider` class, `MEMORY_SEARCH_PROMPT`, `ParsedMemoryEntry`, `parse_memory_entries()`, `extract_memory_paths()`, and all related constants (`MEMORIES_OWNER`, `MEMORY_PATH_META_KEY`, `_NO_RELEVANT_MEMORIES`) from `context_provider.py`. Remove `MemoryContextProvider` from `memory/__init__.py` exports. Clean up display code references to `memory_path` metadata in `post_processing.py`. Verify no active code imports `MemoryContextProvider` directly. | |
| **S4** | Unregister from per-message pipeline — remove `MemoryContextProvider(agent_defaults)` registration from `__main__.py`. Remove the import of `MemoryContextProvider` from the memory module import block. The per-message pipeline will only contain the skills context provider. | |
| **S5** | Format injected index sections — define the rendering format for injected index sections. Each section includes: a header, a one-paragraph description of the memory type and usage instructions, and the MEMORY.md entries preserved as-is. Example format:

```
## Facts Index

Stable reference information: personal details, key people, technical decisions.
Browse the entries below. When a file seems relevant to the current conversation,
read it with the Read tool to get the full content.

- [Restaurants](memories/facts/restaurants.md): Favorite restaurants and food preferences
- [Coding Style](memories/facts/coding-style.md): Preferred coding conventions and patterns
``` | |
