# Delta Spec: DLT-063 — Send files and media to users

## Story

As a user, I want the agent to send me files it creates or references during our conversation so that I can receive images, documents, and other media directly in Telegram without manually locating them in the workspace.

## What It Does

Enables the agent to deliver files it creates or references directly to the user's Telegram chat, with appropriate rendering based on media type. The agent decides when a file is worth sending (e.g., after generating an image or creating a requested document) and triggers delivery explicitly. Errors are reported back to the agent so it can inform the user or try alternatives.

## Requirements

| ID | Requirement | Status |
|----|-------------|--------|
| R0 | Agent can deliver files to users as part of the conversation | Core goal |
| R1 | Explicit MCP tool the agent calls to send a file, with system prompt instructions on when/how to use it | Must-have |
| R2 | Telegram channel sends files immediately when the tool is called, using the appropriate API method based on media type; Telegram's 50MB bot upload limit applies | Must-have |
| R3 | Support common media types (images, documents, audio, video) with auto-detection from file extension | Must-have |
| R4 | File validation errors (missing file, path outside workspace) and sending errors (API failures, size limits) are returned to the agent as tool errors | Must-have |
| R5 | Optional caption/context alongside delivered files | Must-have |
| R6 | REPL channel support (deferred — terminal lacks native media rendering; file paths in text suffice) | Out |
| R7 | Receiving files from users (inbound media) | Out |

## Acceptance Criteria

**File Sending Tool (R1)**

- [ ] Given the agent is processing a conversation in the Telegram channel, when it decides to share a file with the user, then it calls the `send_file` tool with the file path and an optional caption
- [ ] Given the agent's system prompt, when the agent is initialized, then it contains instructions explaining the `send_file` tool: what it does, when to use it (e.g., after generating an image, creating a document the user requested, or when a file would be more useful than pasting its contents), and that the file must exist in the workspace
- [ ] Given the agent is processing a conversation without a file-sending capability registered (e.g., REPL channel), when the agent runs, then the `send_file` tool is not available and the agent cannot attempt to call it

**Telegram File Delivery (R2)**

- [ ] Given the agent calls `send_file` with a valid file path, when the tool executes, then the file is sent to the user's Telegram chat immediately (mid-response, not queued) and the tool returns a success confirmation to the agent
- [ ] Given the agent calls `send_file` during a streaming response, when the file is sent, then it appears in the chat at the point in the conversation where the tool was called (interleaved with text messages)
- [ ] Given the agent calls `send_file` multiple times during a single response, when each call executes, then each file is sent independently and in order

**File Validation (R4)**

- [ ] Given the agent calls `send_file` with a path to a non-existent file, when the tool validates the path, then it returns a tool error stating the file was not found
- [ ] Given the agent calls `send_file` with a path to a file outside the workspace, when the tool validates the path, then it returns a tool error explaining the file must be within the workspace

**Sending Errors (R4)**

- [ ] Given the Telegram API rejects the file (e.g., exceeds 50MB limit, invalid format for the chosen method), when the API returns an error, then the error message is returned to the agent as a tool error
- [ ] Given a transient network error occurs during file upload, when the API call fails, then the error is returned to the agent as a tool error (no automatic retry)

**Media Type Detection (R3)**

- [ ] Given a file with an image extension (.png, .jpg, .jpeg, .gif, .webp), when `send_file` is called, then the file is sent using Telegram's photo API method
- [ ] Given a file with an audio extension (.mp3, .ogg, .wav, .flac), when `send_file` is called, then the file is sent using Telegram's audio API method
- [ ] Given a file with a video extension (.mp4, .avi, .mov, .webm), when `send_file` is called, then the file is sent using Telegram's video API method
- [ ] Given a file with any other extension or no extension, when `send_file` is called, then the file is sent using Telegram's document API method (generic file)

**Caption Support (R5)**

- [ ] Given the agent calls `send_file` with a caption, when the file is sent, then the caption appears alongside the file in Telegram
- [ ] Given the agent calls `send_file` without a caption, when the file is sent, then the file appears without a caption

## User Flow

### Breadboard: File Sending Flow

```
  Agent Processing Response
  -------------------------
  - streaming text to user
  - decides to share a file
         |
         v
  send_file Tool Call
  -------------------
  - file_path (required)
  - caption (optional)
         |
    +----+----+
    |         |
    v         v
  Valid     Invalid
  -----     -------
  |         - tool error → agent
  |           (not found, outside
  |            workspace)
  v
  Telegram Send
  -------------
  - auto-detect media type
  - send via appropriate API
         |
    +----+----+
    |         |
    v         v
  Success   API Error
  -------   ---------
  - file     - tool error → agent
    appears    (size limit,
    in chat     network, etc.)
         |
         v
  Agent Continues
  ---------------
  - resumes text streaming
  - can reference the sent file
  - can send more files
```

### Flow Description

**Entry point**: The agent decides during a conversation that a file would be useful to the user — e.g., after generating an image, creating a requested document, or when file contents are better delivered as a file than pasted inline.

**Happy path**: The agent calls `send_file` with the file path and optional caption. The tool validates the file exists and is within the workspace, detects the media type from the extension, and sends it via the Telegram bot API using the appropriate method (photo, audio, video, or document). The file appears immediately in the Telegram chat. The tool returns a success confirmation, and the agent continues its response. The agent may send multiple files in a single response by calling the tool repeatedly.

**Decision points**: File validation (exists? in workspace?) → media type detection (image/audio/video/other) → Telegram API result (success/failure).

**Exit points**: File successfully delivered (agent continues), validation error returned to agent (agent can inform user), API error returned to agent (agent can explain or retry with different approach).
