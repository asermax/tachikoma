# Delta Spec: DLT-099 - Archive conversation transcripts to project workspace

## Story

As the system, I need conversation transcripts archived to the project workspace so that they survive SDK storage changes and are accessible for project-local operations (search, analysis).

## What It Does

On session close, copies the conversation transcript file from the SDK's internal storage location to `memories/transcripts/` within the project workspace. The archived transcript uses the SDK session ID as its filename, making the archived path derivable from any session record without a dedicated field. Archival failures are logged but never crash the conversation or block other post-processing.

## Acceptance Criteria

**Transcript Archival (R0, R1, R6, R8)**:
- Given a session with a populated `transcript_path` and `sdk_session_id`, when post-processing runs, then the transcript file is copied to `memories/transcripts/<sdk-session-id>.jsonl`
- Given a session with a populated `sdk_session_id`, when the archived path is needed, then it can be derived as `memories/transcripts/<sdk-session-id>.jsonl` without querying a dedicated field

**Pipeline Integration (R2, R5)**:
- Given the transcript archive processor is registered, when post-processing runs, then it executes before the git commit phase
- Given a transcript was archived, when the git post-processor runs in the finalize phase, then the archived file appears in the workspace diff and is committed

**Graceful Degradation (R3)**:
- Given a session with a null `transcript_path`, when the archive processor runs, then it skips with a debug log and completes normally
- Given a session with a null `sdk_session_id`, when the archive processor runs, then it skips with a debug log and completes normally (no `sdk_session_id` means no filename to derive)
- Given a session whose `transcript_path` points to a file that no longer exists, when the archive processor runs, then it logs a warning and completes normally
- Given the archive processor encounters a filesystem error (permissions, disk full), when the copy fails, then it logs the error and completes normally — other processors and phases are unaffected
- Given the destination directory `memories/transcripts/` does not exist at copy time (e.g., removed after bootstrap), when the archive processor runs, then it creates the directory on demand before copying

**Idempotency (R4)**:
- Given a transcript has already been archived for a session, when the archive processor runs again for the same session, then it overwrites the existing file without error
- Given a previous copy was interrupted (partial file), when the archive processor runs again, then the complete file replaces the partial one

**Crash Recovery (R7)**:
- Given sessions were recovered on startup (crash recovery set their `ended_at`), when archival runs for these sessions, then their transcripts are archived if the source file exists

**Directory Structure**:
- Given `memories/transcripts/` does not exist, when the system starts, then the directory is created during bootstrap (alongside other memory directories)
- Given `memories/transcripts/` already exists, when the system starts, then bootstrap completes without error
