# Delta Spec: DLT-186 - Upgrade all direct dependencies to latest, including the pi SDK 1.x major

<!-- Technical delta (dependency upgrade) — no User Flow section. -->

## Story

As the Tachikoma codebase, I need every direct dependency on its latest published version — including the pi SDK 1.x major — so that the version gap with the SDK it is built on stops growing and each future migration stays small.

## What It Does

Moves every direct dependency to its latest published version, regenerates the lockfile, and migrates the two pi APIs Tachikoma uses whose shape changed between 0.84.2 and 1.6.0. Behavior that pi 1.6 changes by default is adopted as-is and recorded in the SDK reference notes. Two bumps are held back and recorded with their reason.

biome 2.6.8 begins formatting Markdown and YAML files, which 2.5.8 does not touch. Tachikoma adopts that: the files it flags are reformatted once, in a commit of their own. Three kinds of file stay out of biome because formatting them breaks something: `CHANGELOG.md`, which semantic-release rewrites on every release; `docs/planning/DELTAS.md`, which the planning script reads by matching each delta's status line directly under its heading; and `SKILL.md` files, because the formatter strips the indentation of the YAML frontmatter description, which leaves the skill unloadable.

Target versions at spec time (2026-11-24). A version published after this date is taken instead, and the record below updated.

### pi APIs Tachikoma uses

**Changed — migrated**

| API | Change in 1.6.0 | Migration |
|---|---|---|
| `StringEnum` (`@earendil-works/pi-ai`) | Returns a pi-schema `Schema<T[number]>` instead of a TypeBox `TUnsafe<T[number]>`, so TypeBox's `Static` no longer resolves the literal union | Tachikoma owns an equivalent TypeBox builder with the same output |
| `before_agent_start` event | A union on `messageType` since 1.2.0: `prompt` and `images` exist only on `"user"` events | The skill-suggestion handler reads `prompt` only for user-started runs |

**Changed — adopted as-is**

| Change | Effect on Tachikoma |
|---|---|
| Tool argument validation and coercion run on pi-schema (1.5.0) | Schemas are validated as JSON Schema; the model sees pi-schema's messages; coercion rules carried over from TypeBox 1.3.27 |
| Prompt-cache warming defaults to `idle` (1.5.1) | Provider requests keep eligible prompt caches warm for up to 30 minutes between runs, when pi estimates at least $0.05 of avoided cache-miss cost |
| Anthropic message threads are on by default for `api.anthropic.com` (1.5.1) | Wire-level only, for that provider |
| Switching models drops the earlier model's thinking blocks (1.3.0) | Reaches fork-and-continue runs whose tier model differs from the main model |
| Resumed sessions restore their active tools; extension tools stay active unless registered with `defaultActive: false` (1.3.0, 1.4.0) | Reopened trunks keep the tools they had |
| `ToolCall.arguments` and `ToolResultMessage.details` are typed JSON-only (0.86.0) | Tachikoma's values are already JSON |
| The `SessionEntry` union gained entry types such as `context_edit` (0.87.0) | Tachikoma's entry filters ignore types they don't know |
| `agent_settled` carries `aborted`; `tool_execution_end` carries `durationMs` (1.1.0) | Additive |
| pi's default models moved (1.5.1, 1.6.0) | Only when no model is configured |
| The pi-ai root no longer re-exports TypeBox (1.5.0) | Tachikoma already imports `Type`, `Static` and `TSchema` from `typebox` |

**Unchanged for Tachikoma:** `createAgentSession` and its options, `DefaultResourceLoader` options, the `SessionManager` daily-trunk primitives, `ModelRuntime` / `ModelRegistry` / `SettingsManager`, `defineTool`, `bindExtensions`, the session file format (version 3), and the JSON shape `StringEnum` produces.

**Deprecated upstream:** pi-ai's `/compat` entry, which `SideRunner` uses for `completeSimple`, is documented as temporary. Moving off it is out of scope here.

## Acceptance Criteria

**R0 · Dependency manifest and lockfile**

- [ ] Given the npm registry at implementation time, when `package.json` is read, then every direct dependency selects its latest published version, except `semantic-release` and `typebox` as recorded in the held-back table
- [ ] Given the previous `package.json`, when compared, then each dependency keeps its pin style (exact pins stay exact, ranges stay ranges)
- [ ] Given a fresh clone, when `pnpm install --frozen-lockfile` runs, then it succeeds without ignored build scripts, unmet peer dependencies or engine warnings
- [ ] Given the lockfile, when inspected, then each direct dependency resolves to the version its specifier intends
- [ ] Given the installed tree, when `typebox` is resolved from Tachikoma and from `pi-coding-agent`, then both resolve to 1.3.27

**R1 · pi SDK 1.6.0**

- [ ] Given `package.json`, when read, then the three pi packages share one exact version, 1.6.0
- [ ] Given the upgraded tree, when a main, fork or bare session is opened, then it is created, bound and prompted as before

**R2.1 · StringEnum**

- [ ] Given a schema built with Tachikoma's `StringEnum`, when serialized, then it is `{ "type": "string", "enum": [...] }` plus the supplied `description` and `default`, identical to what pi-ai 0.84.2 produced
- [ ] Given a tool or config schema with an enum field, when type-checked, then the field's static type is the literal union: thinking level, log rotation frequency, notification severity, task type and status, workflow action, process output stream, goal status
- [ ] Given the source tree, when searched, then no file imports `StringEnum` from `@earendil-works/pi-ai`
- [ ] Given a config with a value outside an enum (for example an unknown thinking level), when loaded, then startup fails with the same config error shape as before

**R2.2 · before_agent_start**

- [ ] Given a user-started run, when `before_agent_start` fires with `messageType: "user"`, then the skill-suggestion classifier receives the latest prompt text and the recent conversation as before
- [ ] Given a run started by a custom message (`messageType: "custom"`), when the handler fires, then it does not read `prompt`, raises no error, and the run proceeds without a skill suggestion
- [ ] Given the hand-built `before_agent_start` events in the test suite, when the suite runs, then each carries `messageType` and every test passes

**R3 · Schemas under pi-schema**

- [ ] Given any registered tool and a well-formed call, when pi validates it, then `execute` receives the coerced arguments as before (numeric strings converted, a single value wrapped into an array, `null` in an optional property dropped)
- [ ] Given a malformed call, when validation fails, then the tool is not executed and the model receives pi-schema's message, such as `- path: missing`
- [ ] Given `SideRunner.classify()`, when the model answers, then the reply is still validated by Tachikoma's own TypeBox validation

**R4 · typebox pin**

- [ ] Given `package.json`, when read, then `typebox` is exactly 1.3.27
- [ ] Given ADR-003, when read, then it states the pin as `typebox@1.3.27`, kept in lockstep with the version `pi-coding-agent` ships, and its context says that pi's agent and AI packages use pi-schema while tool arguments are validated as JSON Schema

**R5 · vitest 5**

- [ ] Given `package.json`, when read, then `@vitest/coverage-v8` is exactly 5.1.1 and `vitest` is `^5.1.1` resolving to 5.1.1
- [ ] When `pnpm vitest run` executes, then every test file passes
- [ ] When `pnpm vitest run --coverage` executes, then the reports are produced without coverage-provider errors

**R6 · croner 11**

- [ ] Given Tachikoma's `cron` and `every` jobs, when registered under croner 11, then they fire on the same wall-clock schedule as before outside DST transitions
- [ ] Given a schedule expression croner 11 rejects, when a task is created or updated with it, then Tachikoma reports it as an invalid schedule and stores nothing
- [ ] [Edge] Given a stored task definition whose cron expression croner 11 no longer accepts, when the tasks tick runs, then that definition is skipped with a logged error and the remaining definitions are still evaluated
- [ ] [Edge] Given a cron expression that can never match, when its next run is computed, then there is none rather than an error
- [ ] [Edge] Given a DST spring-forward gap in the configured timezone, when a fixed-time schedule falls inside it, then it fires at the first valid time after the gap, and `every` jobs keep ticking through a fall-back overlap

**R7 · Remaining dependencies**

- [ ] Given `package.json`, when read, then each remaining dependency is at the version in the target table, or a newer one
- [ ] Given an existing database, when Tachikoma starts on the upgraded `better-sqlite3`, `drizzle-orm` and `drizzle-kit`, then migrations apply and the database opens
