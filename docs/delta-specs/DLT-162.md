# Delta Spec: DLT-162 - Telegram Message Pinning

## Story

As a user, I want the agent to pin important messages in our Telegram chat so that key responses (summaries, decisions, reference material) stay accessible at the top of the conversation without me having to manually pin them.

## What It Does

Adds two MCP tools — `pin_message` and `unpin_message` — that let the agent pin or unpin Telegram messages in the active chat. `pin_message` pins the current response message silently and returns its Telegram message ID; `unpin_message` unpins a previously pinned message by ID. Both are idempotent. In private chats no special permissions are needed; in groups/channels the bot needs the appropriate rights.

## Requirements

| ID | Requirement | Status |
|----|-------------|--------|
| R0 | Agent can pin and unpin messages in the active Telegram chat via MCP tools | Core goal |
| R1 | `pin_message` pins the last response message and returns its Telegram message ID | Must-have |
| R2 | `unpin_message` accepts a message ID and unpins that specific message | Must-have |
| R3 | Both tools are idempotent: pinning an already-pinned message succeeds, unpinning a non-pinned message succeeds | Must-have |
| R4 | Pinned messages are silent — no Telegram notification is triggered (`disable_notification=True`) | Must-have |
| R5 | Graceful error handling: permission failures in groups/channels and API errors return clear error responses to the agent | Must-have |
| R6 | Tools follow the existing MCP server factory pattern (FastMCP, Pydantic args, closure-captured bot/chat_id) | Must-have |

## Acceptance Criteria

### Pin Message (R1, R3, R4)

- [ ] Given the agent has sent a response in the Telegram chat, when `pin_message` is called, then the last response message is pinned in the chat and the tool returns `{"content": [{"type": "text", "text": "Message pinned (ID: 123)"}]}`
- [ ] Given the agent has sent a response that was split into multiple messages, when `pin_message` is called, then the final message in the split sequence (the message stored in the renderer's current message ID after `_send_chunks()` completes) is pinned and its message ID is returned
- [ ] Given `pin_message` is called with no tracked message ID (e.g., from a background task with no active Telegram renderer, or before any response has been sent), when the tool executes, then it returns `{"is_error": true, "content": [{"type": "text", "text": "No message available to pin"}]}`
- [ ] Given a message is already pinned, when `pin_message` is called on it again, then the operation succeeds without error (idempotent)
- [ ] Given a message is pinned, when the pin is applied, then no Telegram notification is sent to the user (silent pin via `disable_notification=True`)
- [ ] Given a message that has been deleted, when `pin_message` is called with its ID, then the tool returns `{"is_error": true, "content": [{"type": "text", "text": "Failed to pin message: <API error details>"}]}`

### Unpin Message (R2, R3)

- [ ] Given a pinned message with a known message ID, when `unpin_message` is called with that ID, then the message is unpinned and the tool returns `{"content": [{"type": "text", "text": "Message unpinned (ID: 123)"}]}`
- [ ] Given a message ID that is not currently pinned, when `unpin_message` is called, then the operation succeeds without error (idempotent)
- [ ] Given a message ID that does not exist or is invalid, when `unpin_message` is called, then the tool returns `{"is_error": true, "content": [{"type": "text", "text": "Failed to unpin message: <API error details>"}]}`

### Permission Handling (R5)

- [ ] Given the bot is in a private chat, when `pin_message` or `unpin_message` is called, then the operation succeeds (no special permissions needed)
- [ ] Given the bot is in a group without `can_pin_messages` permission, when `pin_message` is called, then the tool returns `{"is_error": true, "content": [{"type": "text", "text": "Insufficient permissions: bot requires can_pin_messages in this group"}]}`
- [ ] Given the bot is in a channel without `can_edit_messages` permission, when `pin_message` is called, then the tool returns `{"is_error": true, "content": [{"type": "text", "text": "Insufficient permissions: bot requires can_edit_messages in this channel"}]}`
- [ ] Given a Telegram API error occurs (network, rate limit, etc.), when `pin_message` or `unpin_message` is called, then the tool returns `{"is_error": true, "content": [{"type": "text", "text": "Failed to pin/unpin message: <API error details>"}]}`

### Integration (R6)

- [ ] Given the Telegram channel is active, when the channel's `get_mcp_servers()` is called, then a "telegram-pinning" server is included with both tools
- [ ] Given the MCP server factory, when created, it captures the bot instance and chat ID via closures, and accesses the current message ID through a getter on the response renderer

### Testing Notes

- Permission handling criteria (group/channel) should be tested via mocked Telegram API errors (e.g., `AsyncMock` with `side_effect=TelegramForbiddenError(...)`) since testing against real groups requires manual setup.
